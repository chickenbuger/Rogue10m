# Rogue10m 개인 스튜디오

프로젝트 루트의 `OpenPersonalStudio.bat`을 실행하면 기본 브라우저에 개인 스튜디오가 열린다. Node.js 20 이상을 사용하며 별도 패키지 설치가 필요 없다. 실행 중이면 같은 서버를 재사용한다.

- 주소: http://127.0.0.1:4317
- 스튜디오 홈: 실제 Git 브랜치, 등록 일정, 최근 Sprint 변경 기록, 결과 문서 연결이 없는 설계 확인.
- 개발 일정: 작업 추가/수정/삭제, 날짜·상태·구분·우선순위·메모, 상태별 보드와 날짜순 목록, JSON 백업.
- 개선·수정: Sprint 작업별 원문 상태·변경·검증 조회 및 키워드 검색. 유형은 제목 기반 자동 분류이므로 원문이 판단 기준이다.
- 개발 기록: DevLog 일자별 조회·검색.
- 설계·결과: Feature 문서 조회·검색.

## 데이터와 상태의 의미

원본은 `Docs/SprintChangeLog.md`, `DevLog/*.txt`, `Feature/architect/*.md`, `Feature/doc/*.md`다. 새로고침 버튼으로 최신 파일을 다시 읽는다. 원문 조회는 파일을 변경하지 않는다. 문서 기록의 QA 완료는 해당 당시의 범위이며 현재 게임 실행 검증을 뜻하지 않는다. 같은 이름의 결과 문서가 없는 설계는 확인 대상으로만 표시한다. 이를 미구현이나 실패로 단정하지 않는다.

일정은 기본 빈 목록이다. 기록 날짜를 미래 목표일로 변환하거나 임의의 마감일을 만들지 않는다. 완료율은 사용자가 등록한 일정만 분모로 삼는다. 날짜는 PC의 현지 날짜를 사용한다.

일정은 `Studio/data/tasks.json`에 저장하며 브라우저를 닫아도 유지된다. 이 폴더는 Git에서 제외된다. 일정 백업 버튼의 JSON에는 `tasks` 배열이 포함된다. 복구하려면 서버를 종료한 뒤 이 배열만 `tasks.json`으로 저장한다. 파일이 손상되면 덮어쓰지 않고 오류를 표시한다. 다른 창에서 먼저 변경한 경우 새로고침 후 다시 수정한다.

## 실행 / 검증

```powershell
.\Scripts\OpenPersonalStudio.ps1
# 다른 포트
.\Scripts\OpenPersonalStudio.ps1 -Port 4318
# 터미널에서 서버 실행 (Ctrl+C로 종료)
node Studio/server.mjs
# 구문 및 통합 테스트
node --check Studio/server.mjs
node --check Studio/lib.mjs
node --check Studio/public/app.js
node --test Studio/tests/studio.test.mjs
```

서버는 `127.0.0.1`에만 열리며 다른 PC에는 공개되지 않는다. 백그라운드 실행 PID는 `Studio/data/server.pid`에 남는다. 종료가 필요하면 작업 관리자에서 해당 PID의 Node 프로세스와 `Studio/server.mjs` 명령줄을 확인하고 종료한다. PC를 재시작하면 실행기를 다시 연다. Unreal Editor 실행 여부와 관계없이 사용할 수 있다.

## 등록한 일정의 실제 실행

`예정`에 작업을 저장하면 서버가 즉시 AI 작업을 시작한다. 예약 시각을 기다리지 않는다. 목표일은 마감일이며, 선행 작업이 있으면 완료 후 시작한다. 우선순위가 높은 순서, 같은 우선순위면 빠른 목표일 순서로 프로젝트 작업 하나씩 처리한다. 기존 startAfter 값은 더 이상 실행 조건이 아니다.

기획 에이전트가 파일별 작업을 배분하고 서로 독립적인 구현 패킷은 최대 두 개를 병렬로 처리한다. 빌드 담당자와 독립 검토자가 실제 변경을 확인하고 문서 담당자가 결과를 기록한다. 화면 상태는 `예정 → 진행 중 → 검증 대기 → 완료` 순서로 자동 갱신된다. 사용자가 상태를 수동으로 완료시키지는 않는다.

작업자는 요구사항과 현재 파일을 확인하고 기획·개발·빌드/QA·결과 문서화를 수행한다. 범위가 불명확하거나 승인/환경 제약이 있으면 확인 필요 상태와 질문을 남긴다. 기획 작성 요청은 문서 작성까지만 수행한다. 커밋·푸시·배포·파괴적 삭제는 별도 승인이 필요하다.

스튜디오에서 엔진 상태·담당 에이전트·진행 로그·검증 결과·산출물을 확인할 수 있다. 완료 여부는 원문 일정 상태보다 실제 실행 결과를 우선한다. 실행 중에는 내용 변경과 삭제가 잠기고 중단 요청만 가능하다. 전체 일시정지/중단은 실행 프로세스 종료를 기다린 뒤 기록되며, 이미 만든 결과는 롤백하지 않는다. 실패·확인 필요·중단 작업은 메모를 보완해 저장하고 다시 열어 `다시 검토`한다. 완료 작업의 후속 요청은 새 일정으로 등록한다.

PC와 Studio 서버, 로그인된 Codex CLI가 필요하다. 설치된 Codex CLI를 사용하므로 별도 API 키 입력은 필요 없다. 브라우저를 닫아도 서버는 작업을 계속한다. 모델 사용량·권한·네트워크 문제는 확인 필요 상태로 표시한다. 스튜디오 화면은 2초마다 실행 상태를 확인하며 문서 목록은 새로고침으로 갱신한다. 기존 채팅 heartbeat는 중지했다. 다른 채팅에서 같은 파일을 수정할 때는 스튜디오를 일시정지한다.

상태 파일은 `Studio/data/execution.json`이다. 일정과 실행 기록을 함께 백업하려면 data 폴더의 두 JSON 파일을 보존한다. 진행 중인 레코드나 studio.lock을 임의 삭제하지 않는다. 복구 및 작업자 프로토콜은 `Studio/EXECUTION.md`를 따른다.

추가 검증: `node --test Studio/tests/*.test.mjs`. UI 테스트는 기존 설치된 Playwright 경로를 `Studio/tests/execution-browser-check.mjs`의 첫 인자로 전달한다. 테스트 서버는 실제 AI 실행기를 연결하지 않아 사용자 작업을 실행하지 않는다.
