# 2026-08-19 개발 로그

## 직업별 통합 하단 전투 HUD

### 작업 배경

기존 Main HUD가 체력, 스테미나, 아이덴티티, 스킬, 아이템, 경험치를 각각 직접 소유하고 있어 하단 UI를 직업별로 교체하거나 재사용하기 어려웠다. 하단 기능을 하나의 Widget에서 조립하고 Main에는 그 Widget 하나만 배치하는 구조로 변경했다.

### 주요 변경

- 작업 브랜치를 `Sprint#4-15-class-themed-bottom-hud`로 전환했다.
- 마법사, 전사, 권사, 도적의 실제 전투 화면형 시안 4종을 제작했다.
- 1920×208 투명 직업 프레임 4종을 만들고 Texture2D로 임포트했다.
- `URogue10mBottomHUDWidget`과 `WBP_BottomHUD`를 추가했다.
- HP, MP/스테미나, 아이덴티티, 스킬 5칸, 아이템 5칸, 레벨/경험치를 Bottom HUD 내부로 이동했다.
- `WBP_Rogue10mMainHUD`의 개별 하단 자식을 제거하고 `BottomHUDWidget` 하나만 전체 폭 260px로 배치했다.
- Staff/Mana, GreatSword/Rage, Knuckle/StoneFist/Vigor, Dagger 계열을 기준으로 직업 테마가 자동 전환되도록 했다.
- 마법사는 활성화된 Mana View를 MP로 표시하고, 나머지 직업은 스테미나를 표시한다.
- 52px 초록색 경험치 바를 하단 전체 폭에 밀착했다.
- 재현 가능한 텍스처 준비, UMG 적용, Validator, 적용 프리뷰 스크립트를 추가했다.

### 검증

- UE 5.8 Editor target 전체 빌드 성공
- 퀵 슬롯 소유자 보정 후 증분 빌드 성공
- 네 직업 Texture2D 1920×208, UI 설정 통과
- Bottom HUD 필수 바인딩 14개 누락 0개
- 스킬/아이템 각 5칸 확인
- Main HUD의 `BottomHUDWidget` 1개 및 이전 하단 자식 0개 확인
- `Saved/ClassBottomHUDValidation.txt` 결과 `PASSED`
- `Scripts/CheckGeneratedChanges.ps1`, `git diff --check`, Python 문법 검사 통과
- Windows 화면 자동화는 로컬 ACL 오류로 사용할 수 없어 동일 임포트 텍스처와 UMG 좌표 기반 적용 프리뷰로 대체

## Notion 요약 후보

> 마법사, 전사, 권사, 도적용 하단 전투 HUD를 공통 배치와 직업별 테마로 제작했다. 기존 Main HUD에 흩어져 있던 HP, MP/스테미나, 아이덴티티, 스킬, 아이템, 경험치를 `WBP_BottomHUD` 하나로 통합하고 Main에는 `BottomHUDWidget` 한 개만 배치했다. 직업 테마는 무기와 아이덴티티에 따라 자동 전환되며 Blueprint 오버라이드도 지원한다. 초록색 경험치 바는 화면 최하단 전체 폭에 유지되고, UE 5.8 빌드와 UMG 구조 검증이 모두 통과했다.

## 장착 무기 기반 스킬트리 자동 활성화

### 작업 배경

하단 HUD 테마는 장착 무기와 아이덴티티를 기준으로 전환되고 있었고, 전투 컴포넌트에도 무기 프로필 재적용 경로가 있었다. 그러나 무기 교체 직전의 차징·콤보 상태가 남을 수 있었고, 이전 무기에서 해금한 스킬을 현재 무기 슬롯에 지정할 수 있는 경계 문제가 있었다. 또한 인벤토리에 장착 가능한 활은 전용 스킬 프로필이 없어 빈 트리가 되는 누락이 있었다.

### 주요 변경

- 작업 브랜치를 `Sprint#4-16-weapon-driven-skill-tree`로 전환했다.
- 인벤토리 장착 경로인 `Character.SetEquippedWeaponType`에서 전투 컴포넌트가 현재 무기 프로필을 즉시 활성화하도록 기존 흐름을 강화했다.
- 무기 교체 시 차징, 콤보, 예약 GAS 공격, 진행 중 다중 타격 타이머와 이전 표시 스킬을 정리한다.
- 현재 활성 스킬트리에 포함된 스킬만 입력 슬롯에 지정할 수 있게 했다.
- 활성 프로필이 있을 때 프로필 밖 과거 기본 공격 fallback을 차단했다.
- 활성 트리 무기 타입과 스킬 소속 여부를 Blueprint에서 조회할 수 있게 했다.
- 해금 스킬 조회를 현재 퀵 슬롯 일부가 아니라 활성 트리 전체 기준으로 수정했다.
- 활 전용 스킬 5개, Montage 5개, Niagara 3개, `DA_SkillProfile_Combat_Bow`를 제작하고 기본 캐릭터 데이터에 등록했다.
- 11개 무기를 순회하는 렌더링 비의존 런타임 테스트를 추가했다.

### 검증

- UE 5.8 `Rogue10mEditor Win64 Development` 빌드 성공
- 데이터 검증 `RESULT=PASSED profiles=11 attacks=55 montages=55 niagara=33 combos=11 first_person_safe=55`
- 런타임 전환 검증 `RESULT=WEAPON_SKILL_TREE_PASSED weapons=11 failures=0`
- Dagger, Shuriken, Bow, DualDaggers, LongSword, GreatSword, DualBlades, Shield, SwordBuckler, Staff, Knuckle 각각 활성 스킬 5개 확인
- 이전 무기 스킬의 교차 슬롯 지정 거부, 프로필 밖 점프 스킬 fallback 차단 확인
- `git diff --check`, Python 문법 검사 통과

## Notion 요약 후보

> 장착 무기가 바뀌면 동일 무기 타입의 스킬 프로필이 즉시 활성화되도록 전투 컴포넌트의 전환 경계를 강화했다. 이전 무기의 차징·콤보·예약 공격을 정리하고, 활성 트리 밖 스킬은 현재 슬롯에 넣을 수 없게 했다. 누락됐던 활 전용 5스킬 프로필도 추가해 인벤토리의 모든 주요 무기 전환을 지원한다. 11개 무기 순회 런타임 테스트에서 활성 트리, 기본 슬롯, 회피, 점프, 교차 스킬 차단이 모두 통과했다.

## 직업·무기별 전투 애니메이션 및 1인칭 안전 파티클

### 작업 배경

단검, 표창, 쌍단검, 장검, 대검, 쌍검, 방패, 한손검·작은방패, 마법, 권법의 공격 성격이 구분되면서도 모든 종족이 같은 스킬에서 같은 모션을 사용해야 했다. 또한 공격 파티클은 타격감을 유지하되 1인칭 조준점과 전방 표적을 가리지 않아야 했다.

### 주요 변경

- 요청한 10개 전투 스타일에 기본 3연계, 특수, 차징 공격을 구성했다.
- 총 50개 Animation Montage, 50개 Attack Skill Data Asset, 30개 Niagara, 10개 Skill Profile을 생성하고 기본 캐릭터 데이터에 등록했다.
- 6개 종족 캐릭터가 공통 Manny 애니메이션 소스를 사용하도록 연결해 같은 스킬의 모션을 통일했다.
- 단검·표창·쌍단검·마법사·권사는 2단 점프, 전사 계열은 1단 점프로 설정했다.
- 로컬 1인칭 Cast/Charge/Impact에 별도 위치, 회전, 크기, 지속시간 보정을 적용했다.
- 쌍단검·쌍검·권사의 양손 효과를 화면 중앙에서 바깥쪽으로 이동시키고 최종 Charge 실제 배율을 최대 0.0312로 축소했다.
- 일회성·차징 Niagara를 즉시 비활성화한 뒤 파괴하도록 정리해 화면 누적을 방지했다.
- 기존 이동 파티클 OFF 설정은 유지하고 공격 애니메이션과 파티클 자산을 별도 경로로 관리했다.

### 검증

- UE 5.8 Editor target 빌드 성공
- 요청 10종 데이터 검증: `RESULT=PASSED profiles=10 attacks=50 montages=50 niagara=30 combos=10 first_person_safe=50 races=6`
- 최종 1인칭 튜닝: `RESULT=FIRST_PERSON_CLASS_COMBAT_VFX_TUNED styles=10 attacks=50 charge_multiplier=0.12`
- 실제 게임 실행: 요청 10종에서 30회 연계 공격과 10회 차징 공격 통과, 실패 0건
- 10개 최종 캡처 생성, 쌍단검·쌍검·권사 화면 중앙 가림 없음 확인

## 권사 무협 수련 스킬트리

### 작업 배경

권사는 다른 직업처럼 모든 공격을 처음부터 사용하는 방식보다, 입문 초식을 반복 수련하고 특정 강적을 쓰러뜨리며 경맥과 심법을 여는 성장 방식이 어울린다. 권갑 장착 시에만 활성화되는 기존 무기 연동 구조 위에 무공 사용 횟수, 몬스터 처치, 선행 무공을 결합한 진행형 스킬트리를 구현했다.

### 주요 변경

- 작업 브랜치를 `Sprint#4-17-martial-artist-skill-tree`로 전환했다.
- 권사 트리를 입문, 초식, 절기, 심법 4경지와 10개 무공으로 구성했다.
- 시작 무공은 연환권 하나만 전수하고 붕권, 파진각, 철산고부터 수련·토벌 조건을 요구하도록 했다.
- PlayerState에 무공별 사용 횟수와 몬스터 타입별 처치 횟수를 기록했다.
- 공격이 실제 실행됐을 때만 수련 횟수가 증가하고, 몬스터 사망 시 마지막 피해 플레이어의 토벌 횟수가 증가한다.
- 진행도 이벤트마다 선행 무공과 복합 조건을 검사해 가능한 무공을 연쇄 자동 해금한다.
- 금강불괴는 슬롯 없이 받는 피해 15% 감소가 상시 적용되며 공격 슬롯 장착은 거부한다.
- 권갑을 장착했을 때만 권사 트리가 활성화되고 다른 무기로 교체하면 해당 무기 트리로 즉시 돌아간다.
- 흑철과 고동 장식, 옥빛 경맥을 사용한 1500×840 무협 UI 프레임을 제작하고 Texture2D로 임포트했다.
- 스킬트리 창을 좌측 권맥 경지, 중앙 분기 트리, 우측 무공 비급의 3영역으로 재구성했다.
- 노드 클릭 시 선행 무공, 수련/토벌 현재값, 해금 효과를 표시하고 해금된 공격 무공만 드래그할 수 있게 했다.
- 생성, Widget Blueprint 조립, 데이터 검증, 실제 게임 캡처를 반복 실행할 수 있는 Editor 스크립트와 명령을 추가했다.

### 검증

- UE 5.8 `Rogue10mEditor Win64 Development` 빌드 성공
- 권사 데이터·위젯 전용 검증 오류 0건
- 전체 메뉴 위젯 에셋 및 클래스 참조 검증 오류 0건
- Menu → Lobby → Component Widget Flow 검증 오류 0건
- 실제 게임 런타임 `RESULT=WEAPON_SKILL_TREE_PASSED weapons=11 failures=0`
- 권사 10개 노드, 시작 해금 1개, 후속 무공 9개 연쇄 해금 확인
- 금강불괴 받는 피해 15% 감소와 패시브 입력 슬롯 장착 거부 확인
- UMG 포함 1920×1080 실제 게임 캡처 생성
- `git diff --check` 통과
- Convex hull과 `SM_Plane` BodySetup 경고 3건은 기존 포털 VFX 자산 경고로 확인
