# 2026-09-12 개발 기록

## 팔만 보이는 1인칭 격투 시야
마우스를 아래로 내릴 때 몸통과 하체가 보인다는 요청에 따라 Sprint#4-27-arms-only-first-person 브랜치에서 작업했다. 기획 1·개발 2·검증 2 역할로 나누고, 기존 미커밋 작업은 유지했다.

기존 1인칭 전신 Manny에서 목과 다리 본만 숨겨 몸통·골반 형상이 남는 원인을 확인했다. Unreal Editor로 별도 SK_FirstPersonArms를 생성해 팔 이외의 표면을 제거했다. 89개 뼈의 이름·부모·기준 자세와 재질 2개를 보존했다. 세 LOD의 렌더 정점 검사에서 팔 이외 정점은 0개였다. 원본 Manny 파일 해시도 유지됐다.

로컬 기본 격투와 너클에 팔 전용 메시를 연결했다. 다른 무기로 전환하면 원래 메시·재질·애니메이션·숨김 본·부착 위치·시야 설정을 복원한다. 기존 머리·상체 기반 카메라와 공격 판정을 유지한다.

통합 빌드 118.35초, 새 시야 검증 코드 포함 증분 빌드 21.66초로 성공했다. 독립 소스 검토를 마쳤으며 실제 아래보기·공격·점프와 기존 전투 회귀를 검증 중이다.

## 최종 검증 결과
팔 전용 시야 390프레임, 기본 격투 480프레임, 기존 너클 120프레임과 시야3조건이 모두 실패0으로 통과했다. 기본 -70도 제한을 유지하면서 테스트용 -89도까지 실제 각도를 확인했다. 독립 시각 검토에서 16:9·울트라와이드 대표14장에 몸통·골반·다리 표면과 새 어깨 구멍이 없었다.

첫 전투 회귀 중 조준 입력이 크게 바뀌어 실패한 로그는 보존했다. 테스트에서만 외부 마우스 시점 입력을 분리하고 기존 camera/control 불변 기준을 그대로 유지해 재검증했다. 직접 각도 설정·공격·점프와 POV 측정은 계속 실행한다. 최종 빌드20.00초, 기본 머리5.91도/표시카메라1.27도, 점프89.99cm, 일반어퍼컷31.8/강화36.2 피해를 확인했다.

실제 화면과 검증 자료는 Feature/doc/images/arms-only-20260912 및 Feature/doc/evidence/arms-only-20260912에 보관한다. 컴퓨터 플러그인 오류로 원본 영상 직접 비교는 미완료다. 현재 Manny의 전완 외형과 가드 화면 점유는 유지한다.

## 사용자 녹화본으로 1인칭 레퍼런스 직접 확인
사용자가 KakaoTalk_20260912_185607069.mp4를 제공해 브라우저 없이 실제 영상 프레임을 확인했다. 약70.37초·1080×2340·30fps HEVC이며 오디오 스트림은 없다. 기존 설치 도구의 디코더를 사용해 전체 흐름과 공격18~21초·이동36~39초 구간을 분석했다.

주 담당은 실제 장면을 확인하고 서브에이전트는 현행 격투 소스와 영상 프레임을 독립 대조했다. 팔·무기가 화면 가장자리와 중앙을 넓게 사용하고, 동일 가드에 매번 정착하기보다 다음 자세로 이어지는 구성이 두드러졌다. 큰 배경 변화는 이동·입력·연출의 기여도를 구분할 수 없어 단순 카메라 흔들림으로 단정하지 않았다.

현행 코드에는 이미 곡선 회수·상체 선행·머리 후행이 있으므로, 다음 설계의 우선순위는 공격별 진입/회수 경로와 연계 자세 구분이다. 강공격·착지 카메라 반응과 실제 명중 효과는 그다음 검토 항목으로 기록했다. 팔만 보이는 기존 시야 요구는 유지한다.

이번에는 비교 문서와 추출 이미지만 추가했다. 게임 코드·자산·밸런스 변경과 빌드는 하지 않았다. 이 녹화본을 확인한 것으로 고릴라 암즈나 이전의 다른 영상까지 시청했다고 기록하지 않는다.

## 두 번째 참고 영상 — 타격감 표현의 단계별 보강
사용자 제공 KakaoTalk_20260912_193904427.mp4(26.6초·1080×2340·30fps)를 실제 프레임으로 확인했다. 영상은 공격 효과→적 반응→카메라 흔들림→체력 UI→락온/카메라 시점 조절을 단계별로 보여준다. 마지막 단계는 단순 확대가 아닌 락온과 시점 변경으로 설명된다. 오디오 스트림은 없다.

주 담당의 영상 관찰과 서브에이전트의 현행 소스 대조를 연결했다. 현재 명중 VFX·피해 숫자 경로와 체력바는 이미 있으며, 적 피격 플래시/움찔 및 명중 여부에 따른 카메라 충격이 보강점이다. VFX의 현재 위치는 적 바운드 중심이므로 접촉 위치·방향 전달도 검토 항목으로 기록했다. 스킬 자산의 실제 VFX 활성 설정은 이번에 조회하지 않았다.

앞선 갈브레나 영상의 공격별 팔 경로/회수 개선과 이번 명중 피드백을 함께 참고한다. 하나의 명중 확정에 적 반응·접촉 효과·카메라·체력 감소 강조를 맞추고, 헛스윙/명중 및 일반/강화 공격을 구분하는 방향이다. 팔 전용 표시와 기존 조준·판정은 기준으로 유지한다. 락온과 히트스톱은 자동 도입하거나 필수 요구로 확정하지 않았다.

## 레퍼런스 기반 기본 복싱 애니메이션 제작

사용자가 확정한 입력에 맞춰 기본 직업의 동작을 바꿨다. 좌클릭은 왼손 잽 다음 오른손 잽이며, 우클릭은 짧게 눌렀다 놓으면 오른손 스트레이트,0.85초 이상 모았다 놓으면 오른손 훅이다. 작업 브랜치는 Sprint#4-28-reference-boxing-combos다.

### 동작을 구분하고 자연스럽게 연결하기
두 사용자 녹화의 분석 문서를 바탕으로 기존 골격을 사용하는 절차형 애니메이션을 구현했다. 빠른 잽, 상체·어깨까지 전진하는 스트레이트, 바깥 준비에서 안쪽을 통과하는 수평 훅으로 나눴다. 연타는 직전 손 위치에서 이어지고 충전을 놓을 때 팔꿈치 준비값도 부드럽게 연결한다. 훅 중 왼손 가드를 바깥·뒤로 이동시켜 자기 손을 때리는 듯한 겹침을 줄였다. 팔을 늘리는 대신 원래 골격 길이를 유지했다.

### 실제 맞았을 때만 전달되는 타격감
피해가 확정되면 적 메시가 짧게 움찔하고 밝아지며 기존 충격 이펙트·피해 숫자와 함께 표현된다. 헛스윙에는 명중 충격이 없고, 한 공격으로 여러 적을 맞혀도 카메라는 한 번만 반응한다. 화면에만 짧은 충격을 더하므로 조준 방향과 실제 판정은 유지된다. 다른 무기로 시작한 잔여 공격을 복싱 효과로 잘못 처리하지 않도록 실행의 무기 정보도 저장했다. 기존 적 오버레이를 보호하고 종료·사망·무기 전환에서 원래 상태로 복구한다.

### 실행 검증과 수정
기획1·개발2·검증2 역할을 사용하고 명중 반응 개발 담당1명을 추가했다. 독립 검토에서 충전 해제 팔꿈치 전환, 무기 실행 소유권, 스트레이트 도달 부족, 훅의 양손 겹침을 찾아 수정했다. 사망 시 바로 제거되는 적을 다시 참조한 테스트 오류도 수정했다.

설치된 언리얼5.8.2에서 최종 빌드20.20초로 성공했다. 기본 공격480프레임, 명중 반응280프레임, 팔 전용 시야390프레임, 너클120프레임 및 시야3조건 모두 실패0이다. 아래보기와 울트라와이드에서도 몸통·하체 표면이 보이지 않는다. 실제 손 도달과 피해 시점은 왼잽·스트레이트 같은 프레임, 오른잽2프레임, 훅1프레임 차이다.30프레임 기준 최대0.0667초이며 모든 정점이 완전히 같은 순간이라고 기록하지 않는다.

양팔 위팔27.771cm·아래팔27.251cm는 유지됐고 원본 Manny 해시도 이전 검증값과 일치한다. 실제 게임 시연은1280×720·30프레임·10초 무음 영상으로 저장했다. 독립 소스·시각 검토와 변경 공백·하네스 경로 검사도 통과했다. 전체 영상의 실시간 체감이나 모든 프레임률을 검증한 것으로 확대하지 않는다.
