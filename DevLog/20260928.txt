

## 2026-09-28 — V키로 현재 캐릭터를 3인칭에서 확인

### 목표와 작업 범위
플레이 중 V키로 1인칭과3인칭을 왕복하며 현재 외형과 공격 자세를 확인하도록 변경했다. Sprint#4-40-third-person-inspection 작업 브랜치에서 기존 작업을 보존했다. 기획1/개발2/검증2 역할로 진행했다.

### 구현 내용
V키를 현재 PlayerController에 연결하고 AppearanceCameraComponent의 관찰 상태로 화면을 전환한다. 3인칭 관찰 거리는300cm, 기준 높이는캡슐중심0cm, 벽 충돌반경12cm다. 최초높이60cm에서 하체가HUD에가려 실제촬영을보고0cm로 조정했다. 머리·얼굴·머리카락 가림은 시점에 맞춰 복원하고 별도 FirstPersonMesh는 계속 비활성화한다. 실제 머리 CameraComponent와 공격 기준은 바꾸지 않고 화면POV만 바꾼다. UI/사망/일시정지/다른시점에서는V를무시한다.

### 검증과 시행착오
최종UE5.8 Editor 빌드12.43초 성공. 실제PC.InputKey V왕복3회와UI중V차단, 1인칭135/3인칭145샘플, 좌우잽각12재생샘플, 벽충돌10샘플을 확인했다. 280프레임 실패0, 머리카메라위치오차0cm·회전오차0.00000418도다. 벽충돌은300→128cm로당겨지고장애물제거후복원됐다. 소스독립검토·생성경로·diff검사완료.
첫테스트는몽타주종료후회복상태를실패로잘못가정하여검사조건을수정했다. 다음실행은실제마우스입력유입으로시선이바뀌어실패했다. 테스트Pawn의물리입력만격리하고PC의실제V입력경로는유지해최종통과했다. 이격리는테스트전용이며게임플레이수정이아니다. 실패로그도보존했다.

### 결과와 사용법
V키한번으로뒤쪽3인칭, 다시누르면기존머리카메라로복귀한다. 실제9.33초영상을제작했다. 기존에디터에서새기능이보이지않으면저장후재시작한다. 관찰화면중앙과실제머리기준공격에는시차가있다. 공격진행순간토글/사망/외형교체/재빙의/네트워크는별도실행미검증이다. 바이너리에셋수정과커밋·푸시는없다.

## 2026-09-28 — 미사용 임시 파일 정리

### 정리 목적

### 정리 내용

### 보존 판단
249개 소스·스크립트·설정 파일 조사에서 삭제 가능한 미사용 소스는 입증하지 못했다. 이전 1인칭 코드와 콘솔 도구에는 참조가 남아 있어 유지했다. 원본 촬영본·최종 영상·백업·생성 코드·입력 로그·도구·애셋도 보존했다. 최종 25도 영상이 확인되지 않은 이미지 278개는 재생성 가능하더라도 남겼다. 자동 중복 후보 중 동적 경로와 수동 실행 호환성이 필요한 87개도 유지했다.

### 검증 결과
정리 전후 보존 의존성 2,858개의 SHA-256이 일치했다. 삭제 영수증 2,831개가 확정 목록과 일치하고 대상 파일 부재를 확인했다. 재생성 감사는 모든 프레임의 RGB 픽셀을 대조했으며, 실제 삭제는 검증된 tmp 파일에만 개별 적용했다. 게임 코드·애셋 변경이 없어 UE 재빌드는 생략했다. 엔진 생성 폴더는 정리하지 않았다. 커밋·푸시는 없다.

## 2026-09-28 | 캐릭터 애니메이션 왜곡 점검 및 안정화

### 작업 배경
공격 중 몸이 불안정하게 흔들리고 손발이 일그러지는 문제를 원본 FBX, Manny, 공격 몽타주, Source AnimBP, 외형 리타깃으로 나눠 점검했다. 기획1·개발2·검증2 역할을 순차 병렬로 운영했으며, Sprint#4-42-animation-stability 브랜치에서 작업했다.

### 주요 수정
골반을 실제 루트와 분리해 허리·허벅지 연결이 늘어나는 문제를 수정했다. 외형의 추가 IK와 잘못된 보조 체인 매핑을 정리하고, Source 발 보정을 공격 슬롯 앞으로 옮겨 이동 보정과 공격 자세가 충돌하지 않도록 했다. 오른잽은 하체 스탠스를 유지하면서 가슴 회전과 손 IK를 정렬했다. 훅은 전용 몽타주의 진입 블렌드만0.25초에서0.10초로 조정했다. 카메라는 기존 머리 본을 그대로 따르며 입력·피해·차징·공격 타이밍은 유지했다.

### 검증 결과
몸 연결 길이비0.644~3.546이1.000으로 복원됐다. 왼잽 오른발 최대 회전은30fps 한 프레임150.812도에서17.183도로 감소했다. 원본과 실제 공격 발의 회전 오차는 최대179.214도에서0.0001도 미만으로 줄었다. UE5.8 최종 빌드,15초 통합 실행450프레임, V키 회귀280프레임을 통과했다. 걷기187.74cm와 점프89.99cm, 착지·대기 복귀도 확인했다.

### 남은 연출과 범위
훅 원본의 빠른 전신 회전은 남아 있다. 모든 회전을 낮춘 것이 아니라 리타깃·IK가 추가하던 왜곡과 전환 증폭을 제거했다. 공격 중 지형 접지 보정은 원본 자세를 우선하며, 실제 영상 검증은 Human Male 기준이다.6종 설정은 함께 적용했다. 공유 원본 모션은 보존했고, 모든 애셋 수정은 Unreal Editor API로 수행했다. 커밋·푸시는 없다.

## 2026-09-28 | 1인칭 머리 그림자 복원

### 작업 배경
머리 내부가 보이지 않도록 head 본을 숨기면서 그림자에서도 머리가 사라졌다. 기획1·개발2·검증2 역할로 원인과 렌더 결과를 확인하고 Sprint#4-43 작업으로 수정했다.

### 적용 방식
화면에는 기존 Appearance Mesh와 머리 카메라를 유지하고, 숨기기 전 포즈를 복사한 그림자 전용 메시를 추가했다. 별도 First Person Mesh나 공격 애니메이션 재생은 추가하지 않았다. V키로3인칭에 들어가면 원래 외형 그림자를 복원하고 전용 그림자는 끈다. 얼굴·머리카락 파츠의 포즈·재질 동기화와 불필요해진 proxy 정리도 구현했다.

### 확인 결과
UE5.8 빌드 성공, 그림자 검사390프레임 및 V키 회귀280프레임 실패0이다. 같은 자세와 카메라로 촬영한 전후 이미지에서 머리 실루엣이 복원됐다. 숨기기 전 외형과 그림자 포즈330샘플의 위치 오차는0cm였고 공격4종의91샘플도 확인했다. 첫 테스트 API 컴파일 오류는 수정하고 실패 로그를 보존했다.

### 검증 범위와 작업 상태
현재 Human Male과 맵의 VSM 그림자 기준이다. ray tracing 그림자·반사, 모든 외형 교체, morph·cloth·groom, GPU 성능 측정은 완료 범위에 포함하지 않는다. 외형 교체·종료는 소스 검토로 확인했다. 바이너리 애셋은 이번에 편집하지 않았고 기존 변경은 보존했다. 공유 체크아웃의 후속 Sprint#4-44 브랜치 전환은 되돌리지 않았다. 커밋·푸시는 없다.

## 2026-09-28 — 개발을 한눈에 보는 개인 스튜디오

### 구현 내용
자동 검토 선택, 시작 가능 시각, 선행 작업을 추가했다. 우선순위와 목표일에 따라 한 개씩 요구사항 검토·개발·검증을 진행한다. 실행 소유권과 파일 잠금으로 중복 작업을 막고, 실행 중 변경·삭제는 차단한다. 전체 일시정지, 중단 요청, 내용 보완 후 재검토, 단계별 로그와 산출물 열기를 제공한다. 완료는 검증 내용과 실제 산출물이 있는 경우에만 기록한다. 커밋·푸시·배포·파괴적 삭제는 별도 승인 경계로 유지했다.

### 검증
기존 기능과 새 대기열 검사를 합쳐 아홉 건을 통과했다. 별도 두 프로세스의 동시 claim도 한 개만 성공했다. 실제 Edge에서 미래 시작·재개·작업 잠금·중단·재검토·완료 반영과 결과 문서 열기, 모바일 배치를 확인했다. 첫 UI 검사는 저장 응답보다 빨리 상태를 읽는 경합이어서 응답 완료를 기다리도록 수정했다. 결과 문서를 누를 때 일정 양식이 제출되지 않도록 버튼 타입도 명시했다.

### 실제 첫 작업 처리
기존에 등록된 ‘무기 별 애니메이션 기획 작성’을 대기열에서 가져와 Sprint#4-46으로 진행했다. 실제 무기 유형12개, 장비별 제작 설정11종, 맨손 전용 입력과 최신 머리 카메라·리타깃·그림자 기록을 조사했다. 무기별 동작 표, 데이터 연결, 제작 우선순위와 QA 기준을 작성했다. 무기12개와 기획12행, 출처7개를 검증했다. 최초 자동 집계에서 표 머리글을 무기로 세는 오류를 고친 뒤 통과했다. 이번 완료는 기획 작성이며 게임 적용 완료가 아니다.

### 결과와 제한
등록 → 검토 → 작업 → 검증 → 결과 확인 흐름을 실제 일정으로 확인했다. 실패·입력 필요·중단 작업은 자동 재실행하지 않고 다시 검토 요청을 기다린다. 스튜디오 브라우저만 열어놓는 것으로 모델이 실행되는 것은 아니며 Codex 앱과 PC가 필요하다. 기존 미커밋 변경을 보존했고 게임 코드·에셋을 변경하지 않아 Unreal 빌드는 생략했다. 커밋·푸시는 없다.

## 2026-09-28 — 스튜디오를 역할별 AI 작업실로 전환

### 목표와 작업 배분
사용자가 예정에 한 번 넣으면 에이전트가 일을 나눠 수행하고 검증 대기를 거쳐 완료하도록 요청했다. Sprint#4-47에서 실행기, 화면, 통합 검증 패킷으로 나눴다. 기존 5분 예약은 중지했고, 저장·재검토·재개 이벤트가 즉시 작업자를 깨우도록 변경했다.

### 구현 내용
기획자가 최대 두 구현 패킷과 담당 파일을 정한다. 겹치지 않는 파일만 병렬 개발하고, 빌드 담당자·독립 검토자·문서 담당자·최종 검토자가 뒤따른다. 실제 Codex CLI를 호출하며 역할별 진행과 결과를 스튜디오에 보여준다. 중단은 실행 프로세스 종료까지 기다리고 기존 파일을 보존한다. 산출물과 실제 성공 명령 증거가 없으면 완료하지 않는다.

### 검증과 보완
Node 자동검사19건과 Edge5개화면·CRUD·역할별 상태·중단/재시도·연결 복구·390px 모바일·200% 글자 확대를 통과했다. 병렬 작업 시작 순서를 고정한 테스트의 간헐 실패를 수정했다. 독립 검토가 발견한 검증 명령 부분 일치 오판정도 전체 일치와 복합 명령 제외로 수정했다. 실패 원인이 준비 상태로 덮이지 않도록 보존했다.

### 실제 실행 제한과 사용자 결정
설치된 최신 CLI로 실제 격리 작업을 실행했다. 파일 읽기 단계에서 Windows 샌드박스의 deny-read ACL 오류가 발생했고 확인 필요로 멈췄다. 자동 승인 검토를 사용하는 지속 설정은 승인 심사에서 권한 확대를 이유로 거절되었다. 사용자는 오류 시 중지 유지를 선택했다. 따라서 approval_policy=never를 유지하고 라이브 엔진을 확인 필요·일시정지 상태로 표시했다. 실제 모델이 전체 구현을 끝낸 성공 검증은 하지 못했다. 이전 무기별 애니메이션 기획 완료 기록은 보존했다.

### 결과와 관련 자료
즉시 작업 배분 구조는 구현했다. 현재 PC에서 실제 무인 작업을 진행하려면 샌드박스 환경 문제가 먼저 해결되어야 한다. 게임 코드·에셋 변경이 없어 UE 빌드는 수행하지 않았다. 커밋과 푸시는 하지 않았다.
