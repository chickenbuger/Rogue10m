
# Obsidian에서 소스 파일 관계만 보기

## 작업 배경
전체 그래프에 개발일지와 README가 함께 나타나 C++ 파일 사이의 관계를 보기 어려웠다.

## 적용 내용
소스 전용 경로 필터를 저장하고 현재 소스 121개와 내부 include 관계 292개를 다시 생성했다.
화살표가 실제 include 방향과 일치하도록 역방향 링크를 일반 텍스트로 바꾸고 대시보드 연결을 제거했다.
기존 실행 파일에서 설정도 함께 적용하며, 원래 그래프 설정은 최초 백업으로 보존한다.

## 검증 결과
생성·지표·링크 검사와 파일별 유출 관계 비교, 스크립트 구문 및 설정 보존 검사를 통과했다.
실행 중인 Obsidian 화면 반영은 미확인이다. 그래프 검색창에 소스 경로 필터를 직접 입력하면 된다.
이번 변경은 도구·문서·로컬 설정 및 작업 브랜치에 한정하며 게임 소스와 자산은 변경하지 않았다. 커밋과 푸시는 하지 않았다.

## 노션 요약 후보
- 작업: 소스 전용 Obsidian 그래프
- 결과: 소스 121개와 내부 include 292개를 방향 그래프로 탐색
- 주의: 함수 호출이나 Blueprint 참조는 포함하지 않는 정적 include 관계
- 문서: Feature/doc/2026-09-22_obsidian-source-graph.md

## 소스 그래프에서 Feature 문서 제외 보완
- 요청: Feature 문서도 소스 연관도 그래프에서 보이지 않도록 한다.
- 변경: 소스 폴더 한정 필터에 Feature 경로 제외를 명시하고 설정 스크립트·생성 대시보드·사용 안내에 반영했다.
- 검증: 그래프 설정 저장 확인, 소스 121개·관계 292개 생성 및 링크·지표 검증 통과.
- 화면 반영: 실행 중인 Obsidian의 그래프가 그대로라면 검색 필터를 직접 입력해야 한다.
- 노션 요약 후보: 소스 그래프에서 Feature 문서를 명시적으로 제외했다.

## 기능 노드와 소스 파일 연결 추가

### 요청과 구현
기능 문서는 숨기되 전투·인벤토리·스킬 같은 기능 자체는 그래프에 보여야 한다는 요청을 반영했다.
사용자가 선택한 방식에 따라 기능 노드 10개와 소스 연결 164개를 추가했다. 기존 소스 121개와 내부 include 관계 292개는 유지했다.
여러 기능이 함께 사용하는 파일은 각 기능에서 연결한다. 기능 노드를 금색으로 구분하고 Feature 작업 문서는 계속 제외한다.
분류 규칙은 Scripts/ObsidianFunctionGroups.json에 명시해 이후 수정할 수 있게 했다.

### 검증과 한계
기능 노트·분류 규칙·링크 대상·연결 수 검증과 스크립트 5개 구문 검사를 통과했다. 미분류 소스는 0개다.
기능에서 소스로 향하는 선은 관련 파일 분류이며 함수 호출을 뜻하지 않는다. 실행 중인 Obsidian 화면 반영은 직접 확인하지 않았다.
게임 소스와 에셋은 변경하지 않았으며 커밋·푸시도 하지 않았다.

### 노션 요약 후보
- 기능 노드 10개에서 소스 파일로 연결되는 탐색 구조를 추가했다.
- 공유 소스를 통해 기능 사이의 접점을 확인할 수 있다.
- 기존 include 방향 그래프와 기능 소속 연결을 함께 표시한다.
- 결과 문서: Feature/doc/2026-09-22_obsidian-source-graph.md

## Feature 본문을 근거로 기능 연결선 재구성

### 변경 이유
기능 이름이나 소스 파일명만으로 분류하지 않고 기존 Feature 설계·결과 내용을 참고해 연결해 달라는 요청을 반영했다.

### 구현 결과
Feature 문서 170개를 검사하고 기능 주제와 연결된 157개 문서에서 실제 소스·클래스·축약 이름을 확인했다.
기능 노드 10개에 문서 근거가 있는 소스 연결 397개를 생성했다. 기존 소스 121개와 include 관계 292개는 유지했다.
각 기능 노트에 연결의 근거 문서와 행 번호를 남겼고 전체 근거는 functions.json에 저장했다. 원문 Feature는 그래프에서 계속 숨긴다.
클래스가 파일 이름과 다를 때는 헤더의 실제 정의를 확인한다. 없는 소스·모호한 이름·전방 선언에는 임의 연결을 만들지 않는다.

### 검증
모든 선의 문서 경로·행·언급 문자열 및 소스 실재 여부 검사와 파일 쌍·축약명·클래스 소유권 회귀 검사를 통과했다.
설계나 과거 변경 언급을 포함한 문서 연관도이므로 실제 호출 그래프와 구분한다. 실행 중인 앱 화면 반영은 미확인이다.
게임 소스·자산·커밋·푸시 변경은 없다.

### 노션 요약 후보
- Feature 본문 근거로 기능→소스 연결선 397개를 재구성했다.
- 기능 노드에서 대표 근거 문서와 행 번호를 확인할 수 있다.
- 소스 의존성 그래프 121개 파일/292개 include 관계는 유지했다.
- 관련 문서: Feature/doc/2026-09-22_obsidian-source-graph.md

## Martelo 2 원본 동작을 1인칭 기준으로 검토

사용자가 전달한 Martelo 2.fbx를 설치된 FBX SDK로 직접 읽고 원본 골격 미리보기를 제작했다.65개 뼈·1개 애니메이션 스택·1.3초이며 표면 메시는 없는 파일이다. 실제 관절을 평가하니 오른발로 지지하면서 왼발을 높이 차고 회수하는 전신 동작이었다.

현재 게임은 팔만 표시하고 기본 격투 포즈를 코드에서 직접 구성한다. 그래서 몽타주 파일만 바꾸면 원본 동작이 나오지 않고, 원본을 재생하도록 연결해도 주된 공격인 다리는 보이지 않는다. 별도 발차기 스킬에서 공격 다리를 잠시 표시하고 카메라의 큰 기울임을 제한하는 방향이 맞다고 정리했다.

서브에이전트는 현행 포즈·카메라 코드와 원본 수치를 독립 검토했다. 주 담당은 준비·신전·회수의 실제 골격 화면을 확인했다. 이번 결과는 게임 캐릭터 적용 영상이 아닌 원본 골격 재생이다. 게임 소스와 자산을 교체하지 않았으며 빌드·커밋·푸시는 하지 않았다.

## Martelo 2를 실제 게임 캐릭터의 1인칭 화면으로 확인

### 요청과 구현
원본 골격 대신 게임 캐릭터에 적용된 모습을 보고 싶다는 요청을 받아, Martelo 2 애니메이션을 Manny 뼈대에 옮겼다. 실제 맵과 HUD, 기존 팔 전용 메시에서 원래 속도와 0.5배속으로 촬영했다. 기존 공격 입력을 바꾸지 않는 독립 게임 미리보기 명령을 추가했다.

원본은 왼발을 높이 차는 전신 동작이다. 팔만 보이는 현행 시야에서는 발이 보이지 않고 팔이 화면 밖으로 크게 빠진다. 카메라는 고정했으며 기본 가드와 동작 사이 전환은 블렌딩하지 않았다. 이번 영상은 정식 전투 연출 완성이 아닌 실제 적용 결과를 확인하는 자료다.

### 검증과 문제 해결
UE 5.8.2 빌드를 통과했고 최종 게임 촬영 209프레임에서 실패가 없었다. 원본과 임포트용 파생 파일의 40개 시점·65개 뼈 위치가 일치했다. 소스 의존 자산이 디스크에 빠지는 문제를 고친 뒤 새 Editor에서 재사용을 검증했다. 재베이크 포즈 차이는 최대 0.338cm다. 공용 자산 네 파일의 해시는 보존됐으며 소스·화면 검토와 변경 경로 검사를 통과했다.

기획 1명, 개발 2명, 검증 2명 역할로 나눠 진행했다. 최종 영상은 1280×720·30fps·약 7초다. 커밋과 푸시는 하지 않았다.

### 노션 요약 후보
- 실제 게임의 팔 전용 캐릭터에서 Martelo 2 원래 속도·0.5배속 비교 영상을 제작했다.
- 왼발 발차기 원본은 팔 전용 시야에서 주된 타격 동작이 보이지 않는다는 한계를 확인했다.
- 별도 프리뷰 자산과 재실행 명령, 포즈 검증 및 촬영 증거를 남겼다.

## 팔·몸통·다리가 보이는 전신 1인칭으로 전환

### 요청과 변경
팔만 보이던 캐릭터에서 몸통과 다리도 보이게 해 달라는 요청을 반영했다. 기본 맨손·너클의 1인칭 메시를 전체 Manny로 사용하고 머리·목만 숨긴다. 전신은 캡슐에 붙여 수직으로 유지하며, 아래보기는 전신 모드에서 -85도까지 허용한다. 팔 전용 옵션과 다른 시점의 기존 범위는 유지했다.

### 실제 화면에서 발견한 문제 해결
초기 표시에서는 몸통이 띠처럼 잘렸다. 기본 재질의 1인칭 마스킹·투영 경로를 분리한 대조에서 원인을 좁혔고, 전신을 일반 월드 투영으로 표시해 표면 끊김을 해결했다. 원본 메시·재질을 편집하지 않았다.

카메라는 캡슐 기준 (20,0,76), 손·팔꿈치 보정은 (0,12,18)이다. 맨손은 팔 길이 실측에 맞춰 기본 가드만 14cm 당기고 8cm 안쪽으로 모았다. 타격 끝점은 보존했다. 계산이 다른 너클에는 이 가드 후퇴를 적용하지 않는다. 검사 기준을 낮추지 않고 실제 손 크기와 상하 시야까지 확인했다.

### 검증과 범위
UE 5.8.2 최종 빌드는 22.86초에 성공했다. 기본 격투 480프레임, 너클 120프레임 및 상하·울트라와이드 3시점 검사를 통과했다. 최종 통합 촬영과 팔 전용 복귀 결과는 기능 결과 문서에 기록한다. 기획 1·개발 2·검증 2 역할로 소스와 실제 화면을 독립 검토했다.

Martelo는 원래 속도·0.5배속 전신 미리보기로 남긴다. 발을 보기 쉽게 시연용 표적만 210cm로 옮겼으며 실제 공격 범위나 입력 매핑을 바꾸지 않았다. 새 보행·발 접지 애니메이션은 추가하지 않았다. 커밋·푸시는 하지 않았다.

### 노션 요약 후보
- 팔 전용 표시를 머리만 숨긴 전신 1인칭으로 전환했다.
- 재질의 시야 가림을 해결하고 몸통·다리가 실제로 보이는 카메라를 적용했다.
- 맨손과 너클의 가드 계산을 분리해 기존 공격과 상하 시야를 유지했다.
- 실제 전신 아래보기와 Martelo 원래 속도·절반 속도 영상을 남겼다.

### 전신 1인칭 최종 통합 결과
최종 카메라 X20 설정으로 기본 격투 480프레임, 너클 120프레임과 추가 3시점, 이전 팔 전용 모드 390프레임, Martelo 전신 촬영 269프레임을 모두 실패 없이 마쳤다. 몸통·다리 표면과 너클 상하 시야를 실제 화면으로 검토했다. 영상은 약 8.97초이며 하단 HUD가 다리 일부를 가리는 일반적인 화면 겹침은 남는다. 기존 거리·공격 신전 검사 기준은 낮추지 않았다.

■ 작업 목표
카메라가 머리에 붙은 것처럼 달리기·점프·공격 동작을 따라가고, 실제 머리가 뒤로 도는 동작에서는 후방을 보도록 수정했다.

■ 주요 변경
전신용 머리 포즈 신호와 개별 애니메이션 재생 시점의 평가 포즈를 최종 화면에 연결했다. 머리를 숨긴 렌더 좌표 대신 원래 포즈를 사용하며, 회전 시 눈과 머리 사이 간격도 함께 돌린다. 실제 지상 속도에 맞춰 상체·머리·팔이 같은 박자로 흔들리고 정지 후 감쇠한다. 점프의 실제 높이는 중복 적용하지 않는다.
입력 조준은 유지하고 최종 화면에 움직임을 더했다. 회전 감도를 줄였을 때 180도 경계에서 반대로 튀는 문제도 연속 회전량 계산으로 수정했다. 이전 팔 전용 옵션은 유지했다.

■ 검증 결과
