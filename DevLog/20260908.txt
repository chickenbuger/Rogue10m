
[2026-09-08] 로스트아크풍 전투 HUD 개선 기획

작업 배경
현재 UI의 크기와 구조가 무너졌다는 피드백을 바탕으로, 실제 적용 전에 정보 배치와 크기 기준을 다시 정리했다.

조사와 결정
기획 담당 1명과 구조·시각 검증 담당 2명이 현재 코드와 이전 자료를 나누어 확인했다. 화면 전체로 늘어나는 프레임과 1920 기준 고정 좌표가 섞인 구조를 주요 원인 후보로 기록했다. 최신 플레이 화면에서 문제를 재현한 것은 아니다.
하단 전투 코어는 1080p 기준 1000×160, 경험치는 4px 선으로 제안했다. 현재 행동 5칸과 잠긴 아이템 표시 4칸을 유지하고, 직업 문장과 얇은 금속 테두리로 로스트아크 느낌을 표현했다.
아이템 사용 입력 1~5와 HUD 데이터 4칸 사이의 불일치는 구현 단계의 별도 확인 항목으로 남겼다.

검증 및 상태
소스와 시안을 대조했다. 생성 이미지는 분위기 참고용이며 실제 게임 화면이나 정확한 치수 도면이 아니다.
이번 변경은 기획 문서와 시안이다. 게임 코드·설정·바이너리는 변경하지 않았으며 빌드와 실제 플레이 검증은 후속 구현 단계에 남겼다.
Sprint#4-19-lostark-hud-design-plan 브랜치에서 기록했다. 기존 미커밋 변경을 보존했으며 커밋과 푸시는 하지 않았다.

[Notion 요약 후보]
제목: 로스트아크풍 HUD 리디자인 기획
요약: 전체 폭 장식을 중앙 전투 코어로 축소하고, 체력·자원·행동 슬롯의 정보 위계를 정리한다. 화면 비율별 정렬 문제와 아이템 표시 데이터 불일치를 해결 과제로 기록했다.
현재 상태: 기획·생성 시안 완료, 구현 전.

시각 검토 보완
생성 그림의 패널과 문장이 목표보다 커서, 정확한 1000×160 배치와 회피 표기를 담은 hud-layout-1920x1080.svg 치수 도면을 추가했다. 생성 그림은 재질·분위기 참고로 제한한다.
문서 검증 결과: git diff --check와 CheckGeneratedChanges.ps1가 통과했다. 기존 미커밋 바이너리에 대한 안내가 있었으며 이번 작업에서는 해당 바이너리를 변경하지 않았다. 신규 SVG는 XML 파싱과 1920×1080 선언을 확인했다.

[2026-09-08] 화면 비율 대응 전투 HUD 구현

기획에서 실제 적용으로 진행
화면 비율 변화에 따른 배치를 중심으로 소스를 수정하고 현재 설치된 UE 5.8.2에 적용하는 작업을 시작했다. Sprint#4-20-responsive-combat-hud 브랜치에서 기존 미커밋 작업을 보존했다.

담당과 구현
기획1명이 실행 설계와 작업 패킷을 정리하고, 개발2명이 C++ 반응형 구조와 Editor 위젯 적용 스크립트를 나누어 작성했다. 검증2명은 좌표 계산·슬롯 정합성·데이터 초기값·GC와 회귀 위험을 독립 확인했다.
하단 중앙1000×160 공통영역, 아래24 여백, 전체폭 경험치4 구성을 준비했다. DPI는 엔진 정책을 상속하고 추가 중복 배율은 적용하지 않는다.
전용 위젯5종을 분리하며 스킬5칸·아이템4칸은56 크기로 통일했다. 현재 빌드·Editor 통합 검증 진행 중이며 결과는 이어서 기록한다.

[Notion 요약 후보]
제목: 해상도와 화면 비율에 대응하는 전투 HUD
핵심: 공통 좌표계와 비율 유지 축소로 장식과 실제 컨트롤의 어긋남을 줄인다. 기존 게임 데이터 경로를 유지하면서 전용 소형 UI 파트를 분리한다.

[2026-09-08] Sprint#4-20 화면 비율 대응 전투 HUD 완료

작업 목적
화면 비율이 바뀔 때 배경·체력·문장·슬롯의 크기와 위치가 따로 움직이던 구조를 하나의 공통 좌표계로 정리했다. 설치된 언리얼 5.8.2에서 실제 위젯을 저장하고 게임 화면까지 확인했다.

주요 변경
- 하단 중앙1000×160 코어, 여백24, 전체폭 경험치4 구조 적용.
- 엔진 DPI 상속과 균등 축소 사용. 넓은 화면에서 문양을 가로로 늘리지 않음.
- 행동5칸·잠금 아이템4칸56 정사각형, 간격8. 직업 문장76 정사각형.
- 상단 대상 정보, 우상단 런 타이머, 좌하단 실제 로그2줄, 우측 획득 알림3줄 배치.
- 빈 System/TextBlock 미리보기 제거. 획득 수량을 본문과 툴팁에 표시.
- 전용 파트6개와 Main/Bottom 총8개 Widget Blueprint를 Editor에서 저장.
- 기획1·개발2·검증2 역할로 분리하고 빌드·에셋 저장은 직렬 실행.

검증 결과
최종 Editor 빌드 성공. Editor 계층·바인딩 검사 통과.
실제 게임1280×720,1920×1080,2560×1440,3440×1440,800×900/UI125%,1080p 복귀 총6조건에서 실패0건.
좁은 창은 코어816.6×130.7, 문장62.1×62.1로 함께 축소됨.
마나/스태미나, 직업4종, 타이머, 획득 수량10 및 시스템 로그 원문 검사 통과.
최초 테스트의 마나 활성화·런 시작 누락을 테스트 조건에서 보완했으며 실제 게임 규칙은 바꾸지 않음.
공백 검사 및 Harness 경로 검사 통과. 기존 Widget31개와 비교해 이번에 수정한 기존 자산은 Main/Bottom 두 개뿐임.

남은 범위
아이콘 데이터가 없는 스킬은 기존 키 레이블만 표시한다. 생성 콘셉트의 신규 던전·보스·스킬 그림, 메뉴 전체 개편, 별도 접근성 배율 설정은 이번 변경에 포함하지 않았다.
