## 적용

# Unreal Engine MCP Codex 스킬 설치 및 연결 등록

## 요청
WildCake/unreal-engine-mcp-codex를 개인 Codex 환경에 설치한다.

## 적용
공식 skill-installer로 저장소의 skills/unreal-engine-mcp-codex를 C:/Users/PC/.codex/skills/unreal-engine-mcp-codex에 설치했다.
Codex 전역 설정에 unreal-mcp를 Streamable HTTP 방식으로 등록했다. 연결 주소는 http://127.0.0.1:8001/mcp이다.
기본 포트 8000은 기존 Manager 프로세스가 사용하고 있어 8001을 선택했으며, 설치된 agents/openai.yaml의 연결 주소도 맞췄다.
변경 전 설정을 C:/Users/PC/.codex/config.toml.before-unreal-mcp-20261005-021614.bak에 백업했다.
CLI 등록 과정에서 생략된 기존 node_repl의 빈 args 배열을 복원했고, unreal-mcp 추가 외 기존 TOML 설정이 백업과 동일함을 확인했다.

## 검증
독립 검증 에이전트가 필수 스킬 파일 20개, Python 파일 7개의 AST 및 PowerShell 구문을 확인했다. 구문 오류는 없었다.
Codex 조회 결과 unreal-mcp가 활성화되어 있고 연결 주소가 8001임을 확인했다.
현재 Unreal Editor는 실행 중이지 않으며 8001 서버 연결은 확인되지 않았다. MCP 초기화 및 도구 실행 검증은 에디터 서버 기동 후 진행해야 한다.
게임 소스, 에셋, Saved 설정을 변경하지 않았으므로 Unreal 빌드는 실행하지 않았다. 커밋과 푸시는 하지 않았다.

## 사용
스킬은 다음 대화 턴부터 사용할 수 있다.
Unreal Editor에서 ModelContextProtocol.StartServer 8001을 실행하고 Codex의 MCP 연결을 다시 불러오면 실제 연결을 검증할 수 있다.

작업 브랜치 Sprint#5-8-fighter-arm-swing을 생성하고 기존 미커밋 작업을 보존했다. 기획 1명, 개발 2명, 검증 2명으로 조사·제작·스크립트·코드 리뷰·실제 게임 검증을 나눴다.

## 검증 결과

최종 렌더840프레임/28초 촬영 완료. 변경 전후218프레임/7.27초 비교 영상도 저장했다. HUD와 모션 블러로 세밀한 손가락/발 전체의 육안 확인에는 한계가 있다.

# 2026-10-05 격투가 전투 대기 자세

## 작업 배경
일반 Idle과 별도로 주먹을 올린 격투가 전투 자세를 준비했다. Sprint#5-9-fighter-combat-stance 브랜치로 전환하고 기존 미커밋 작업의 현재 바이트를 체크포인트에 보존했다.
기획 1명·개발 2명·검증 2명의 역할로 분담했다. 동시 슬롯 제한에 따라 기획·개발 이후 일부 담당을 독립 검증 역할로 재배치했다. 실제 에디터 호출은 직렬로 실행했다.

## 구현 내용
기존 공격의 시작 가드에서 2초 전투 대기 루프를 제작했다. 흉곽 호흡은0.3도로 작게 넣고 머리 방향·손목·손가락·다리 포즈를 유지했다. 최종 손발 위치에서 IK를 동기화했다.
Manny 소스 AnimBP의 부모를 native 전투 자세 AnimInstance로 바꾸고 FootIK 뒤, DefaultSlot 앞에 가드 블렌드를 추가했다. 공격과 회피 몽타주가 최종 우선권을 갖는다. 별도 FirstPersonMesh를 켜지 않고 기존 Appearance Mesh와 머리 카메라를 사용한다.
전투 활동 후3초 유지,0.20초 진입/0.45초 복귀, 차징 중 유지와 이동·질주·공중 우선을 구현했다. 메뉴·무기·사망·조종 해제 시 상태를 정리하며 캐릭터 컴포넌트에 Tick을 새로 추가하지 않았다.
Unreal Editor API로 신규 자세1개와 기존 공통 AnimBP1개만 저장했다. 전체 기존4,186개 uasset 중 나머지4,185개는같은SHA256이다. 기존 공격10종·관련 DA/몽타주/프로필·일반 Idle·머리 카메라 설정을 보존했다.

## 검증 결과
UE5.8 Editor 빌드 및 재로드 원시120Hz241포즈 검사 통과. 머리 이동 최대0.25cm, IK위치오차 약0.000032cm, 루프 시작·끝 오차0이다.
실제 플레이어640프레임·90,381포즈에서 일반 Idle·잽연계·스트레이트·4초차징·훅·걷기·점프·착지·너클·V·무기/메뉴 취소·회피 검증을 통과했다. 전투 입력은 기존 Combat 처리 경로로, V는 InputKey로 실행했다.
외형 평균 손 높이24.90cm 상승, 발 높이 차이 최대2.9345cm, 정지 캐릭터/메시 월드변환 오차0, 카메라최대7.0144도로 기존8도 이내다. 안정된 가드205프레임에서는 손목·손가락 로컬회전과 발 위치가 유지됐다.
기존 FistCombat9종·실제피해14회·V1인칭580/3인칭260샘플, StoneFist3종1,234검사 회귀 통과. 기존 FootIK 준비 스크립트의 새 그래프 인식도 별도 재로드 감사에서 확인했다.
실제1280×720 렌더640프레임 검사 통과 및21.33초 H.264 무음 영상 저장·전체디코딩 검사 완료. 독립 선택 화면 검토와 원시/실제 포즈 수치 검증을 구분했다.

## 확인한 문제와 범위
최초 걷기 검사3건은0.45초 복귀 블렌드 완료보다 빨리 검사한 시간 오류였다. 임계값을 완화하지 않고15틱 뒤 구간으로 교정해 통과했다. 가져온 루트 본 높이는 자식골반이 상쇄하므로 모델부유 판단에 쓰지 않고, 실제 발과 캡슐/메시 월드변환으로 검사했다.
전투 가드 자체는 안정적이지만 기존 너클 진입의 큰 세계 좌표 손가락 회전과 섞어 전체 공격을 흔들림 없다고 평가하지 않았다. 이전 기준선과 같은 몽타주 시각의1,551개 본포즈는 동일하다. 최초 블렌드는 일부 빨라진 범위가 있다.
실제 머리 카메라의1인칭에서는 오른손이 현재HUD뒤에 가려지고,3인칭 오른발도 일부 가려져 세부 접촉의 전체 육안 검증은 제한된다. 이동가드 레이어·별도 사망/재빙의 실행·전체 체형/장비관통·온라인 검증은 범위 밖이다.
Python문법·diff·하네스 경로 검사 통과. 커밋·푸시는 하지 않았다.

# 기본맵 기반 판타지 시작 마을 — Sprint#5-10

## 목표와 제작
unreal-engine-mcp-codex 스킬과 보유 Stylized Village 에셋을 사용해 시작 마을부터 제작했다. Sprint#5-10-start-village 브랜치에서 기존 미커밋 작업을 보존하고 기획·공간 제작·메뉴 연결·검증·기록 역할을 나눴다.
기본 플레이맵 /Game/FirstPerson/Lvl_FirstPerson을 에디터 템플릿 API로 복제하여 /Game/Rogue10m/Maps/StartHub를 저장했다. 120m × 120m 지면에 집 외관10채, 우물 광장, 네 방향 길, Equipment·Traits·Difficulty·Story 준비 구역과 북쪽 포탈을 배치했다.
신규 소유 액터 667개와 전용 머티리얼 12개(Instance 2개·Material 10개)를 만들었다. 남쪽 PlayerStart 1개와 외곽 숨김 BlockAll 경계 4개를 검증했다. NPC 자리는 공간·표지로 준비했으며 실제 서비스와 집 실내는 아직 없다.

## 메뉴 연결과 환경 설정
메뉴에서 캐릭터를 선택하면 StartHub로 이동한다. native PlayerController 목적지를 변경하고 메뉴 이동의 StartRun 옵션 자체를 제거했다. 마을에서는 WaitingToStart를 유지하고 기존 C++ 포탈 overlap에서 StartRun=1을 붙여 실제 기본 전투맵에 진입한다.
공식 Epic MCP 서버에 initialize·toolset 스키마·읽기·맵 로드·캡처 경로로 연결했다. 네이티브 MCP 도구가 노출되지 않아 로컬 JSON-RPC 클라이언트를 사용했고, 대량 생성·저장과 PIE는 기존 Epic Python Remote Execution으로 직렬 실행했다.
MCP 자동 시작과 8001 포트의 프로젝트 기본값을 기록하고 에디터 설정 readback을 확인했다. 미저장 패키지가 없는 상태에서 명시적 서버 시작 명령 없이 재기동하여 8001 자동 시작과 StartHub 재로드를 검증했다. 공식 MCP로 신규 맵·전용 재질13개 경로 저장 성공도 확인했다. 초기 XGE 셰이더 실패·로컬 재시도 로그를 근거로 -NoXGEShaderCompile 실행 옵션을 사용했다.

## 검증 결과
UE 5.8 Editor NoHotReload 빌드와 CheckGeneratedChanges 검사 통과. 메뉴 정적 검사와 실제 메뉴→캐릭터 선택→StartHub PIE 이동을 확인했다.
최종 runtime.json의 50개 검사가 모두 통과했다. PlayerStart 실제 착지·XY 오차 0cm·접지 간격 약 2.15cm, 허브 2초 이상 1200초 고정·비활성, 실제 광장 보행 약 2.01초·11.50m와 지면 관통 없음이 확인됐다.

완성된 오픈월드의 지도를 요청받아 Sprint#5-13-open-world-map 브랜치에서 실제 제작 좌표와 저장된 지형 데이터로 한국어 탐험 지도를 만들었다. 2200×2550PNG에 남쪽 야영지·서쪽 숲·중앙 강 교차로·동쪽 폐풍차·바위 고원·북쪽 보스 유적을 표시했다.
실제1800m 정사각형·북쪽+Y 방향을 유지하고1009²R16 지형의 음영과10m등고선을 넣었다. 세 갈래 길과 유한60m폭 강,18m×120m 교량3개를 같은 축척으로 표현했다. 전투 구역5곳·실제 고정 보스·야영지80m 안전 반경과 방위·500m 축척도 포함했다.
시작마을은 별도 맵이므로 지도 밖 포탈→입장 야영지 연결로 나타냈다. 수목은 실제183개PCG 타일의 분포를 기호화했으며 개별 나무 좌표를 그대로 캡처한 결과는 아니다. 건물도 지도 기호로 표현했다.

## 검증과 보존
독립 검토로 지역·보스·풍차·도로·교량 실제 좌표와 별도 시작마을 연결을 확인했다. 제작POI와 교량 정의 일치,183PCG타일 완료·실행 메시지 없음, R16모서리4곳/중심의 양자화 오차1cm이내를 검사했다. 입력3개 SHA256을 좌표JSON에 기록했다.
모든 라벨의 지도 범위·비중첩과 한국어 글꼴을 검사하고 PNG를 직접 열어 지역명·강·교량·길·범례·축척 가독성을 확인했다. Python AST·PNG무결성·diff 검사를 수행했다.
이번 작업은 지도 산출물과 도구·문서만 추가했으며 Unreal 에셋·C++·설정은 수정하지 않았다. 에디터 재실행·빌드·PIE는 필요하지 않아 생략했다. 기존 미커밋 작업을 보존했고 커밋·푸시는 하지 않았다.

# 기본 몬스터와 시작마을 안내 NPC — Sprint#5-14

## 목표와 제작 범위
사용자 최종 요청에 맞춰 몬스터는 Idle·이동·기본 공격, NPC는 간단한 대화와 기본 아이템 지급으로 범위를 확정했다. Sprint#5-14-open-world-monsters 브랜치에서 기존 맵·전투·HUD 미커밋 작업을 보존했다. Lazy Codex 패킷 M1 재료 조사, M2 기본 공격, M3 기존 6종 연결, M4 NPC 보급, M5 통합 검증·기록으로 나누고 설계·구현·빌드·독립 검토·문서를 역할별로 진행했다.
오픈월드의 초록 점액체·포자 버섯·붉은 점액체·철갑 등껍질·가시 수문장·아자토르에 보유 모델과 호환되는 Idle·이동·공격·피격·사망 클립을 연결했다. 기존 체력·피해·경험치·속도·사거리와 지역 스포너 정책을 유지했다. 구매 모델과 원본 25종 데이터를 보존하고 새 전용 DataAsset 6개와 기본 공격 Profile 6개를 만들었다.

## C++와 실제 맵 적용
Tick 없는 기본 공격 컴포넌트가 준비→타격→회복을 처리한다. 타격 시 대상 캡슐·거리·방향·높이·벽 차단을 확인해 한 번만 피해를 주고, 사망 시 공격과 AI를 정리한다. 실제 속도에 따라 Idle과 이동 클립을 선택한다. 공격 중 AI Focus가 잠근 방향을 바꾸지 않도록 검토 결과를 반영했다.
StartHub 남쪽 시작점 근처에 길잡이 아린을 저장했다. 보유 Quinn 모델과 MM_Idle을 사용하며 F로 대화 열기→회복 포션 2개 수령→닫기를 진행한다. 가방이 꽉 차면 수령 기록을 남기지 않고 공간 확보 후 재시도한다. PlayerState와 GameInstance 세션 기록으로 중복 수령을 막는다.
기존 포탈의 OpenLevel은 Pawn을 다시 만들기 때문에 지급한 보급품의 GUID와 실제 남은 수량만 추적하는 Subsystem을 추가했다. 물약을 사용하거나 버렸다면 해당 수량을 다시 만들지 않고 다음 맵에 남은 스택만 전달한다. Inventory와 RunPortal에 한정된 연결부를 추가했다. 영구 프로필 저장과 특성 강화는 이번 기능 범위에 포함하지 않았다.
실제 화면에서 대화 카드가 보이지 않던 문제를 발견했다. NativeConstruct 이후 트리를 생성하던 방식을 RebuildWidget 이전 생성으로 수정하고 빌드·재시작 후 한글 대화와 수령 문구를 확인했다.

## 최종 검증과 보존
UE 5.8 Editor NoHotReload 첫 빌드 111.69초, 대화 표시 보완 빌드 70.11초 성공. 저장 후 에디터 재시작의 에셋·클립 호환·마을 기존 677개 액터 보존 검사 100항목을 통과했다.
최종 몬스터 PIE 219항목 모두 통과했다. 6종의 Idle·이동 클립 시간 진행, native AI 추적·실제 플레이어 피해, 1회 타격·범위 이탈 회피·사망 취소를 확인했다. 미로드 지역 종은 현재 로드된 지형의 실제 native 스포너를 검사 세션 안에서 사용했다. 플레이어에게 검사 코드로 직접 피해를 주지 않았다.
최종 NPC PIE 57항목 모두 통과했다. 실제 지급·중복 방지·만석 재시도·대화 거리 종료·마을 대기 유지·물약 한 개 사용·실제 포탈 overlap·잔여 한 개 전달·1200초 런 시작과 카운트다운을 확인했다. 실제 F 입력으로 열기·2개 수령·닫기도 통과했고 실제 한글 카드 화면 2개를 저장해 직접 검토했다.
Content 6,292개 전체 SHA256 기준선에서 6,282개 동일, 허용된 기존 10개 변경·신규 15개만 확인했다. 원본 구매 에셋과 마을 배치를 보존했다. 모든 에셋 편집·저장은 에디터로 수행했다. 독립 Unreal 코드 검토와 Python 문법·프로젝트 JSON·diff·하네스 경로 검사를 수행했다.
검사 소유 PIE 종료와 StartHub 미저장 맵·이번 소유 콘텐츠 없음 확인. 전체 20분 플레이·네트워크·패키징·출시 성능 검사는 이번 집중 검사 범위 밖이다. 커밋·푸시는 하지 않았다.

# 길잡이 아린 NPC 이미지 제작 — Sprint#5-14 추가

# 하단 전투 HUD 시안 적용 — Sprint#5-15

## 목표와 적용 결과
승인한 imagegen 시안을 실제 UMG HUD에 적용했다. 검정·청동 패널을 화면 하단 20 논리 단위 기준으로 내리고 체력·직업 자원·중앙 무기 문장·스킬 5칸·아이템 4칸·레벨·경험치를 하나의 1200×196 디자인 공간에 정리했다. 경험치 바는 패널 내부로 옮겼다.
Compact 전용 파트 5개를 만들고 기존 Main/Bottom에 연결했다. 실제 무기명·자원·스킬·쿨다운·아이템 획득 데이터를 계속 사용한다. 잠금 기호와 첫 기본 공격 준비 강조, HOLD 두 줄 입력을 연결했다. 획득 카드는 실제 아이콘·이름·수량을 표시하며 공간이 좁으면 패널 위로 이동한다.

## 구현과 검증
HUD C++ 6파일과 Editor 적용·검증 스크립트, 기존 프레이밍 보호 조건, 별도 게임 QA를 보강했다. 위젯 바이너리는 Unreal Editor에서만 수정·컴파일·명시 저장했다. 공식 MCP로 7개 패키지 dirty=false를 확인했다.
UI 전체 Editor 빌드는 28.42초에 성공했다. 다른 채팅의 에디터가 고정 DLL을 사용 중이어서 최종 검증 모듈은 UBT ModuleWithSuffix로 별도 빌드했고 25.40초에 성공했다. 실행 중인 에디터를 강제 종료하거나 다른 채팅에 메시지를 보내지 않았다.
실제 StartHub 게임에서 1280×720·1920×1080·2560×1440·1920×800·800×600·1920×1080의 6단계를 실행했다. 작은 화면에는 ApplicationScale 1.25배도 적용했다. 922개 assertion, 실패 0이며 새 PNG 6개의 생성 시각·크기를 확인했다. 자원 바·실제 무기명·원형 게이지·잠금·실제 공격 쿨다운·경험치·획득 데이터·알림 만료·일반 View 재사용을 검사했다.
첫 화면의 HOLD 둘째 줄 잘림은 입력 영역 42·슬롯 108로 늘려 해결했다. 콤보 공격의 쿨다운 검사는 실제 콤보 종료 직후로 옮겼으며 전투 데이터나 전투 로직은 수정하지 않았다. 일반 획득/경험치의 수량 0 로그 필터는 기존 규칙을 유지한다.
1920×1080과 800×600 실제 캡처를 검토했다. 기존 UI 112개 중 Main/Bottom 두 개만 바뀌고 나머지 110개는 SHA256이 동일했다. 신규 에셋은 Compact 5개다. 독립 C++·UMG API 리뷰, Python AST·PowerShell parse·diff·CheckGeneratedChanges·Harness 경로 검사도 통과했다.

# 길잡이 아린 FBX 제작·적용 준비 — Sprint#5-14 후속

## 요청과 준비한 내용
사용자가 아린 콘셉트를 실제 FBX로 제작해 시작마을 NPC에 적용하도록 요청했다. Sprint#5-14-open-world-monsters에서 기존 미커밋 작업을 유지하고 A1 참조·A2 생성/리깅/FBX·A3 Unreal 연결·A4 검토/기록 패킷으로 나눴다.
imagegen 내장 도구로 동일한 얼굴·초록 여행복·땋은 머리·가죽 가방·물약 두 병을 유지한 정면 전신 T포즈를 제작했다. 흰 배경과 그림자 없는 구도로 정리하고, 손의 물약을 허리/가방으로 옮겨 리깅용 손을 비웠다. 참조와 실제 프롬프트를 프로젝트에 저장했다.
읽기 전용 조사로 NPC의 메시와 Idle이 같은 Skeleton 객체여야 함을 확인했다. 기존 FBX 임포트와 IK Rig/Batch Retarget 스크립트를 재사용해 새 Skeleton의 Idle을 연결하는 경로를 정리했다. 기존 Quinn/Manny Skeleton과 공유 MM_Idle은 보존한다.

## 연결 확인과 진행 상태
TRIPO_API_KEY의 Process/User/Machine 환경변수와 관련 MCP 설정을 값 노출 없이 확인했으나 키가 없다. 사용 가능한 3D 생성 MCP도 없어 실제 모델 생성 단계에는 Tripo API 연결이 필요하다. 공식 최신 인증·휴머노이드 리깅·FBX 변환 명세를 확인하고 사용자에게 로컬 키 설정을 요청했다.
현재 완료된 것은 모델링 참조·아키텍처·적용 경로 준비다. 유료 태스크를 생성하지 않았으며 지갑 잔액·실제 FBX·새 SkeletalMesh·게임 외형 적용을 완료했다고 기록하지 않는다. PNG·원본 사본 일치·육안·diff/하네스 검사를 수행했다. 실제 새 에셋 적용 전이므로 빌드/PIE는 실행하지 않았다. 커밋·푸시는 하지 않았다.

# Apollo 스킬로 아린 3D·FBX 제작 시도 — Sprint#5-14 후속

## 요청과 실제 제작 범위
사용자가 지정한 Merchantlee99/apollo 소스의 실제 apollo-asset-factory 스킬을 읽고 로컬 실행했다. Sprint#5-14-open-world-monsters에서 A2b 입체 초안·A2c 간단 리깅·A3b 검증 후 적용 패킷을 추가하고 기존 미커밋 작업을 보존했다.
전용 Python 환경과 공식 stdio MCP·loopback API, 공식 체크섬과 일치하는 portable Blender4.5.14를 준비했다. MCP2.x의 FastMCP 모듈 불일치는1.30.0으로 맞췄다. Apollo 설정 POST의 Lock 교착은 작업 소유 API 재시작과 BLENDER_PATH 프로세스 환경으로 우회했다. vendor 소스·사용자 전역 환경 설정은 변경하지 않았다.
단일 이미지 compile 계획의 textured_cutout을 실제 실행해2.5D FBX·GLB·OBJ를 생성했다. 이어 imagegen 내장 도구로 같은 아린의 정사각 정면·정측면·뒷면 T포즈 참조를 만들고 원본 PNG·프롬프트·해시를 보존했다.
외부 뷰를 묶는 public MCP 입력이 없어 실제 변경하지 않은 ApolloHullAdapter를 프로젝트 스크립트에서 직접 호출했다. 정면·측면 실루엣으로 높이1.7m의 입체 GLB를 생성했다. 뒷면은 외형 검토 자료이며 형상 생성에는 쓰지 않았다. 실제 GLB를 새 Apollo asset에 공식 MCP 업로드한 뒤 preview compile·후보 선택·Unreal export·download로 입체 FBX와 GLB를 저장했다.

## 검증과 실패 판단
최종 입체 형상은12,442정점·24,880삼각형이다. 닫힌 표면·양의 체적·단일 연결 등11검사를 통과했다. 실제 FBX 재수입에서 높이1.7m·삼각형24,880개·뼈0·Action0을 확인했다. 원본 GLB와 export GLB의 SHA256 일치, native manifest 파일 체크섬과 ZIP CRC를 검사했다. 회색 프리뷰는 실제 무재질 FBX의 검사 표시이고 모델에 텍스처를 추가한 결과가 아니다.
실제 hull에20본과 의미 영역 가중치를 지정하고 세 면 색상을 투영했으나 팔65°·55° 내리기 모두 변형 기준에 실패했다. 최대 변 늘어남7.38배·6.34배이며 상한4배를 유지했다. 실제 사선 화면에서 얼굴 중복·흰 경계·망토와 몸통 텍스처 늘어짐도 확인했다.
두 실패 후 Reviewer로 돌아갔다. 가중치 보정만으로 얼굴 중복과 표면 UV 문제를 해결할 수 없다고 판정해 추가 반복·기준 완화를 하지 않았다. 게임용 리깅 FBX와 Idle은 출력하지 않았다. 기존 NPC의 같은 Skeleton 메시·Idle 계약을 만족하지 못해 Unreal 임포트와 외형 교체를 실행하지 않았다. StartHub의 Quinn NPC와 대화·물약 지급 기능은 유지했다.
Apollo upload 점수1.0·export ready는 파일 처리 상태이다. 직접 생성한 CPU local_draft 출처와 리깅 실패를 별도 보고서·패키지에 동봉했다. Hunyuan3D·TRELLIS·SF3D·TripoSG 생성 서버는 연결되지 않았고 외부 API 키나 유료 태스크는 사용하지 않았다. 최종 전달물은 정적 무리깅·무애니메이션·무완성텍스처 3D 초안이다.
Python6스크립트 AST·하네스 경로·독립 provider/FBX 검토를 수행했다. C++·엔진 콘텐츠를 변경하지 않아 빌드와 PIE는 재실행하지 않았다. 커밋·푸시는 하지 않았다.
