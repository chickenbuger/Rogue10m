[사용자 요청]

[통합 범위와 계획]
기존 전투·애니메이션·카메라·HUD·특성·마을/NPC·영속 저장·오픈월드/몬스터와 원본/검증 자료, Studio 제거, 설계·도구·설정·문서를 보존한다. P1 조사, P2 검증/규칙/기록, P3 커밋·develop→test→main 승격·푸시의 3개 패킷으로 나눴다. 바이너리 에셋과 게임 코드는 이번 통합 작업에서 편집하지 않는다.

[초기 확인]
원격 fetch 후 develop/test/main은 로컬과 같은 b7ab6b6이며 작업 HEAD 7d2b688의 조상이다. 읽기 전용 파일 조사에서는 100MiB 초과 파일·고신뢰 자격 증명·중첩 저장소·생성 캐시 게시 대상을 발견하지 못했다. 50MiB를 넘는 검증 JSON 등이 있으며 현재 상태 보존 범위로 관리한다. 기존 Studio 삭제 21개는 별도 기능 문서의 사용자 요청과 일치한다.

[검증 진행]
Build.cs 변경에 필요한 프로젝트 파일 생성을 완료했다(16.47초). 현재 Editor 전체 빌드와 독립 소스/통합 검토, 스테이징 경로/크기 검사를 진행한다. 최초 제한 실행은 엔진 접근 문제로 실패했고, 승인된 실행 범위에서 프로젝트 생성에 성공했다. 실제 main 병합 성공 후 Sprint5를 닫고 다음 기능은 Sprint#6-1부터 시작한다.

[동시 작업 분리]
검증 후 다른 채팅의 새 스킬트리 작업과 브랜치 전환을 감지했다. 사용자는 빌드·QA를 통과한 상태만 게시하고 새 작업은 보존하도록 선택했다. 공유 작업 파일을 덮어쓰거나 stash/reset하지 않고, 최초 스테이징 blob과 파일 목록으로 별도 게시 인덱스를 구성한다. 이후 추가된 스킬트리 코드/계획/증거는 이번 스냅샷에서 제외한다. 최초 blob은 생성 시점·클래스 내용·가능한 baseline SHA 대조로 확인했다. 현재 진행 중인 Sprint#5-38 작업 브랜치는 그대로 유지하고, main 통합 뒤 기준 커밋만 새 체크포인트로 맞춘다. 다른 채팅과 직접 조율하는 사용자의 승인은 해당 채팅의 실제 사용자 답변에서 확인했다.

GitHub 연결 조회로 인증 사용자와 저장소 소유자 chickenbuger 일치, 저장소 ID 1278064834, admin/push 권한과 기존 origin URL 일치를 확인했다. 저장소는 공개 상태다. 자동 승인 검토가 공개 저장소로 코드·에셋·원본·검증 자료를 전송하는 별도 명시 승인이 필요하다는 이유로 push를 두 차례 거절했다. 사용자에게 목적지와 6,084개 변경 범위를 제시하여 공개 게시 승인을 요청했다. 원격 push는 아직 실행되지 않았으며 기존 원격 main b7ab6b6을 완료 상태로 바꾸어 보고하지 않는다.

[작업 목표와 진행 방식]
보스 처치 이후 승리 판정이 이어지지 않던 흐름에 결과창과 진행 저장, 시작마을 귀환을 연결했다. R1 종료·사망 연결, R2 결과 화면·입력, R3 빌드·실제 게임 검증·리뷰, R4 문서·최종 통합으로 패킷을 나눴다. 브랜치는 Sprint5 main 병합 전에 생성했으므로 기존 번호를 유지한다. 원본의 스킬트리와 체크포인트 작업을 보존하기 위해 별도 작업 폴더에서 개발했다.

[플레이어가 보게 되는 변화]
활성 런에서 아자토르를 처치하면 기존 경험치 3,000과 골드 300을 한 번 받고 승리 결과를 본다. 결과창에는 보상과 저장 상태가 표시되며 Enter/Space 또는 귀환 버튼으로 다시 저장한 뒤 StartHub로 돌아간다. 저장 실패 시 오류와 재시도를 보여주고 이동은 막는다. 재시도는 기존 보상을 다시 지급하지 않는다. 시간 초과와 실제 플레이어 사망도 패배 결과창에 연결했다. 완료 후 피해와 입력을 막고, 마을에는 StartRun 옵션을 전달하지 않는다.

[빌드와 실제 검증]
고정 콘텐츠 기준 Editor 빌드가 90.27초에 성공했다. D3D11 1280×720의 실제 렌더링 게임에서 여섯 프로세스, 총 200개 검사가 모두 통과했고 실패 0·종료 코드 0이다. 승리 Write 53개·별도 프로세스 Read 12개, 저장 실패 58개·복구 결과 Read 12개, 시간 초과 33개, 실제 사망 32개다.
StartHub의 실제 포탈 중첩으로 OpenRunMap에 들어가 저장된 BP_OW_FinalBoss를 플레이어 좌클릭의 마지막 피해로 처치했다. 중복 피해·사망 통지에 보상이 늘지 않고 일반/테스트 몬스터로 승리하지 않는 것을 확인했다. 종료 결과 변경·동일 월드 재시작·승리 후 치명적 피해를 거절했다. Growth, 아이템 GUID·골드를 포함한 Inventory, Combat 해금/바인딩, Town 스냅샷이 마을 이동과 새 프로세스에서 정확히 복원됐다.
저장 실패는 기존 QA 저장에 Windows 읽기 공유 핸들을 열어 실제 쓰기를 막는 방식으로 재현했다. Saved 파일 내용을 직접 편집하거나 파일을 교체하지 않았다. 오류에서 귀환이 막히고, 핸들을 닫은 뒤 Enter가 동일 보상을 저장하고 마을로 이동했다. 승리·저장 실패·시간 초과의 실제 화면을 열어 글자와 안내를 확인했다. 독립 정적 검토에서 결과창 배경 정렬과 기존 특성 fixture의 종료 계약을 보완했다.
기존 특성 효과 회귀도 101개 검사·실패 0·종료 코드 0으로 통과했다. 렌더된 핵심 검사 200개와 합쳐 총 301개를 확인했다. 회귀 결과는 Feature/doc/evidence/trait16-runtime-20261011/Rogue10m_Town_QA_boss_completion_frozen1/effects-results.txt에 보존했다.

[초기 실패와 콘텐츠 고정]
처음 연결한 공유 콘텐츠가 Write와 Read 사이에 변경돼 대검 Hybrid 기술 5개 차이를 검출했다. 예상 스냅샷 20:40:43, 공유 에셋 수정 20:41:00, Read 저장 20:41:22로 시점을 대조했다. 비교를 완화하지 않고 Content 연결을 제거한 뒤 체크포인트 207c595의 콘텐츠 파일 6,417개를 별도로 고정했다. 콘텐츠 트리 890c83ca26eb5ac410bbd9b0d34e406c9a3c44e3와 기준 소스 205개를 대조하고 여섯 프로세스를 다시 통과했다. 초기 프로필 이름 제한과 보호 메서드 접근 문제도 QA에서 수정했으며 실패 증거를 보존했다.
게임 실행 시 자식 프로세스에만 UE_SKIP_UBT_SDK_SETUP=1을 전달하고 부모 환경을 복원한다. 이미 성공한 Windows Editor 빌드 이후 플랫폼 SDK 재탐색만 줄이는 설정이며 컴파일·빌드 검사를 대체하지 않는다.

[검증 범위와 현재 상태]
순간이동·AI 정지·이동 준비 중 임시 무적을 사용하는 통제된 검사다. 보스 체력을 비치명적 피해로 1까지 낮춘 후 실제 좌클릭으로 마지막 피해를 줬다. 시간 초과는 실제 타이머의 잔여 시간을 1초로 줄여 확인했다. 전체 20분 플레이와 밸런스, Shipping 패키징, D3D12·장시간 GPU, 네트워크와 모든 무기/외형의 회귀는 이번 검증이 아니다.
기능 구현·고정 빌드·핵심 QA·특성 효과 회귀·정적 검토와 문서를 마쳤다. 최종 경로 검사·원본의 병행 작업을 보존하는 통합·커밋·로컬 승격은 준비 중이며 현재까지 공유 원본 소스와 스킬트리 작업은 수정하지 않았다. 원격 push도 실행하지 않았다. 기존 체크포인트 채팅에서 공개 원격 자료 전송의 명시 승인을 기다리는 상태가 이어지므로, 그 결과가 확인되기 전에는 게시 완료로 보고하지 않는다.
