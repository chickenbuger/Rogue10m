# 탐험 종료와 마을 복귀

## 플레이 흐름

StartHub 포탈 → OpenRunMap 20분 탐험 → 최종 보스 처치 → 토벌 성공 → 저장 → 결과 화면의 **마을로 돌아가기** → StartHub 순서다. 결과 화면에서는 마우스 버튼 또는 Enter/Space로 복귀한다.

플레이어 사망과 시간 초과는 탐험 실패로 종료한다. 먼저 확정한 승리/패배는 이후 사망 알림이나 타이머로 뒤집히지 않으며, 종료한 같은 월드에서 StartRun을 호출해 시간을 초기화할 수 없다. 다음 탐험은 마을 포탈에서 시작한다.

## 보상과 저장

- 기존 최종 보스의 Data Asset 경험치와 난이도 보정, 기존 처치 골드·특성 보너스를 사용한다. 추가 클리어 보너스나 보상 상자를 덧붙이지 않는다.
- 보스 사망에서 경험치·골드·토벌 기록을 한 번 반영한다. 마지막 명중의 숙련 지급까지 끝난 상태를 기존 ProgressionSubsystem으로 저장한 뒤 결과 창을 표시한다. 결과 창의 금액은 실제 지급한 값이다.
- 중복 사망/추가 피해/결과 재시도는 보상을 다시 지급하지 않는다. 다음 탐험의 새 보스는 정상적으로 보상을 지급한다.
- 기존 프로필별 성장·전체 인벤토리·아이템 GUID/강화·스킬/바인딩·특성·난이도와 Save v3의 숙련·투자·활성 계열 원장을 저장한다. 이번 보완은 SaveGame 형식을 변경하지 않는다.
- 저장이 실패하면 결과 창에 이유를 표시하고 복귀를 차단한다. **저장 재시도 후 귀환**은 이미 지급한 보상을 다시 지급하지 않고 저장만 재시도한다. 복귀 직전에도 선택/연결 프로필과 저장 성공을 다시 확인한다.
- 마을은 StartRun 옵션 없이 열어 대기 상태로 돌아간다. 생산 저장의 런 도중 위치·현재 HP·월드 드롭 비저장 정책은 기존과 같다.

## 데이터와 책임

- `Rogue10mGameState`: 권한이 있는 Running 상태에서 한 번만 terminal 결과로 전환한다.
- `Rogue10mRunCompletionComponent`: GameMode가 소유한다. 실제 최종 보스/플레이어·로컬 단일 플레이를 확인하고 정산·저장·귀환을 조정한다.
- `Rogue10mBasicMonster`: 기존 보상을 지급한 후 최종 보스 사망을 전달한다. F6 테스트 인스턴스는 보상과 승리에서 제외한다.
- `Rogue10mRunResultWidget` / PlayerController: 이벤트로 결과·저장 상태를 표시하며 UIOnly 입력과 포커스를 유지한다. 종료 후 전투 피해와 게임 메뉴 열기를 차단한다.
- TownMap의 기본값은 `/Game/Rogue10m/Maps/StartHub`다. 보상 수치는 기존 Monster Data Asset을 조정한다.

## 검증 실행

`Scripts/ValidateRunCompletion.ps1 -Label <새 QA 이름>`으로 렌더된 별도 게임 프로세스에서 승리/재실행 복원, 실제 저장 실패·재시도/재실행 복원, 시간 초과, 사망을 검사한다. 기존 생산 저장과 다른 QA 슬롯 세 종류를 강제한다.

QA는 실제 포탈·맵·배치 보스·마지막 전투 타격·UMG Enter 입력·마을 재로드를 사용한다. 비어 있지 않은 숙련·유료 투자·활성 계열을 준비하고 최초 완료 저장, 귀환, 별도 프로세스에서 실제 디스크 저장 버전과 전체 원장을 비교한다. 북부까지의 이동은 순간이동으로 단축하고 보스 체력을 비치명적 사전 피해로 낮추므로, 전체 20분 밸런스나 전투 난이도 검증은 별도다. [Save v3 보완 결과](../Feature/doc/2026-10-20_boss-save-v3-integration.md)에 최종 실행 결과를 기록한다.
