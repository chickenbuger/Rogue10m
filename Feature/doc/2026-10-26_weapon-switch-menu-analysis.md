# 무기 교체·문맥 메뉴·4슬롯 영향 분석 최종 결과

이번 packet은 [코드 영향 분석과31개 테스트 계획](../architect/2026-10-26_weapon-switch-menu-analysis.md), [최신 통합 규칙](../../Docs/RapidFieldRules.md), 읽기 전용 소스 해시/보존 증거를 작성했다. 실제 무기 교체·입력·HUD·일시정지·보스·미니게임·보상·저장 코드는 변경하지 않았다.

## 확인한 영향

- 현재 무기/인벤 변경 경로는 행동 gate 없이 진행한 뒤 공격을 취소한다. 요청을 인벤 mutation 전에 거부하는 W1 경계가 필요하다.
- 현재 프로필 전환은 binding 맵을 지우고 기본 세팅을 다시 채운다. 무기별 런 사전4슬롯 프리셋 보관/복원 W2가 필요하다.
- 기존 숫자 공격 cooldown은 남지만 source가 reset되고0.5 floor는 없다. 지연 시작 getter가0일 수 있으므로 절대 deadline과 모든 대상 cooldown 도메인/HUD를 검토하는 W3가 필요하다.
- 일반 메뉴에 안전 문맥 pause는 없다. 명시적 safe provider와 중첩 pause 소유권·닫기 입력을 처리하는 M1이 필요하다. 입장만으로 자동 정지하지 않는다.
- E는 현재 회피/예약키와 충돌한다. Ctrl은 modifier 검증·held modifier 거부·key selector에서 차단된다. 기존 HUD4칸은 마우스/차징 의미라 새 Ctrl/Q/E/R4슬롯과 다르다. 기존 enum 재정렬 대신 별도 슬롯 모델/Enhanced Input·HUD·drag/drop 접점을 제안했다. 실제 IMC 에셋/렌더링은 검사하지 않았다.
- 미래 무기는 프로필 배열만 추가하면 자동 지원되는 상태가 아니다. 현재 두 숙련 트랙/조건 ID whitelist/최대2 mastery snapshot 검증의 별도 확장 검토가 필요하다.

## 확정/미정 규칙

4액티브 Ctrl/Q/E/R은 마우스 기본/특수 공격 밖이며 무기 프리셋과 함께 전환한다. 교체는 대기/이동/달리기 허용, 공격/사망 차단, 무적 없음. cooldown은 `max(남은 시간,0.5초)`이고 가산이 아니다. 필드 메뉴는 게임/런 timer 계속, 안전 메뉴는 둘 다 정지다.

대검은 고정 장소·상점·퀘스트에서 획득하고, 상점 기본/퀘스트 희귀/드롭·히든 피스 좋은 등급 기회로 구분하며 확률/표는 미정이다. 숙련100은 자동 승급, 특정 행동은 필수 gate가 아니다. 보스는 특정 기술 없이 기본 조작의 대응 경로가 있어야 한다.

런 성장/손실/장비·기술은 런 종료 초기화, 로비 강화/재화와 정보용 Discovery는 보존한다. 융합 실패 생존은 런 회복불가 마나/내공 손상으로 조건 미달이며 다음 판 초기화한다. 프로필별 해당 융합 최초 성공1회 큰 로비 재화, 중복 성공/콜백/저장 재시도 중복 지급 금지, 금액 미정이다. 모두 요구사항 기록이고 새 정책 구현/실제 세이브 이행은 없다.

현재 너클/대검에 방패를 추가하지 않는다. 한손검·둔기와 방패/패링은 후속 범위다. 장비에 따른 기본 회피/가드 방향은 유지하지만 방어 키는 아직 미정이다.
