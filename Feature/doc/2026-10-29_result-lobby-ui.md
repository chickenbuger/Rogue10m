# 정산 재화 UI와 포기 처리 (2026-10-29)

기준7891e1b2, Sprint#9-8-result-lobby-ui. 핵심은 제한 시간 안에 성장 선택으로 보스를 처치하는 루프다. 이번 작업은 종료·포기 정보를 정확히 보여주고 실패 재시도를 안전하게 만드는 범위다.

## 구현
- 이번 로비 포인트 획득량과 기존 지출을 뺀 정산 후 사용 가능량을 구분한다. 런 골드/크리스탈 잔액과 다음 판 초기화도 별도로 표시한다. 첫 지급의 실제 증가량(cap 후)을 transient RunId 영수증에 캡처하므로 재시도 후 +12가 +0으로 바뀌거나 중복 지급되지 않는다. 유효한 +0도 표시한다.
- 저장 실패는 숫자를 유지하고 저장 대기/기존 오류 안내를 표시한다. 성공 재시도 후 실제 저장 상태로 전환한다. 다른 프로필의 결과는 금액·저장완료 표시를 숨기고 귀환 명령도 차단한다. Widget은 검증된 읽기 전용 경제 요약만 읽는다.
- 포기는 별도 Abandoned 종료 상태다. 비용 차감이 확정된 뒤 필드 입장 직전에 기준선을 저장한다. 입장 저장이 실패하면 이동을 차단하고 기준선 후보를 되돌린다. 마을에서 비용을 더 쓴 뒤 재시도하면 최신 비용 차감 값을 사용한다. 실제 런 시작 표식이 있어야 중단 복구가 작동하므로 실패한 입장 시도가 나중에 준비 비용을 환불하지 않는다.
- 포기 시 런 안의 세 재화 이득/지출을 기준선으로 복원하고 보상은 0이다. Town 지출 원장은 그대로 보존한다. 런 물품·장비·숙련·학습은 허브 재연결에서 초기화하고 Discovery는 영구 정보로 유지한다. 공개 정보는 다음 판 학습/사용권이 아니다. 저장 실패에는 같은 적용 영수증을 재저장하고 귀환을 차단한다.
- 포기 이후 지연 피해·몬스터 보상이 더해지지 않도록 기존 플레이어/몬스터 종료 가드를 Abandoned에도 적용한다.
- v5 별도 `_v5` 슬롯을 사용한다. 읽기 우선순위는 v5→v4→legacy이며 상위 파일이 존재하나 잘못되면 하위로 되돌아가지 않는다. v4 이행은 기존 도메인/Discovery/RunId/영수증을 보존하고 v4 원본에 쓰지 않는다. 기준선이 없는 구 활성 런은 포기를 거부하며 0으로 추정 복원하지 않는다.
- 활성 v5 런 저장으로 새 허브를 열면 이어하기 대신 포기로 복구한다. 마지막 성공 저장 이후 강제 종료까지 무손실은 보장하지 않는다.

## 사용자 진입 경로
공개 Controller API `RequestAbandonCurrentRun()`과 콘솔 `AbandonRun`을 지원한다. 콘솔에서 실시간3초 이내 두 번 실행하여 확인하며 World/Profile/RunId가 달라지면 확인을 취소한다. 기존 F9/F10 등 바인딩은 변경하지 않았다. 실제 설정 버튼은 아직 없고 콘솔은 프로토타입 경로다. 메인 메뉴 QuitGame의 기존 동작은 변경하지 않았으며, 재진입 시 활성 저장의 허브 복구로 처리한다.
