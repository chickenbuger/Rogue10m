# 격투가 전투 자세 적용

브랜치: `Sprint#5-9-fighter-combat-stance`. 일반 대기와 별도로, 맨손·너클 전투 후 양손을 올리는 전투 대기 자세를 실제 Appearance Mesh에 연결했다.

## 동작

- 처음에는 기존 손을 내린 일반 Idle을 사용한다. 공격·차징·회피 후 전투 자세로 전환하고, 동작 종료부터 기본 3초 동안 유지한다. 차징은 버튼을 누르는 동안 유지한다.
- 가드는 기존 공격의 시작 포즈를 사용하며 흉곽에 0.3도 호흡을 더한 2초 루프다. 손목·닫힌 손가락·발의 기본 자세를 보존했다.
- 진입 0.20초, 복귀 0.45초로 블렌드한다. 이동 입력·질주·공중 상태에서는 기존 이동 애니메이션이 우선한다. 유지 시간 안에 정지·착지하면 가드로 돌아온다.
- 무기 변경·메뉴·사망·조종 해제는 준비 상태를 정리한다. 상태 정리와 자세 블렌드를 구분해 갑자기 팔을 내리는 전환을 줄였다.
- 시각적인 준비 자세이며 새 방어 키·패링·피해 경감은 추가하지 않았다.

## 구현과 보존

`CharacterAnimationComponent`가 전투 활동 종료 예정 시각과 차징 유지 여부를 관리한다. Tick을 추가하지 않았다. 신규 `Rogue10mFighterCombatStanceAnimInstance`가 실제 Manny 소스의 AnimBP 부모가 되어 가드 알파를 갱신한다. `FootIK → TwoWayBlend(기존 이동, 가드) → DefaultSlot → 출력`으로 연결하여 기존 공격과 회피 몽타주가 최종 우선권을 갖는다. Appearance Retarget와 머리 카메라 경로를 그대로 사용한다.

신규 시퀀스와 공통 AnimBP 두 패키지를 Unreal Editor API로 저장했다. 변경 전 기존 에셋 4,186개 중 공통 AnimBP 하나만 변경됐고, 나머지 4,185개는 SHA256이 같다. 기존 강화 공격 10종, 관련 몽타주·DA·프로필과 일반 Idle을 보존했다. 기존 FootIK 준비 스크립트도 새 중간 블렌드를 인정하도록 보완했다. 자세 시퀀스는 그래프에 고정 연결되어 있으며, native 경로는 편집 불가능한 provenance 속성으로 표시한다.

## 검증

- UE 5.8 Editor 빌드 성공. 별도 프로세스 재로드 및 120Hz 원시 포즈 241개 검사 PASS. 루프 경계 위치·회전 오차 0, 렌더 본 로컬 이동·scale 오차 0, IK 위치 오차 약 0.000032cm, 머리 이동 최대 0.25cm.
- 실제 플레이어 640프레임·90,381포즈에서 일반 대기, 잽 연계, 스트레이트·4초 이상 차징·훅, 걷기·점프·착지, 너클, V, 무기/메뉴 취소, 회피 검사 PASS. 공격은 기존 Combat 입력 처리 경로로, V는 PlayerController InputKey로 실행했다.
- 외형 메시의 평균 손 높이는 일반 대기보다 24.90cm 상승했다. 정지 캐릭터/메시 월드 변환 오차 0, 발 높이 차이 최대 2.9345cm, 머리 카메라 최대 회전 7.0144도, 뼈 길이 비율 오차 최대 약 0.097%다.
- 독립 검토에서 실제 안정된 가드 205프레임의 손목·손가락 로컬 회전 변화와 발 위치 변화는 0이다. 호흡에 따른 외형 손목 위치 변화는 프레임당 최대 약 0.021cm다.
- 기존 FistCombat 9종·실제 피해 14회·V 1인칭 580/3인칭 260샘플 및 StoneFist 3종·1,234항목 회귀 PASS.

최초 실행의 3개 실패는 걷기 검사를 0.45초 복귀가 끝나기 전에 실행한 검사 시간 오류였다. 알파 임계값은 유지하고 15틱 뒤의 관찰 구간으로 수정했다. 원본 FBX에서 유래한 루트 본 좌표 약 90cm는 자식 골반 오프셋이 상쇄하므로 모델이 90cm 뜬다는 뜻이 아니다. 루트 높이는 진단값으로 남기고 실제 발과 캡슐/메시 월드 위치로 지면 접촉을 검사했다.

큰 전체 최대 회전값을 전투 대기의 흔들림으로 해석하지 않았다. 너클 첫 블렌드의 손가락 component 회전은 기존 기준선에서도 약 110도였고, 새 자세에서도 약 111도다. 새 가드의 병행 진입으로 최초 손목 블렌드는 조금 빨라졌으나, 이후 같은 몽타주 시각의 1,551개 본 포즈는 기준선과 일치했다. 자세 안정성과 모든 공격의 자연스러움을 같은 주장으로 묶지 않는다.

## 재현과 범위

`Scripts/VerifyFighterCombatStance.ps1 -Phase audit|runtime|render|combat|stone -Label <새 이름>`을 사용한다. 최초 에셋 제작은 `-Phase prepare`이며 기존 자세 패키지 덮어쓰기를 거부한다. Editor 호출은 직렬로 실행하고 검증은 별도 QA 저장 슬롯을 사용한다.

걷는 동안의 상체 가드 레이어·별도 전투 이동 클립은 이번 범위에 포함하지 않았다. 사망·조종 해제 정리는 코드 검토로 확인했으며 이 두 상황의 별도 실행 시나리오는 미검증이다. 모든 체형·장비 관통·네트워크 상황의 검증으로 확장해서 해석하지 않는다. 이전 미커밋 작업을 보존했으며 새 커밋·푸시는 하지 않았다.

## 실행 화면

1280×720 실제 그래픽에서도 동일 640프레임 검사를 통과했다. 30Hz PNG 640장을 H.264 무음 영상으로 묶었으며, 전체 디코딩 검사도 통과했다. 길이는 약 21.33초다. 캡처 실행에서만 Ray Tracing/Path Tracing을 끄고 프로젝트 렌더 설정 파일은 바꾸지 않았다.

- [실행 영상](evidence/fighter-combat-stance-20261005/fighter-combat-stance.mp4): 일반 Idle → 잽/가드 → V 관찰 → 차징/걷기 → 훅/점프/착지 → 일반 Idle → 너클/가드 → 취소 → 회피.
- [일반 Idle](evidence/fighter-combat-stance-20261005/frame_0020.png), [1인칭 가드](evidence/fighter-combat-stance-20261005/frame_0080.png), [V 전투 자세](evidence/fighter-combat-stance-20261005/frame_0123.png).

선택 화면에서 전방 시야와 양팔·발 지지 실루엣을 확인했다. 실제 머리 카메라 구조의 1인칭에서는 왼쪽 주먹이 하단에 보이고 오른 주먹은 현재 HUD 뒤에 가려진다. 양손·하체 자세는 V 시점에서 볼 수 있다. HUD와 모션 블러로 세밀한 손가락/장비 접촉을 전체 육안 검증한 것은 아니다.
