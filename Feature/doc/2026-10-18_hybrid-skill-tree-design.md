# 혼합 성장 스킬트리 설계 결과

- 날짜: 2026-10-18
- 브랜치: `Sprint#5-33-hybrid-skill-tree-design`
- 상태: Pre-production 설계·검토 완료. 실제 게임 시스템과 UMG 적용은 후속 Production 범위다.

## 결과

사용자 참조 이미지의 중앙 → 아이덴티티·기본기 → 핵심 기술 구성을 [혼합 성장 설계](../../Docs/HybridSkillTreeDesign.md)에 정리했다. 격투가는 초기 기본기4·연환권을 유지하고, 스탯과 개별 기술을 번갈아 얻는 숙련 경로를 따른다. 기존9개 잠금 무공의 새 순서·M 조건과 일회 스탯 보상을 제안했다.

격투가 아이덴티티는 사용자 확정에 따라 내공·투지 두 계열로 제한한다.1P로 입문할 수 있어 숙련이 낮아도 사용할 수 있다. 두 계열의 심화는2P 또는 지정한 숙련·영구 성장 조건으로 연다. 성질 선택은2P이며 활성 계열은1개다. 마지막 공명은 핵심 기술과 선택 성질을 모두 갖췄을 때 기존 공격을 변형한다. 마나는 다른 직업용 공용 정의로만 남긴다.

레벨업 포인트는 기존 마을 특성과 공유한다. 스킬 포인트를 별도로 다시 지급하지 않으며 양쪽의 실제 투자 비용을 같은 원장에서 차감한다. 숙련 스탯의 해금용 영구 기록과 무기별 발동 적용값, 일회 보상, 재분배 후속 철회와 기존 저장 이전 규칙을 명시했다.

검토용 구조도는 대표 정권 경로와3아이덴티티·공명 조건을 클릭해 볼 수 있다. 전체 방어·연계 경로와 자세한 수치는 설계 문서에 담았다. 이 구조도는 실제 Unreal 화면이나 원형 UMG 구현 결과가 아니다.

위3계열 HTML은 초기 기획 기록이다. 사용자가 격투가를 내공·투지로 제한한 뒤의 현재 화면 시안은 아래v3 이미지이며, 마나 사용은 격투가의 허용 목록에서 제외한다.

## 검증

- 기존 성장·스킬 코드와 문서를 독립 조사했다. 현재 숙련 상수, 기존 사용/토벌AND 조건, 특성 포인트 원장을 확인했다.
- 독립 Reviewer가 단계·선행·스탯 합계·XP·포인트 잔액·OR/AND·환급·LegacyGranted를 검토했다. 발동 성장값의 무기 범위와 입문 환급 시 후속 철회2개 문장을 보완했고 최종 미해결0이다.
- M1→5 70XP, M12 385XP, M20 1,045XP와 총공격+5·스태미나+10·HP+10·방어+1·공속배율+0.02를 별도 산술로 확인했다.
- 구조도 fragment·JavaScript 검사와736/320px 및320px 다크·터치 렌더를 확인했다.19노드 선택·단일 선택 상태·조건/효과/경로 갱신을 검사했고 가로 넘침·버튼 겹침·JS 오류0이다. 기본/좁은 다크 캡처를 주 작업자도 열어 검토했다.
- 참조 이미지 복사본의SHA256이 첨부 원본과 동일하다.
- `Scripts/CheckGeneratedChanges.ps1` 통과. 출력의 바이너리 변경 경고는 작업 시작 전부터 있던 변경이며 이번 작업은 해당 파일을 편집하지 않았다.
- 새 문서·로그5개 공백 오류0·상대 링크15개 누락0, Sprint 추가 내용의 `git diff --check` 통과. 기존 수정 파일108개SHA 동일과 기존 Sprint 내용의 원본 바이트 접두사SHA 동일을 확인했다. C++/Build.cs 변경이 없어 Editor 빌드는 실행하지 않았다.

## imagegen 화면 시안 추가 · 변경 전v2 기록 (2026-10-18)

사용자 후속 요청에 따라 built-in `image_gen`으로 참조 스타일 기반 화면을1회 생성하고 상태/기술명 교정 편집을1회 수행했다. 검토용 HTML 구조도와 별도로 흑철·황동 프레임, 중앙 원형 기점, 금색 숙련 경로와 비취색 내공 경로를 사용한 실제 화면 형태의 PNG 시안을 만들었다.

스냅샷은 캐릭터LV4·격투M12·숙련XP60/65다. 획득3P를 내공 입문1P·심화 수련0P·방출2P에 사용해 잔액0P이며 내공만 활성화한다. 선택 상세는 내공 심화의2P 또는 숙련 성장 조건과 실제 비용0P를 보여준다. 무극패왕권M20과 내공 공명은 미전수로 잠겨 있다.

최초 시안에서M9 스태미나 노드가 미전수처럼 보이고 미전수 투지/마나 입문이 밝게 표시되는 문제와 기술명 오자를 발견했다. 두 번째 이미지에서 해당 상태·글자를 교정했다. 화면의 일부 경로는 대표 노드만 담아 전체 데이터 모델을 생략했으며 실제 선행선·키/슬롯·원형UMG 구현 결과가 아니다.

- 최종 이미지: [imagegen-mockup-v2.png](evidence/hybrid-skill-tree-20261018/imagegen-mockup-v2.png).
- 생성 프롬프트: [imagegen-prompt-v1.txt](evidence/hybrid-skill-tree-20261018/imagegen-prompt-v1.txt).
- 교정 프롬프트: [imagegen-prompt-v2.txt](evidence/hybrid-skill-tree-20261018/imagegen-prompt-v2.txt).
- 사용 모드: 기본 built-in 도구, 참조 기반 생성1회와 편집1회. CLI/API 키 경로는 사용하지 않았다.
- 검증: 최종1672×941 RGB PNG 직접 시각 검토·독립 설계 대조, 생성 원본과 프로젝트 복사본SHA256 동일. 주요3기술명·혼합 조건·0P·활성 계열·숙련60/65 일치. 공명 연결선의 정확한 양부모 끝점과 전체 노드 카탈로그는 이미지에서 확정할 수 없어 후속UMG 검증으로 남긴다. 실제 런타임 에셋/코드/설정 변경 없음.

## 격투가 내공·투지 확정 · 현재v3 시안 (2026-10-18)

사용자 지시에 따라 격투가의 아이덴티티를 내공·투지 두 계열로 제한했다. 상세 설계에서 마나 입문/심화/성질·격투 성장 산식을 제거하고 직업 허용 목록의 UI·구매·활성·장착·공명 검증을 명시했다. 마나는 다른 직업용 정의로만 보존한다.

기존v2 이미지를 built-in `image_gen`으로1회 편집해 마나 노드·이름·연결선을 제거했다. 금색 숙련 경로, 비취색 활성내공·방출, 잠긴투지, LV4/M12·잔액0P·심화수련0P를 유지한 새v3 이미지를 저장했다. 이미지를 직접 확인했고 생성 원본과 복사본SHA256이 동일하다. 기존 HTML과v2 원본은 초기 기획 증거로 유지하며 최신 격투가 시안으로 사용하지 않는다.

- 현재 최종 이미지: [imagegen-mockup-v3.png](evidence/hybrid-skill-tree-20261018/imagegen-mockup-v3.png).
- 현재 편집 프롬프트: [imagegen-prompt-v3.txt](evidence/hybrid-skill-tree-20261018/imagegen-prompt-v3.txt).
- 사용 모드: 기본 built-in 이미지 편집,1회.
- 완료 범위: 설계·화면 시안 수정. 실제 런타임 허용 목록 구현은 후속Production이며 코드/설정/Unreal 바이너리/생산 저장은 편집하지 않았다.
