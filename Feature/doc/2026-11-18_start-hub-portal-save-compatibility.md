# 시작 마을 포탈의 이전 저장 호환 수정

2026-11-18 · Sprint#9-32 · UE 5.8

시작 마을에서 포탈에 닿았을 때 이전 캐릭터 진행 저장을 읽지 못해 이동이 중단됐다. 실제 에디터 로그에서 메뉴가 `StartHub`를 정상적으로 연 뒤 저장 복원 오류가 발생했고, 이어 다섯 차례의 포탈 진입을 막았다. 포탈의 대상인 `/Game/Rogue10m/Maps/OpenRunMap`을 열기 전에 발생한 문제다. [기획과 검증 계획](../architect/2026-11-18_start-hub-portal-save-compatibility.md)

## 저장 형식 호환

이전 저장을 작성한 Unreal 직렬화 경로는 당시 클래스 기본값과 같은 `SaveVersion` 필드를 생략했다. 현재 클래스는 읽을 때 그 자리를 버전 5로 초기화한다. 런 ID가 없던 이전 저장에 런 ID를 필수로 요구하게 된 이유다.

`Rogue10mProgressionSubsystem`에서 이전 네이티브 저장을 읽을 때, 다른 초기값을 넣은 객체로 같은 바이트를 한 번 더 읽어 `SaveVersion`이 실제로 빠졌는지 확인한다. 버전 없는 파일은 저장에 포함된 스킬 트리와 특성 기록에 따라 기존 이행 경로를 선택한다. 버전 표기가 생략된 `_v4` 파일은 런 정보를 확인해 버전 4로 읽는다. 복원과 검증이 끝나면 기존 저장 흐름으로 `_v5` 슬롯을 만든다. 명시된 버전과 프로필 ID는 기존 검증을 따르고, 더 새로운 슬롯에 오류가 있으면 오래된 슬롯을 대신 열지 않는다. 포탈은 입장 시점의 재화를 기록한 뒤 기존 맵으로 이동한다. [저장 복원 코드](../../Source/Rogue10m/Core/Rogue10mProgressionSubsystem.cpp)

## 검증 기록

별도 사용자 폴더에 준비한 실제 저장 복사본으로 17개 조건을 모두 통과했다. 정상 캐릭터 접속 후 이동 입력으로 배치된 포탈을 걸어서 통과했고, `StartRun=1` 조건으로 `OpenRunMap`에 진입해 1,200초 런이 시작됐다. 입장 전후 프로필, 런 ID, 레벨, 골드, 크리스털, 숙련도, 인벤토리의 저장 값이 일치했다. 새 `_v5` 슬롯의 입장 재화 기록과 복사 입력 두 개의 바이트도 확인했다. 실제 테스트 프로세스 종료 코드는 0이다. 기존 저장 460개는 전후 해시가 같고, 추가 파일 23개는 이번에 이름을 붙인 격리 QA 슬롯이다. [개인 식별 정보 없이 정리한 검증 결과](evidence/portal-progression-recovery-20261118/replay-summary.json)

합성 재현 일곱 케이스도 실제 종료 코드 0까지 확인했다. 버전 1과 3은 기존 포탈 통과까지 검증했고, 버전 2는 특성 기록의 복원을 확인했다. 버전 표기가 생략된 `_v4`와 `_v5`는 저장된 런을 이어갔다. 최신 저장에 명시된 잘못된 버전 0과 999는 거절됐고, 최신 파일과 그보다 이전 파일을 모두 보존했다. [검증 도구](../../Scripts/VerifyLegacyPortalTravel.ps1)

첫 복사본 재현도 캐릭터를 복원하고 `OpenRunMap`에 도착했으나, 검증 도구가 Unreal `FText`의 내부 식별자까지 비교해 인벤토리를 다르다고 판정했다. 별도 직렬화 비교 후 표시 값과 텍스트 이력, 나머지 인벤토리 데이터를 검사하도록 보강했다. 새 복사본에서는 내부 식별자가 달랐지만 저장 텍스트 64개가 모두 동등했고 실제 데이터 차이는 0건이었다. 버전 3의 첫 검증은 종료 대기 시간 240초를 넘겨 그 프로세스만 종료했으며, 새 검증은 17개 조건과 종료 코드 0을 확인했다. 테스트 시작이 수정본 적용을 앞지른 시도와 검증 코드의 `FScriptArrayHelper` 컴파일 실패도 각각 바로잡고 결과를 별도로 기록했다.

라이브 코딩으로 현재 에디터에 수정본을 적용했고 마지막 컴파일은 성공했다. 이후 검사한 에디터 로그 구간에 새 오류가 없었으며, 작업 전후 에디터의 기존 미저장 패키지 두 개가 일치했다. 에디터 세션을 유지했으므로 다음 실행에 쓰일 Development 모듈의 정규 빌드는 남아 있다. 실물 키보드 입력과 패키지 빌드는 이번 검증 범위에 포함되지 않았다.
