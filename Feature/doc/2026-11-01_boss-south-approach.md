# 보스 남쪽 진입 경사로와 정상 사망 루프 검증

Sprint#9-19, 기준648ca964. 보스 보호 바닥 아래에서 머리가 걸려 진입하지 못하던 경로에 단일 보행 경사로를 추가했다. 원래 바닥과 맵은 보존했다. 원본 Engine Cube/재질을 실행 중 transient actor로 재사용하고, 실제 지형/바닥 trace 및 주변 Pawn 검사를 통과할 때 한 번만 만든다. 폭160cm·두께60cm·최대경사20도는 편집 가능한 값이다. 다른 측면의 바닥 아래 접근까지 해결한 것은 아니다.

## 변경과 검증

- 제품: OpenWorldBootstrap.h/.cpp의 독립1초 타이머, 정확한 맵/바닥 식별, 정상 소유권·수명과 중복 생성 방지. 기존 바닥·맵·애니메이션·저장 스키마는 변경하지 않았다.
- QA: BasicRunPlaytest는 일반 키 입력으로 좁은 진입 차선을 따라 걷고, 키를 놓아 감속한 뒤 다음 경유점으로 이동한다. 위치/HP/경험치/무적/승리 주입은 없다.
- 빌드31.52초 성공. Transform/InvalidGeometry 자동 테스트2개 성공. 기존30개 핵심 회귀는 NPC 수정 후·이번 경사로 전 기준선 결과이며, 경사로 후 재실행 결과로 부풀리지 않는다.
- BasicRun1101H: 정상 메뉴 생성→마을 F 대화/보급→포털→대검 실제 overlap 습득→몬스터 처치/경험치→K 화면의 런 기술 학습→경사로/보스→자연 사망→정산 UI→마을 복귀를355.076초에 관찰했다. 실제 키보드가 아닌 Controller.InputKey/DoAim/Slate/UMG 자동 입력이다.
- 실제 발밑 actor31개 표본은 transient 경사로, 발바닥 높이8725.543→9603.620cm, walkable=1이었다. 다음52개 표본은 원래 보스 바닥, 높이9602.150cm였다. XY 도달만으로 통과 처리하지 않았다. 진입 구간960개 입력 프레임의 중심선 이탈은−8.611..36.998cm였다. 전체40381행으로120000행 상한에 닿지 않았다.
- 보스 체력10000→9917.992 감소. LV2 너클 캐릭터는 약5.4초 전투 후 사망했다. 보스 승리/밸런스 통과가 아니다. 결과 화면 로비 포인트+6과 저장 완료, 귀환 후 LV1/런 숙련/학습 기술/해당 대검 제거·Discovery 유지의 좁은 검사 범위를 통과했다. 모든 인벤토리·성장 도메인에 대한 완전 검사를 주장하지 않는다.
- 기존338개 Saved/SaveGames 파일은 전부 SHA256 동일, 이후340개는 새 QA 파일2개만 증가했다. 기존31개 자산과 OpenRunMap.umap 해시도 동일하다. 이전 실패 G와 원본·QA 증거는 보존했다. 프로세스50616은 정상 종료0, watchdog 강제 종료는 없었다.

## 증거와 재실행

로컬 DevLog/20261101_BossSouthApproach_Review에 수정 전 막힘, 보스 바닥 도달, 사망 정산, 마을 귀환 PNG4개와 VERIFICATION.json을 보존했다. 모두1280×720 디코딩/SHA256 확인; 보스/정산/귀환 화면은 직접 이미지로 읽었다. 계정·브라우저 화면이 아닌 실제 QA 렌더다. 원시 QA 파일은 DevLog/BasicRunPlayQA/BasicRun1101H에 있다. 로컬 미디어와 저장 목록은 Git에 자동 추가하지 않는다.

재실행은 UE 프로세스를 먼저 확인한 뒤 Scripts/VerifyBossApproachGeometry.ps1 -RunLabel <새라벨>, Scripts/VerifyBasicRunPlay.ps1 -Label <새라벨>을 사용한다. 기존 라벨/세이브를 삭제하거나 덮어쓰지 않는다. bEnableBossSouthApproach를 끄면 이전 실행 경로로 되돌릴 수 있다. map 저장/원격 push/병합은 하지 않았다.
