# 시작 마을과 오픈 월드 두 맵 운영

프로젝트 레벨을 `/Game/Rogue10m/Maps/StartHub`와 `/Game/Rogue10m/Maps/OpenRunMap`으로 정리했다. 게임 기본 실행은 `StartHub`에 기존 메뉴 게임 모드를 적용한다. 캐릭터 선택 완료 뒤 같은 맵을 플레이 모드로 로드한다. 오픈 월드 출발은 기존 포탈이 담당한다. 패키징 기본 목록도 두 맵으로 맞췄다.

## 정리 범위

- 레벨 33개, 빌드 데이터 21개, 월드 파티션 외부 패키지 4,396개, 제작 후보 전용 에셋 37개, 벤더 맵 전용 보조 에셋 62개를 활성 콘텐츠에서 정리했다.
- `StartHub`에서 폐기 맵으로 연결되던 포탈 3개와 표식·구조물 10개를 기존 위치에서 제거했다. 별도 FiveVillage 런타임 모드, 진행용 컴포넌트·데이터·포탈, 전용 테스트와 실행기를 정리했다. 제작자가 지원 월드를 지정할 수 있는 공용 의뢰 시스템은 계속 사용 가능하다.
- 폐기 맵과 전용 에셋의 해시를 확인해 로컬 복구본을 보관했다. 최근 동굴·경계·도로 후보와 해당 후보의 로컬 액터 변경도 복구본에 있다. 이후 월드 제작은 현재 클리어 경로를 가진 `OpenRunMap`에서 구역별로 진행한다. [제작 기준](../../Docs/WorldMapProductionGuide.md)

## 검사

- Unreal Asset Registry에서 프로젝트 맵 35개가 2개로, 물리 패키지 10,948개가 6,386개로 줄었다. 제거 패키지로 이어지는 남은 레지스트리 의존성은 0개였다. `OpenRunMap` 본체와 외부 패키지 1,260개를 기존 작업 브랜치와 대조했다.
- 실제 기본 실행으로 `StartHub`와 `Rogue10mMenuGameMode`를 확인했다. 렌더링된 기존 UI에서 메인 메뉴, 캐릭터 선택 화면, 종료 동작 36조건을 통과했다. 공용 의뢰 자동화 26개가 통과했다.
- Development Editor 빌드와 실제 승리 실행 77조건 및 별도 프로세스 저장 재로드 17조건을 통과했다. 기존 포탈로 `OpenRunMap`과 런 타이머를 열고, 저체력으로 준비한 실제 보스에게 플레이어 공격으로 마지막 타격을 가했다. 승리 보상을 한 번 정산하고 결과 창의 Enter 처리로 `StartHub`에 귀환했다. 영구 보상과 특성, 정산 ID를 보존하며 새 런의 성장과 투자·장비를 초기화하는 현행 규칙을 확인했다.
- 초기 검증 과정에서 화면 전용 API가 명령 프로세스에서 충돌했으며 저장 전에 중단됐다. 해당 호출을 명령 실행용 API로 교체했다. 기존 클리어 테스트의 저장 슬롯, 착지·장착 시점과 귀환 이후 런 데이터 보존 가정도 현행 규칙에 맞췄다. 검증은 Development 환경에서 수행했다. Win64 cook 및 패키징 배포본은 별도 단계다.
- 작업 에디터를 기존 `OpenRunMap`으로 다시 열었다. 맵 검사 0오류·0경고, Zen 로컬 캐시 응답 HTTP 200을 확인했다. 게임 로그에는 정리 전부터 있던 캐릭터 패키지의 `/Engine/EngineMeshes/Humanoid` 의존 참조 경고가 남아 있다.
