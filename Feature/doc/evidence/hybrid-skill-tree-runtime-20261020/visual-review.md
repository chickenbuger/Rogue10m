# 혼합 성장 스킬트리 최종 화면 검토

2026-10-20. `HybridRun05` 실행 후 생성된 실제 Unreal 게임 화면 PNG 3장을 원본으로 열어 확인했다. 픽셀 치수는 이미지 메타데이터로 별도 확인했다. 이 검토에서는 게임 소스·카탈로그·스크립트를 수정하거나 빌드를 실행하지 않았다.

판정: 세 화면에서 진행을 막는 라벨 중첩, 그래프 가장자리 잘림, 고정 조작 영역의 화면 이탈을 발견하지 않았다. 720p에서도 노드명·숙련 단계·잠김/전수/활성 표기를 구분할 수 있다. 긴 상세 설명과 조건은 별도 스크롤 본문에서 읽는 구조다.

## 해상도별 배치와 읽기

- 격투가 1080p: 중앙 정권의 이름·M·상태 라벨을 중앙선 왼쪽에서 읽을 수 있다. 호흡·연계는 왼쪽 바깥, 체술·방어는 오른쪽 바깥으로 분리되어 이전 캡처의 M3·기본기·철산고·방어력 라벨 중첩이 해소됐다. `기본`은 중앙 원 내부에 표시된다.
- 대검술사 720p: 그래프는 이름과 짧은 M/상태 두 행으로 축약되어 주요 기술과 스탯을 읽을 수 있다. 기술 아이콘이 없는 대검 기술은 `검` 표식으로 구별되며 스탯의 `+`와 혼동되지 않는다. 하단 공명 이름·상태, 닫기, 키 지정 영역이 화면 안에 있다.
- 대검술사 잠금 1080p: 잠금 노드의 낮은 강조와 전수된 기본·시작 노드를 구분할 수 있다. 잠금 기술에도 이름·요구 M이 남아 있고, 좌측에는 미리보기 상태와 필요한 장착 조건이 제시된다.
- 긴 상세 조건은 본문 스크롤 영역을 사용한다. 720p 화면에서 스크롤바와 본문 경계가 확인되며, 조건 전체를 동시에 표시했다는 판정은 하지 않는다. 본문 밖의 하단 조작 영역은 그 경계 아래에 따로 남아 있다.

## 고정 조작 영역과 실제 입력 증거

전수·성질 선택·활성·키·부분 재분배 컨트롤은 `HybridTreeActionFooter` 안에 있고, 상세 설명·조건을 담는 `HybridTreeDetailsScroll`의 자식이 아니다. 현재 선택에서 필요한 컨트롤만 노출한다. 최종 PNG에서는 잠긴 무극패왕권의 비활성 키 지정과 전수된 패왕참의 활성 키 지정 영역이 각각 좌측 바닥에 보인다.

구매 버튼의 클릭 여부를 PNG만으로 추정하지 않았다. [Run05 결과](runtime-results.txt)에 실제 Slate hit path와 포인터 이동·누름·놓기 경로를 통한 다음 검증이 함께 통과했다.

- `real_mouse_hit_reaches_button` 두 차례 통과.
- `real_UI_free_mastery_deepening`: 내공 심화를 수련 0P로 전수하고 실제 투자 합이 입문 1P로 유지됨.
- `UI_property_spends_remaining_two_points`: 방출 성질을 실제 포인트 버튼으로 전수하고 남은 공용 2P를 사용함.

Run05는 PASS 50개, 실패 0개다. [Read05 결과](runtime-read-results.txt)는 PASS 14개, 실패 0개이며 실제 투자 합 8P·공용 잔액 5P, 선택 마나 확산·공명, 별도 숙련, F7 바인딩의 새 실행 복원을 확인한다. 기능 실행과 복원 결과는 이 로그의 근거이며, 사진은 해당 상태가 화면에 표시되는 근거로 구분한다.

## 허용 아이덴티티와 연결선

- 격투가 화면의 노드와 범례에는 내공·투지만 있다. 마나 경로는 보이지 않는다. 추가로 Run05의 `brawler_mana_purchase_rejected`가 통과해 표시 제한과 구매 제한을 구분하여 확인했다.
- 대검술사 두 화면의 노드와 범례에는 마나·투지만 있다. 내공은 나타나지 않는다. 잠금 미리보기에서는 활성 아이덴티티가 미활성으로 표시되며, 탭 선택이 실제 장비 변경으로 이어지지 않는 결과도 Run05에 있다.
- 실선·점선과 전수/활성 텍스트가 계열 색과 함께 사용된다. 핵심기와 하단 공명의 긴 연결은 그래프 외곽으로 돌아가며, 내부의 다른 노드가 중간 선행처럼 보이는 문제를 줄인다.
- 격투가 M12 사진에서는 내공 성질까지 활성이어도 미전수 핵심기의 공명이 잠겨 있다. 대검술사 M20 사진에서는 선택한 확산 공명만 활성으로 구분된다. 공명의 양쪽 선행 판정 자체는 Run05의 `core_and_property_both_required_for_resonance` 결과를 근거로 한다.

## 검토 범위의 한계

- 실제 마우스 드래그로 기술을 HUD 슬롯에 놓는 끝까지의 입력은 이번 최종 실행에서 검증하지 않았다. 전수 공격의 드래그 소스와 기존 `URogue10mSkillDragDropOperation` 연결은 코드상 지원이며, 드래그 앤 드롭 실입력 통과로 보고하지 않는다.
- 키 지정·해제 컨트롤은 사진에서 확인했고, 기술 키 지정과 별도 저장 복원은 API/복원 검증을 통과했다. 이 결과를 물리 키 선택기 입력이나 모든 바인딩 기술의 실제 키 발동 검증으로 확대하지 않는다.
- 노드의 선택 강조와 종류·계열 구분은 화면에서 확인했다. 호버 스타일 전체 상태의 실입력 검증, 모든 모니터 배율, 720p 미만 해상도는 검토 범위가 아니다.
- 현재 native 표현은 원형 크기·계열 색·종류 표식·텍스트를 사용한다. 설계 문서에 언급된 아이덴티티 마름모와 공명 이중 외곽선은 이번 화면에 구현된 것으로 판정하지 않는다.
