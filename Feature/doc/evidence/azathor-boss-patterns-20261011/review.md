# 아자토르 패턴 독립 검토 — 2026-10-11

현재 런타임·에셋 적용·QA 변경에서 수정이 필요한 추가 결함을 발견하지 못했다. 기존 미커밋 기본 공격 구현을 기준으로 이번 확장 부분을 검토했으며, 저장소 전체 변경을 이번 작업으로 간주하지 않았다. 검토자는 에디터를 조작하거나 게임 파일을 수정하지 않았다.

## 확인한 증거

- `build-editor.log`: `BuildEditor.ps1 -NoHotReload` 결과 `Succeeded`, 68.49초. 이후 검증 조정은 Python 검증·미리보기 스크립트에 한정됐으며 런타임 C++는 변경되지 않았다.
- `runtime-validation.json`: 최종 `passed`, 22개 사례 모두 통과, 480개 확인 중 실패 0개, 55.688초. 소유 PIE 종료 및 임시 백그라운드 CPU 제한 설정 복원이 확인됐고 정리 오류가 없다.
- 같은 저장 프로필을 변경 없이 사용해 기본 공격과 두 특수 공격의 실제 플레이어 체력 감소, 단일 타격, 옆·뒤·거리·높이 회피, 실제 Visibility 가림, 쿨타임 선택, 취소·프로필 제거·대상 사망/파괴·보스 사망·EndPlay를 검증했다.
- 일반 정면 공격은 예고 1.1184초 뒤 실제 체력 81.5를 감소시켰다. HP 50% 강화 공격은 0.8358초 뒤 106.875를 감소시켰다. 이는 방어가 적용된 해당 검증 플레이어의 결과다. 회복 시간은 관측 불확실성을 포함해 일반 `[0.6339, 0.6907]`초, 강화 `[0.4971, 0.5453]`초였으며 두 구간이 겹치지 않는다. 전이 직전/직후 관측 간격은 모두 요구된 0.08초 이하였고 기존 0.04초 이상 단축 확인도 유지됐다. 안정 상태 내부의 큰 관측 간격을 진단값으로 분리한 수정은 이 전이 증거를 완화하지 않는다.
- `application.json` 및 `content-comparison.json`: 기존 아자토르 DA 1개 변경, 전용 프로필·경고 재질/인스턴스 4개 추가, 기존 콘텐츠 6,296개 동일, 삭제 없음. 기본 수치·애니메이션과 다른 5종의 기본 프로필 참조 및 opt-in false 상태를 확인했다.

## 구현 검토

기본 공격 경로를 보존하고 보스 패턴은 명시적 opt-in으로 활성화한다. 특수 공격의 위치·방향과 강화 시점 설정을 시작할 때 고정하므로 예고 도중 대상 추적이나 단계 변경으로 타격 범위·예고 시간이 바뀌지 않는다. 권한·생존·높이·범위·가림·중복 조건을 실제 타격 전에 검사한다. 타이머, 약한 대상/ASC 참조, 체력 델리게이트 해제, GC 추적 데칼·재질 참조 및 취소/사망/EndPlay 정리를 확인했다.

엔진 소스의 데칼 반경과 회전 축을 기준으로 경고 직사각형이 타격 방향·폭·길이에 일치한다. Material Function 속성 편집이 엔진의 함수 연결 갱신으로 이어지는 API도 확인했다. 재사용 재질의 필수 매개변수 검사와 실제 UE 5.8 반환값에 맞춘 컴파일 오류 배열/MI 매개변수 readback 검증이 반영됐다. 실패했던 임시 프로필 복사 및 미노출 deferred spawn API는 최종 검증 경로에서 제거됐다. 이전 실패 증거는 별도 JSON으로 보존됐다.

## 검증의 범위

런타임 검증은 OpenRunMap의 로드된 숲 지형과 실제 보스 Blueprint를 native 스포너로 생성한 통제된 PIE 사례다. 북부 폐허까지의 실제 이동, 통합 AI 전투 흐름, 물리적 회피 입력, 패키징·네트워킹·최종 밸런스를 검증한 것은 아니다. 대상 사망은 실제 PlayerState 사망 플래그를 사용했으며 패배 UI를 실행한 검증은 아니다. 데칼의 등록·재질·가시 상태 검사는 화면 픽셀의 경고 표시를 입증하지 않는다. 화면 확인과 새 에디터에서의 저장 에셋 재로드는 root의 별도 증거로 확인해야 하며, 이 검토 기록만으로 그 단계의 완료를 선언하지 않는다.

## 후속 독립 확인 — 화면과 새 에디터 재로드

root의 후속 검증 뒤 검토자가 `view_image`로 실제 `visual-frontal.png`, `visual-zone.png`, `visual-enrage.png`를 각각 열어 확인했다. 정면 공격의 주황 직사각형은 잔디와 도로 위에 테두리·내부 면이 표시돼 배경과 구분된다. 영역 공격은 보라색 원형 테두리·내부 면으로 표시돼 정면 패턴과 구분된다. 강화 공격은 같은 직사각형 형태가 붉은색으로 바뀐다. 실제 Beholder 모델과 전투 HUD가 함께 렌더링돼 있으며, 세 화면 모두 경고가 지면에 투사되는 것이 픽셀에서 확인된다. 서로 다른 모양과 단계 색을 확인했으며, 한정된 구도의 스크린샷으로 모든 지형·조명에서의 가독성을 보장하지 않는다.

`visual-preview.json`은 세 사례 모두 `captured`, 최종 `passed`, 소유 PIE 정리 및 임시 CPU 제한 설정 복원 true다. 화면 고정에는 임시 게임 시간 배율 0.001을 사용했으므로 이 화면 기록으로 타격 시간·회복 시간 검증을 주장하지 않는다. 그 수치는 앞서 별도의 정상 속도 런타임 QA에서 검증됐다. 현재 미리보기는 세 캡처 완료 수를 검사하며 조기 종료를 성공으로 기록하지 않는다.

`inspection-fresh.json`과 `inspection-final.json`에서 새 에디터의 저장 프로필·전용 재질·Shape 0/1 인스턴스·기존 보스 Blueprint 데이터 연결을 확인했다. 아자토르 HP10000·기본 피해70·EXP3000·이동240cm/s와 기본 공격 설정·애니메이션이 유지됐으며 다른 5종의 프로필 및 opt-in false도 유지된다. 최종 OpenRunMap은 PIE false, dirty 콘텐츠/맵 목록 모두 비어 있다. 따라서 앞 절에 남겨 둔 화면 확인과 저장 후 재로드 확인은 후속 증거로 충족됐다.

첫 화면 검증 도중 발생한 D3D12 `Out of video memory trying to allocate a rendering resource` 오류는 `visual-preview-gpu-memory-error.log`에 실제 기록돼 있다. root는 새 에디터로 복구해 저장 내용을 재로드하고 세 화면 검증을 완료했다. 에디터 복구와 미리보기 방식 변경은 장시간 GPU 안정성 문제의 원인이 해결됐다는 증거가 아니다. 장시간 실행과 북부 폐허의 전체 전투 등 앞 절의 집중 검증 범위 밖 항목은 그대로 남는다. 이 후속 검토에서도 게임 파일·에디터를 변경하지 않았으며 이 검토 문서만 추가했다.
