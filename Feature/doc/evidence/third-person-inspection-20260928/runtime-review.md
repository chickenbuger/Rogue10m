# V키 3인칭 관찰 실행·시각 검토

- 검토 날짜: 2026-09-28
- 검토자 역할: 독립 검증 2
- 결론: 검증한 범위에서 PASS. 실행 결과 280프레임, 실패 0.
- 실행 근거: `tmp/third-person-inspection/verified.log`
- 시각 근거: 같은 폴더 `contact-sheet.jpg`의 프레임 15, 45, 62, 105, 125, 180을 직접 확인했다. 같은 실행의 영상은 `v-third-person-gameplay.mp4`다. 이 검토는 모든 영상 프레임을 수동 검수했다는 의미가 아니다.

## 실행 검증

- V키는 `PlayerController.InputKey(FInputKeyEventArgs::CreateSimulated(...))`로 눌림/떼짐을 전달했다. 전환 메서드를 직접 호출하여 일반 전환 검사를 대체하지 않았다.
- 1인칭 자동 렌더 카메라 135샘플, 3인칭 145샘플을 검사했다.
- 3인칭에서도 실제 머리 카메라는 애니메이션 머리 위치를 유지했다. 최대 위치 오차 0cm, 회전 오차 0.00000418도다.
- First Person Mesh 비활성, Appearance Mesh 및 원본 애니메이션 클래스 유지, 시점에 따른 머리/외형 파츠 소유자 표시 복원을 검사했다.
- 3인칭 중 좌우 Boxing 원본 몽타주의 실제 재생 샘플은 각각 12개였다. 공격 회복 타이머가 남아 있지만 활성 몽타주는 끝난 8프레임은 회복 구간으로 별도 집계했다.
- 카메라 전용 임시 장애물 10샘플에서 거리 300cm가 128cm로 줄었으며, 제거 뒤 다시 300cm로 복귀했다.
- 인벤토리 중 V 입력과 전환 핸들러 직접 호출이 모두 차단되었다. 인벤토리 종료 후 반복 전환이 정상 작동했다.
- 물리 마우스 간섭을 배제하려고 이 검증 Pawn만 `DisableInput`했다. PlayerController 입력은 유지했으며 Look/Move Ignore 플래그는 모두 false였다. 공격은 기존 Combat API로 입력하고, 종료 시 원래 Pawn 입력 상태를 복원했다.
- 이번 검증의 시작 시선은 명시적으로 Pitch -30도와 캐릭터 Yaw로 고정했다. 일반 게임의 최초 시선 초기화 정책을 새로 검증한 것은 아니다.

## 실제 화면 관찰

- 프레임 45와 180: 뒤쪽 관찰 시점에서 실제 외형의 머리, 몸통, 팔, 다리를 확인할 수 있다. 캡슐 중심을 기준으로 한 배치로 전신 구도가 화면 중앙에 들어온다. HUD가 발 부근 일부와 겹치는 구간은 있다.
- 프레임 62: 같은 실제 외형이 공격 자세로 움직인다. 별도의 1인칭 팔이 겹쳐 표시되는 현상은 확인되지 않았다.
- 프레임 105: 장애물 때문에 카메라가 몸 뒤로 가까워지는 화면이 확인된다. 이때 상체가 크게 보이고 머리 윗부분이 프레임 경계에 가까워지는 것은 충돌 수축에 따른 구도다.
- 프레임 125: 다시 1인칭 머리 시점으로 복귀했다. 프레임 180에서 3인칭으로 다시 전환된 모습도 확인했다.

## 검증 경계

- 공격은 3인칭으로 전환한 뒤 재생했다. 공격 재생 도중 V키를 눌러 전환하는 경우를 직접 검증하지는 않았다.
- V키의 OS 물리 키보드 이벤트가 아닌 엔진 InputKey 경로를 자동 주입했다. 실제 컨트롤러 바인딩과 메뉴 차단 경로는 통과한다.
- 별도 네트워크 클라이언트, 사망·재생성, 모든 외형/헤어 조합 및 실제 레벨의 모든 충돌 형태는 이번 실행 범위에 포함되지 않는다.
