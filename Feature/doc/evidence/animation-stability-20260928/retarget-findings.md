# Appearance 리타깃 원인 분리 결과

2026-09-28. 원본 클립 오프라인 비교와 실제 331프레임 실행을 구분하여 분석했다. 카메라·V 관찰 시점·원본 FBX는 변경하지 않았다.

## 확인된 원인

1. **Root Motion 연산이 골반을 root로 사용했다.** 6종 모두 SourceRoot=pelvis, TargetRoot=pelvis/Pelvis이고, Pelvis Motion→FK→IK 이후 이 연산이 골반을 덮었다. 엔진 `RootMotionGeneratorOp.cpp`는 이때 이미 리타깃된 자식의 글로벌 변환을 함께 이동시키지 않는다. 실제 root/root로 교정한 단일 실험에서 골반→허벅지·척추의 로컬 길이비가 정확히 1로 복원되었다.
2. **타깃 Run IK Rig가 발의 급회전을 추가했다.** 루트만 교정해도 발의 한 프레임 최대 회전은 그대로였지만, Run IK Rig만 끈 다음 실험에서는 원본 소스 수준으로 줄었다. 현재 요청인 원본 몸동작 보존에 맞춰 FK를 기본으로 선택한다. 타깃 체형별 IK 보정은 추후 별도로 검증한 설정에서 도입할 수 있다.
3. **보조 체인의 자동 이름 매핑이 잘못되어 있었다.** Tail/Cape가 Spine에, Tabard_Back/Front가 HandRootIK에 연결됐다. 대응되는 소스 보조 체인이 없으므로 이 4개 매핑은 해제한다. 이것이 팔·다리 문제의 주원인이라는 주장은 하지 않는다.

| 실제 331프레임 계측 | 기존 | Root만 교정 | Root 교정 + 타깃 IK 끔 |
|---|---:|---:|---:|
| 골반→왼쪽 허벅지 길이비 | 0.6443~3.5464 | 1.0 | 1.0 |
| 골반→오른쪽 허벅지 길이비 | 0.7787~3.3884 | 1.0 | 1.0 |
| 골반→척추 길이비 | 0.8245~3.1314 | 1.0 | 1.0 |
| 왼발 최대 프레임 회전 | 123.061° | 123.068° | 26.289° |
| 오른발 최대 프레임 회전 | 150.812° | 150.813° | 26.328° |

동일 실행의 소스 발 회전 최대값은 왼발 26.542°, 오른발 26.324°였다. 원본 공격의 빠른 움직임 전체를 제거한 결과가 아니라 리타깃에서 추가된 발 회전이 사라진 결과다. 원본 소스의 별도 FootIK와 몽타주 배치 문제는 이 분석과 분리해 다룬다.

## 기각되거나 적용하지 않은 가설

- Source rig의 Spine 범위는 spine_01→spine_05로 Manny와 일치했다. UE4의 짧은 Spine을 잘못 사용한다는 가설은 기각했다.
- Source/Target의 foot goal은 모두 ball_l/r에 연결되어 다리 체인 끝점과 일치했다. 발목·발끝 목표 본 불일치 가설은 기각했다.
- 현재 오프라인 리타깃에서도 머리 최대 기준자세 회전은 57.096° 수준이었다. 152° 증폭이 타깃 리타깃에서 발생한다는 가설은 실제 소스에도 같은 회전이 관찰되어 기각했다.
- 자동 정렬은 오프라인 머리·몸통 문제를 개선하지 않아 적용하지 않는다.
- 단순 팔·다리 8개 구간 길이만 검사하면 골반→허벅지·척추 변형을 놓친다. 이 구간을 반드시 추가해야 한다.

## IK 설정 관찰과 범위

Source FBIK는 pelvis/PinToInput, Target FBIK는 Root/PrePull이었다. 이런 구성 차이는 발의 추가 동작이 발생할 수 있는 경로를 설명하지만, 세부 수치 조정으로 모든 모션에서 안정화된다고 검증한 것은 아니다. FK 기본 선택은 타깃 FBIK의 추가 포즈 수정을 제거한다. 소스 ABP의 보행 지면 보정까지 없애는 변경은 아니다.

## 도구와 적용

- 읽기 전용: `AuditAppearanceRetarget.py`, `AuditAppearanceIKGoals.py`.
- 진단 복제: `CompareAppearanceRetargetVariants.py`. 7설정×2클립을 별도 Developers 폴더에서 비교했고 프로덕션 입력 해시 불변을 확인했다.
- 원인 분리: `ApplyAppearanceRootOnlyFix.py`, `ApplyAppearanceIKExperiment.py`. Hu_M만 수정하고 각 단계의 원본 해시·백업·Editor API 복구 경로를 둔다.
- 확정 설정: `ApplyAppearanceRetargetPolicy.py`. 6종 전체를 사전 검증·백업한 뒤 실제 root 분리, Run IK Rig 비활성화, 잘못된 보조 매핑 해제만 수행한다.
- 생성기: `CreateInheritedCharacterAssets.py`가 같은 `configure_pose_preserving_retargeter()`를 호출해 재생성 후 되돌아가는 일을 방지한다.

현재 문서는 원인 분리 실험 결과다. 6종 최종 저장과 통합 실행의 완료 여부는 루트 담당의 최종 결과 문서를 기준으로 한다.
