# 복싱 애니메이션 소스 검토 — 2026-09-12

검토 역할: 개발1이 입력 구현을 마친 뒤 다른 개발자의 FistAnimInstance 변경을 검토했다. 본 문서는 정적 검토이며 런타임·영상 검증을 대체하지 않는다. 검토 중 소스는 수정하지 않았다.

## 조치가 필요한 사항

- P2 — 차징 해제 시 팔꿈치 폴 목표가 순간적으로 변경된다. `Source/Rogue10m/Character/Rogue10mFistAnimInstance.cpp:800`~804에서 차징은 `SmoothPhase(Charge) * Enter * 0.5`, 훅의 시작은 `0.35`, 스트레이트는 기본값 `0`을 사용한다. 완충 직전(예: 0.85초 기준 약 0.80초) 놓으면 스트레이트로 선택되면서 폴이 약 0.5에서 0으로 바뀐다. 두 폴의 차이 `(4, 20, 29)`에 약 0.5가 곱해져 목표가 약 17.7cm 이동한다. 손 목표는 594~612에서 이전 자세를 포착하지만 팔꿈치에는 동일한 이음 처리가 없어 하완 회전이나 팔꿈치가 튈 수 있다. 출시 전 이음 보완 또는 해당 전환의 실제 골격 프레임 검증이 필요하다. 애니메이션 담당과 root에 전달했다.

## 확인한 계약

- `Rogue10mBasicBrawlerComponent.cpp:126`에서 짧은 해제는 RightStraight, 완충 해제는 RightHook이다. 애니메이션 577~580의 분류와 일치한다. enum 기존 값 0~3은 유지되고 RightJab=4, RightHook=5가 추가됐다.
- 입력의 LastHitFraction은 지연시간/재생속도/실제공격길이로 계산된다. 애니메이션 582~585가 이를 Peak로 사용하고 646~653에서 정확히 해당 정점에 도달한다. 공격 중 손에 추가 지연 필터를 적용하지 않는 790~792도 계약과 일치한다. 단, 실제 골격의 최대 팔 길이 제한(807~811) 이후 손 위치와 첫 피해 프레임은 런타임에서 확인해야 한다.
- 훅은 외측 준비점→외측 곡선 제어점→중앙선 반대편 정점으로 이동한다(632~653). 786~788은 양손의 실제 골격 부호를 한 번 적용한다. 594~600은 저장된 손 좌표의 부호를 다시 정규화하므로 중앙선을 넘은 훅을 다음 입력으로 끊어도 양수 절댓값으로 튀지 않는다.
- 좌클릭 2타 예약 시 719~728이 다음 오른손 잽을 준비한다. 다음 공격의 AcceptedSerial이 바뀌면 608~611이 현재 손 위치를 새 시작점으로 보존한다.
- Unarmed 분기는 292~309에서만 활성화되고 442~446 이후 기존 너클 경로와 분리된다. 무기 전환 시 손·몸·차징 보간 상태를 초기화한다. 너클의 기존 몽타주 평가 및 손 공간 보정은 유지된다.
- 카메라 전달값은 767~771에서 위치 최대 2cm, pitch/yaw ±1.5도, roll ±0.8도로 제한된다. ControlRotation을 직접 바꾸는 코드는 해당 애니메이션에 없다.

## 통합 검증 요청

- 0.80초 차징 후 놓기→스트레이트, 0.85초 이상 차징 후 놓기→훅을 각각 측정한다.
- 네 공격의 실제 첫 피해와 손 정점 시점을 함께 기록한다. 훅은 앞으로 가장 멀리 간 프레임보다 중앙선을 가로지르는 접촉 프레임을 기준으로 판단한다.
- 훅→다음 입력, 좌클릭 예약 연타, 무기 변경 후 복귀를 실제 팔/하완 골격으로 확인한다.
- 기존 너클 및 아래보기 회귀 검사를 실행한다.

## 재검토 및 타격 피드백 검토

- 팔꿈치 P2는 수정된 소스에서 해소됐다. FistAnimInstance의 차징/공격 시작 시 `CurrentHookElbowWeight`를 각각 포착하고, 733~749의 짧은 보간으로 해제 후 목표를 잇는다. 훅 준비 0.5→정점 1→회수 0도 연속이며 단순 스트레이트로의 해제는 기존 폴에서 0으로 감쇠한다. 실제 프레임 검증은 여전히 필요하다.
- P2 — 피드백이 공격 실행을 시작한 무기 대신 현재 장착 무기만 검사한다. `Rogue10mCombatComponent.cpp:1069` 및 `1245`가 현재 Unarmed 여부로 복싱 반응/효과 위치를 선택하지만, `CancelPendingAttackHits:1306`은 첫 펄스 전 지연 공격만 취소한다. 다른 무기의 다단 공격이 첫 타격 후 남아 있는 상태에서 Unarmed로 바꾸면 후속 타격이 복싱 반응을 낼 수 있다. 실행 생성 시 출발 무기/복싱 여부를 포착해 현재 무기 조건과 함께 확인하는 보완을 요청했다.
- 테스트 수정 필요 — `Rogue10mBoxingFeedbackRuntimeTest`의 피해 거부 fixture는 `SetCanBeDamaged(false)`만 설정한다. 그러나 현재 BasicMonster::TakeDamage와 UE5.8의 AActor::TakeDamage, UGameplayStatics::ApplyDamage에는 해당 속성을 검사하는 gate가 없다. 실제 피해가 발생하므로 155프레임의 거부 검증은 실패할 수밖에 없다. Damage=0 fixture 또는 명시적인 제품 피해 거부 조건을 사용해야 한다. root에 근거를 전달했다.
- 컴파일/IWYU — 테스트에서 `TWeakObjectPtr<UMaterialInterface>`를 대입/Get하면서 Materials/MaterialInterface.h를 직접 포함하지 않는다. 완전형 의존을 보장하도록 헤더 포함을 권고했다.

다음 사항은 정적 검토상 일치한다.

- 유한한 양수 AppliedDamage 이후에만 hit-count, 이펙트, 피드백이 발생한다.
- 실행별 `bConfirmedCameraFeedbackSent`가 다수 대상/다단 펄스에서도 카메라 충격을 한 번만 보낸다.
- HitFeedbackComponent의 동적 머티리얼은 UPROPERTY TObjectPtr로 GC에 추적되며, 메시 참조는 weak이다. 기존 전체/슬롯 오버레이가 있으면 설치하지 않고, 자신이 설치한 인스턴스일 때만 제거한다.
- 반복 피격은 원본 메시 transform을 다시 기준으로 계산하므로 누적 이동을 만들지 않는다. 콜리전 Actor transform은 변경하지 않는다. 사망·물리 전환·EndPlay 시 타이머와 자신이 소유한 오버레이를 정리한다.
- POV 충격은 기존 몸-머리 필터 상태와 분리돼 최종 View에만 더해진다. 합산 이후에도 기존 위치/회전 제한을 적용하고, 비유한 입력·카메라 크기 0·무기 변경 시 충격을 초기화한다. 실제 CameraComponent와 ControlRotation은 수정하지 않는다.

## 최종 재검토 — 지적 사항 해소

정적 재검토에서 남은 수정 요청은 없다. 아래 항목은 실제 실행 최종 통과 로그와 함께 판단한다.

- 무기 출발 정보 P2 해소: `FRogue10mActiveAttackExecution::bBrawlerPresentation`을 공격 실행 생성 시 포착한다(`Rogue10mCombatComponent.cpp:831`). 피해 후에는 포착값과 현재 Unarmed 여부를 모두 검사한다(1072). 동일 bool을 SpawnImpactEffect에 전달하고 위치·방향 보정에도 적용한다(1252). 다른 무기의 남은 다단 피해 자체는 기존 방식대로 유지하면서 복싱 효과가 섞이는 문제를 차단한다.
- 무피해 fixture 해소: `Special->Damage = -AttackPower`로 데이터상 피해 합계를 0으로 만들었다. `Rogue10mAttackSkillData::RollDamage:25`의 `Max(0, Damage + AttackPower)`에 의해 실제 RolledDamage가 0이 되며, 기존 스킬 Damage는 Finish에서 복구한다. 제품의 무적 처리 의미를 변경하지 않는다.
- MaterialInterface IWYU 해소: 테스트에 `Materials/MaterialInterface.h`가 추가됐다.
- 사망 테스트 해소: 195프레임에 타깃 weak 참조가 유효할 때만 생존 시체의 피드백/오버레이 복귀를 검사한다. 이미 Destroy된 몬스터를 역참조하던 테스트 결함을 제거했다. root 보고 기준 첫 실행은 해당 테스트 역참조 지점에서 종료됐으며, 앞선 구현 관련 assertion 실패는 없었다. 이를 최종 통과로 간주하지 않고 재실행 결과를 기다린다.
- 팔꿈치 P2 정적 해소 상태 유지: 0.8초 차징 후 스트레이트 해제 사례와 실제 lowerarm_r의 최대 프레임 이동량 12cm 미만 검증이 신규 테스트에 추가됐다. 합격 여부는 최종 런타임 로그로 확인해야 한다.

## 최종 판정: PASS

최종 소스와 실제 로그를 직접 대조했다. 기본 격투 480프레임, 팔 전용 시야 390프레임, 타격 피드백 280프레임, 기존 너클 120프레임 검사에서 failures=0을 확인했다. 근거: `tmp/boxing-combos/basic-regression.log:2337`, `runtime.log:1752`, `feedback.log:1720`, `knuckle-regression.log:2091`.

- 마지막 스트레이트 보완은 팔을 늘리는 대신 몸통/어깨의 전진을 조절한다. `BasicStraightBodyAdvance=7`을 UPROPERTY로 노출하고 proxy에서 0~12cm로 제한해 스트레이트 분기에만 적용한다. 기존 너클 경로에는 적용되지 않는다.
- 훅의 반대쪽 가드는 `BasicHookGuardOffset=(6,-7,1.5)`를 통해 옆/뒤로 물리며 기존 BodyDrive에 맞춰 시작·종료한다. 손의 좌우 부호 적용, 기존 팔 길이 제한 및 카메라 최종 제한은 유지된다.
- 실제 오른손 스트레이트 전진 위치는 가드 X=37.500에서 피해 프레임 X=47.692로 바뀐다. 양팔 상완/하완 길이는 모든 ARM_CHAIN 표본에서 27.771/27.251cm를 유지했다.
- 완충 직전 해제 전환의 최대 팔꿈치 프레임 이동은 10.190cm이며 설정한 12cm 기준을 통과했다(`feedback.log:1719`).

남은 정적 차단 사항은 없다. 이번 판정은 현재 전용 자산과 테스트된 스켈레톤/시야 조건을 대상으로 한다.
