# 손 내린 대기 → 권사 공격 전환 시각 검증

## 판정

**최종 실제 게임 캡처의 대기 → 잽 2타 → 오른 스트레이트 → 차징 훅 → 손 내림 복귀 흐름은 시각 검토 통과다.** 대기 중 정면 시야가 열리고, 공격할 때 손이 올라오며, 잠시 가드를 유지한 뒤 다시 내려가는 상태 변화가 명확하다. 기존 초안의 큰 팔 쓸어올림 원호나 관절 분리는 최종 대표 프레임에서 관찰되지 않았다.

검증2는 런타임 테스트 fixture를 작성했으나 실제 포즈 구현 파일 `Rogue10mFistAnimInstance`는 작성하지 않았다. 따라서 포즈 구현과 시각 검토 담당은 분리되어 있다. 본 검토는 대표 프레임과 전후 연속 자세를 이미지로 확인한 결과이며, 전체 영상의 모든 프레임을 실시간 재생하여 검토했다는 뜻은 아니다.

## 최종 증거

- 실제 캡처: `Saved/Screenshots/WindowsEditor/BrawlerIdleTransitionLookDown/frame_####.png`
- 검사 시트: `visual-review-0.jpg`, `visual-review-1.jpg`
- 직접 확인 프레임: 25, 40, 49, 52, 65, 140, 193, 203, 285, 335, 355, 445
- 시점: 공격 구간은 정면·UI 포함. 처음 20~34, 끝 441~449 프레임은 손 내린 자세 확인을 위해 아래 65°·UI 제외.
- 최종 촬영 실행: `tmp/relaxed-idle/preview.log`, `BRAWLER_IDLE_TRANSITION_PASSED`, 453틱, 실패 0. 영상은 450프레임이고 마지막 3틱은 무기 복원 검증이다.

## 관찰

| 구간 | 확인 결과 |
|---|---|
| 25 / 445 아래보기 | 플레이어 왼손이 몸 옆 아래에 내려와 편 상태로 보이고 자기 다리·발 일부가 보인다. 오른손 전체는 시야 밖이므로 양손 전체의 모양을 눈으로 확인했다고 주장하지 않는다. |
| 40 / 140 / 285 정면 대기 | 손이 화면 앞을 가리지 않아 정면 시야가 열린다. 타격 이후 다시 이 상태로 복귀한다. |
| 49 → 52 첫 잽 | 준비 초기에 손이 아직 아래에 있고, 이어 왼팔이 앞으로 뻗으며 반대손은 가드 쪽으로 올라온다. 팔이 크게 원을 그려 돌아 올라오는 초안의 현상은 대표 프레임에서 보이지 않는다. |
| 65 오른 잽 | 오른손 타격과 반대 왼가드가 구분된다. |

| 335 → 355 차징 훅 | 오른손을 뒤로 준비하는 모습과 이후 옆에서 들어오는 오른손 타격이 구분된다. 왼손은 가드를 유지한다. |

대표 프레임에서 메시 구멍, 좌우 손 뒤바뀜, 팔 관절 분리, 복귀 후 손이 엉뚱한 위치에 고정되는 현상은 관찰되지 않았다. 오른쪽 공격 중 반대 왼가드는 여전히 화면 좌상단에서 크게 보이며 일부 잘린다. 이는 현재 카메라와 근접 가드의 프레이밍 한계로 남는다.

## 수치 검증과의 구분

최종 촬영 로그는 손의 프레임 간 이동 최대 16.935cm, 팔 길이 오차 0, 피해 4회, 타격 시점 오차 최대 0.02735초를 보고한다. 손목의 프레임 간 회전 최대는 45.272°로 기록되며 자동 통과 임계값을 임의로 설정하지 않았다. 준비 동작이 빠른 구간에는 모션 블러가 보인다.

손을 내리는 도중 재입력하는 별도 최종 실행은 `reentry-final.log`의 수치 검증을 따른다. 해당 실행은 캡처를 생략했으므로 재입력의 최신 전체 동작을 직접 영상으로 확인했다고 주장하지 않는다. 양손 하강, 피해 발생 시 준비 가중치 1, 팔 길이 보존, 입력·피해 수, 무기 전환 후 준비 상태 복원은 별도 런타임 assertions로 검증한다.
