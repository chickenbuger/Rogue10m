# 격투가 UI·콘텐츠 독립 검토

검토일: 2026-09-30. 역할: 구현 담당을 바꾼 읽기 전용 Reviewer. 이 문서 외 게임 소스·에셋·검증 코드는 수정하지 않았다. 빌드와 Unreal 실행은 통합 담당이 단독 진행한다.

## 판정

완료 판정: 이번 로컬 싱글플레이 격투가 스킬트리·테스트 해금·키 설정 범위에 남은 blocker는 없다. 발견했던 테스트 저장 슬롯 가드 불일치와 테스트 점프 상태 복구를 수정했고, 최종 전체 107항목·저장 복원 2항목이 실패 없이 통과했음을 독립적으로 확인했다. 공격 13개의 키 실행과 몽타주 검사는 각각 13개 모두 통과했다. 기존 무기 11종과 맨손·너클 전투 840프레임 회귀도 실패 0이다. 아래 한계는 검증 범위를 명시한 것이며 확인된 잔여 결함이나 완료 차단 사유가 아니다.

## 수정 완료: 테스트 저장 슬롯 가드 불일치

- 대상: `Source/Rogue10m/Tests/Rogue10mFighterSkillTreeRuntimeTest.cpp`, `FRun::Start`.
- 최초 검토에서 테스트는 `Rogue10m_Fighter_QA_` 접두사만 검사하고, 실제 컴포넌트는 길이 100자 이하와 영숫자·밑줄 문자도 요구하는 불일치를 발견했다.
- 예를 들어 `-RogueSkillKeySaveSlot=Rogue10m_Fighter_QA_bad-name`으로 테스트가 사용자 기본 슬롯을 변경할 수 있었다.
- 현재 `FRun::Start`는 접두사·길이·문자 조건을 모두 동일하게 검사한다. 실패하면 상태 준비와 키 저장 전에 `Finish`로 종료한다. 수정 코드를 확인했으며 이 항목은 해결했다. 유효하지 않은 인자의 실제 실행 시험은 이번 재검토에서 수행하지 않았다.

## 정적으로 확인한 내용

- `Rogue10mMenuWindowWidgets.h/cpp`: 테스트 해금 버튼은 Shipping에서 숨기며 API도 Shipping에서 동작하지 않는다. 키 지정은 활성 트리의 해금된 공격 기술만 허용한다. 패시브·잠긴 기술은 선택기를 비활성화한다. 키 설정 오류는 실제 컴포넌트가 반환한 사유를 표시한다.
- 키 선택 위젯은 단일 키를 안내하며 modifier/gamepad 선택을 끈다. 캡처 취소는 Slate 포커스를 해제한다. UE 5.8 `SInputKeySelector::OnFocusLost`가 선택 취소를 처리하는 구현도 확인했다. 프로그램에서 선택 키를 갱신할 때는 재진입 방지 플래그를 사용한다.
- 해금·바인딩 이벤트 수신, 창 열기·닫기와 기술 변경 시 선택 취소, 상세 패널 스크롤 추가가 연결되어 있다. 새 버튼·선택기 이름은 헤더, 생성기, validator, runtime test에서 일치한다. 알려졌던 이름 불일치는 현재 파일에서 수정됨을 확인했다.
- `ConfigureFighterSkillTree.py`: 원래 무공 10개 뒤 기본 4개를 추가하여 두 프로필에 같은 순서의 트리를 설정한다. 기본 4개의 티어·배치와 프로필 제목·설명만 바꾸며 명시 초기 해금 배열과 기존 기본 입력 배열을 보존 검사한다. 몽타주, 피해, 자원, 차징, 재사용 대기시간, 선행조건·진행조건 등 열거된 전투 필드는 변경 전후 비교한다.
- `ValidateMartialArtistSkillTree.py`: 14개 노드, 네 티어, 패시브 1개·피해 감소 15%, 기존 상위 9개 무공의 조건, 두 프로필 트리 동일성과 필수 위젯 이름을 검사한다. 출력의 `initial=1`은 너클의 명시 배열 크기이며 실제 최초 해금 수 5와 구분해야 한다.

## 직접 읽은 생성·빌드 증거

- `build-tested.log`: 갱신된 `Rogue10mFighterSkillTreeRuntimeTest.cpp` 컴파일, DLL 링크와 메타데이터 기록 후 `Result: Succeeded`를 확인했다. 보존된 최초 `build.log`에는 실패 기록이 있으므로 최종 성공 증거와 혼동하지 않는다.
- `editor-assets.log`: `FIGHTER_SKILL_TREE_CONFIGURED profiles=2 skills=14 combat_preserved=true` 및 위젯 2개 생성 완료를 확인했다.
- `editor-validation.log`: 14개 노드·네 티어·프로필 2개·패시브 15%·위젯 2개 검증 통과를 확인했다. 이름 검사는 현재 콘텐츠의 `축경권`을 사용한다.
- `asset-preservation.json`: 프로필 2개, 변경 전후 각각 14개의 서로 다른 기술 경로를 확인했다. 전체 `combat_before`와 `combat_after` 객체를 깊이 30의 JSON으로 다시 직렬화하여 대소문자를 구분한 동일성 비교를 수행했고 일치했다. 초기 배열과 기본 바인딩 보존 플래그도 모두 참이다. 이 증거는 열거된 전투·진행 필드의 구성 실행 전후 보존을 뒷받침한다.

## 최초 런타임과 테스트 상태 복구 수정

`fighter-full-first-trial.log`의 PASS/FAIL을 직접 집계했다. 최종 결과는 `assertions=94 active_executed=13 failures=2`이며 PASS 92개, FAIL 2개다. `active_executed=13`은 시도 횟수다. 실제 기술별 키 발동과 몽타주 검사는 각각 12개가 통과했다. 실패한 두 항목은 모두 `DA_Attack_StoneFist_ChargedShockwave`의 발동·몽타주다.

Slate 선택기 진입·종료 8개와 저장·Esc 취소·예약 키 복원·새 키 저장 4개를 합친 12개 검사가 모두 통과했다. 차징 중 메뉴 열기, 무기 변경, 일시정지, 이전 보유 키 재지정 취소도 각각 통과했다.

실패 직전 `JumpSlam`의 지상 거부·공중 발동·몽타주는 모두 통과했다. 최초 테스트는 점프를 위해 플레이어를 Z+250cm로 옮기고 중력을 0으로 만든 뒤, 정리 단계에서 중력 1과 Walking 모드만 복구했다. 위치를 복구하지 않았으므로 다음 지상 기술의 키 누름까지 0.5초 사이 다시 Falling 상태가 될 수 있다. 전투 코드의 `CanUseBoundSkill`은 점프 슬롯 여부와 `IsFalling`의 일치를 요구하고, 차징 시작·감시·놓기에서 이 검사를 사용한다. 지상 차징을 거절하는 현상은 이 테스트 준비 오류와 일치한다. 다만 최초 로그에는 키 누름 순간의 이동 모드가 기록되어 있지 않으므로 이 로그만으로 원인을 단정하지 않는다.

현재 수정된 테스트는 시작 위치 `GroundPosition`을 저장하고, 점프 정리 시 그 위치로 teleport한 뒤 속도 0·중력 1·Walking을 복구한다. 지상 기술별 Falling 아님 assertion도 추가되었다. 최종 `fighter-final-full.log`에서 ChargedShockwave의 지상 상태·키 발동·몽타주가 모두 PASS로 바뀌었고 전체 107항목이 통과했으므로 이 재검증 항목은 해결했다. 최초 실패 로그도 보존되어 있다. 본 Reviewer는 생산 코드와 테스트 코드를 수정하지 않았다.

별도로 통합 담당이 수정한 입력 충돌 검사에서는 자체 InputAction의 소유자를 `GetOuter() != this`로 구분한다. 같은 프레임의 매핑 재구성 전까지 남는 이전 자체 Action을 외부 충돌로 오인하지 않는 의도와 코드가 일치한다. 외부 Action은 계속 충돌 대상으로 남는다.

## 실검증 범위와 남은 공백

최종 실행은 실제 Enhanced Input 키 입력, 키 변경·해제, 기존 입력 충돌, 잠긴 기술·패시브 거부, 메뉴 중 입력 차단, 무기 전환, 차징의 짧은 누름 거부와 release 발동, 13개 공격 기술의 사용 횟수·몽타주, 별도 프로세스 저장 복원을 통과했다. 실제 Slate 키 선택기의 Enter 진입→키 해제→선택 콜백→저장, Esc 취소, 예약 키 거부 후 기존 키 유지, 같은 프레임 연속 변경, 차징 중 메뉴·무기 교체·일시정지·이전 키 재지정 시 취소도 통과했다.

다음은 현재 테스트로 증명되지 않는다.

- 실제 마우스로 노드를 고르고 버튼을 누르는 전체 UI 경로. 노드 선택은 `SelectSkill`, 해금 버튼은 `OnClicked.Broadcast`를 사용한다. 새 선택기 시험은 실제 Slate 위젯의 키 핸들러를 직접 호출하므로 운영체제 입력의 전체 라우팅과는 구분한다. 조합 키 거부·선택 중 창 닫기·다른 해상도의 화면 배치는 이번 자동 검증 범위 밖이다. 1920×1080 캡처의 배치는 위에서 별도로 확인했다.
- 이미 눌려 있는 새 목적 키에 기술을 지정할 때 release 전 미발동, 손상되거나 충돌하는 저장 데이터 복원. 새 held-remap 시나리오는 기존에 누른 키를 다른 키로 바꿨을 때 이전 차징의 취소를 검사한다.
- 13개 모두의 실제 피해 적중. 전 기술은 발동·몽타주 검사이며 대상 체력 감소 검사는 최초 잽 한 개다. 패시브는 계산된 감소율 검사이며 피격 피해량 비교가 아니다.
- 전체 수련·토벌 기록 불변. 테스트는 잽 사용 횟수 한 개를 비교한다. 해금 구현이 기록을 조작하지 않는 것은 정적 검토로 확인되지만 모든 기록의 런타임 스냅샷 비교는 없다.
- 자원 부족·사망 입력 차단과 냉각 실패 시 자원/시각효과 무변경. 현재 냉각 검사는 반환값만 확인한다.

실제 결과 요약에서 위 범위를 확대해서 표현하지 않아야 한다. 임의의 모든 전투 필드나 모든 애니메이션이 보존되었다는 주장은 열거된 필드 비교만으로 대신할 수 없다.
