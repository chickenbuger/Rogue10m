## 도형·라벨·상태

마름모는 녹색/붉은색/푸른색 아이덴티티에서 모두 식별된다. 원형 중앙 몸체와 외곽 마름모가 역할을 구분하며, 공명은 내부 원과 별도 외부 원을 읽을 수 있다. 720p에서 잠긴 회색 외곽선은 활성 계열보다 약하지만 이름과 잠김 상태를 함께 확인할 수 있다.

외곽 기준 간격 보완 후 아이덴티티 이름이 마름모 모서리와 부딪히는 모습은 없다. 공명 라벨도 두 번째 원 아래에 놓이고 하단 프레임 안에 남는다. 소스의 배치는 외곽 extent에서 9 단위 간격이며, 공명 라벨 범위는 그래프 y=741~787/높이 790이다. 이 값은 화면상의 비겹침과 일치한다. 중앙 정권 계열은 여전히 촘촘하지만 이름·M단계·상태를 두 행으로 읽을 수 있으며 기본 노드나 옆 체술 노드의 글자와 직접 겹치지 않는다.

잠긴 기술과 간선은 회색, 전수된 기술과 연결은 금색, 활성 아이덴티티와 공명 연결은 계열색으로 구별된다. 대검술사 화면에는 활성 마나와 조건을 충족한 투지 입문이 함께 보이지만 투지 심화·성질은 잠겨 있다. 흰 외곽선은 종료 후 캡처에서 선택된 기술을 가리킨다. 격투가에 마나가 표시되거나 대검술사에 내공이 표시되는 사례는 없다.

## 상세 스크롤과 고정 동작 영역

720p의 상세 본문에는 스크롤바가 있고 본문 하단 일부가 스크롤 경계에서 잘린다. 본문 아래 키 지정·키 해제 동작은 별도 영역에 남아 프레임 안에 보인다. 1080p의 F7/F8 캡처에서도 긴 상세 조건과 고정 키 동작 영역이 분리된다. 이 여섯 사진에는 미전수 상태의 전수 버튼 사례가 없으므로, 모든 동작 버튼의 클릭 성공을 사진만으로 주장하지 않는다.

## 드래그 중 노출과 종료 후 복원

1080p와 720p 드래그 중 사진에서 검은 패널이 실제 HUD를 가리던 문제는 해소됐다. 패널의 도형·연결선은 옅은 잔상으로 남지만, 실제 전투 슬롯의 테두리·아이콘·입력명은 확인할 수 있다. 이 상태는 일반 상세 열람 상태와 명확히 구별된다.

두 드래그 후 키 캡처는 모두 1080p이며 정상 패널 불투명도, 유지된 선택 기술, 사라진 드래그 표시를 확인한다. 720p 종료 직후의 별도 전체 화면 사진은 이 묶음에 없으므로 720p의 정확한 복원 값은 런타임 검사 근거로 구분한다.

`runtime-results.txt`에는 실제 외곽 마름모·공명 pointer 선택, `input_active_drag_dims_menu_and_exposes_HUD_hit_testing`, 실제 HUD 슬롯 드롭, E 회피 슬롯 거절, 메뉴 닫기 중 소유 Slate 드래그 취소, 종료 후 visibility/opacity/열림 상태 복원, 선택 기술 보존 검사가 모두 PASS로 남아 있다. 실제 키 선택·취소·예약 키 거절·재지정·단일 발동 검사도 PASS이고 최종 input/runtime marker는 각각 failures=0이다. 이는 생성한 실제 엔진 입력 경로의 검사이며 OS 입력 장치 전체나 모든 기술의 전수 검증으로 확대하지 않는다.

## 근거와 범위

`build-02.log`의 Editor 빌드는 Succeeded/103.04초다. 자동화와 새 프로세스 읽기 결과의 종합 판정은 담당 결과 문서에서 관리한다. 이 문서는 위 PNG와 해당 runtime marker를 확인한 시각 검토다.

공유 Content가 작업 내내 불변이었다고 주장하지 않는다. 공유 root 추적 Content 6,423개 삭제 사고와 복원 후 전량 blob 대조의 근거·한계는 [incident-review.md](incident-review.md)에 있다. 이번 최신 실행은 담당자가 확인한 실제 독립 Content 구성에서 수행한 결과다. 복원 감사 자체를 이번 UI 시각 확인이나 입력 성공의 대체 근거로 사용하지 않았다.

최종 시각 판정: 확인한 두 해상도에서 도형·외곽 라벨·동작 영역·드래그 중 HUD 노출·정상 패널 복원이 수용 가능하다. Shipping 패키지, 장시간 플레이, 다른 UI 배율과 모든 입력 장치·기술 조합은 이번 사진 검토 범위에 포함하지 않는다.
