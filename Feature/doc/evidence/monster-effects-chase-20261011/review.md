# 몬스터 시야 추적·Niagara 변경 검토

## 확인한 변경

시작 소스 사본과 실제 구현의 한정 diff를 검토했다. 다른 기능의 누적 diff와 분리해 AIController cpp/h, 공격 프로필, PatternComponent cpp/h, CombatTestComponent의 자동 AI 및 사거리 테스트 함수, 신규 QA·Editor 제작 도구를 확인했다.

## 발견 및 수정

1. 풀링된 Niagara의 Weak 포인터만 보관하면 시스템 완료 후 다른 몬스터가 같은 컴포넌트를 사용할 때 정지가 간섭할 수 있다. 완료 델리게이트에서 소유 목록과 델리게이트를 제거하고, 취소 시 목록을 먼저 이동해 비우고 즉시 비활성화한다. 수동 DestroyComponent를 사용하지 않는다.
2. AI 정지 후 시야/피해 콜백이 목표를 다시 잡을 수 있어 실행 플래그와 재개 시 시야 재수집을 도입했다. 몬스터·목표가 홈 리시 밖이면 즉시 재인식하지 않는다.
3. Idle에서도 짧은 공격 효과가 남을 수 있으므로 목표 정리 시 패턴 취소를 호출한다. 실제 정지·재개·리시 테스트를 통과했다.
4. 수동 UI가 짧은 공격의 최소 거리를 120cm로 고정해 사거리 120cm의 초록 점액체에서 부동소수점 경계 실패가 발생했다. 프로필 사거리보다 20cm 안쪽에 놓도록 수정했다.
5. 최초 원본 통합은 copy2가 헤더의 오래된 수정 시간을 보존해 UHT 재실행이 생략되었다. 원본 소스의 수정 시간만 갱신하고 정식 빌드로 선언을 재생성했다. 생성 파일을 직접 편집하지 않았다.
6. 다중 Editor의 Remote Execution은 프로젝트 경로로 정확히 하나를 선택한다. 원본과 worktree의 서로 다른 노드를 실제 발견해 확인했다.

## Unreal 및 수명 점검

- 신규 에셋 보유는 UPROPERTY/TObjectPtr, 비소유 컴포넌트는 Weak, 동적 완료 콜백은 UFUNCTION이다.
- 전용 서버에서 Niagara 로드를 생략하며, 기존 공격의 권한·기하·타깃·벽 가림·한 번 명중 규칙을 유지한다. 신규 Tick과 생성자 월드 조회가 없다.
- 효과 스폰은 실패해도 게임 피해를 변경하지 않는다. 명중 효과는 양수 피해가 실제로 적용된 경우에만 생성한다.
- 단회 CPU burst 8개는 모두 컴파일 UpToDate, 오류·경고 0, 스택 오류·경고 0이다. 기존 Niagara 소재의 Sprite/ParticleColor 렌더러를 사용하며 컬러·형태·속도·수명이 종별로 저장되었다.
- 새 소스와 원본 통합본 7개는 바이트 일치를 확인했다. 에셋 14개(신규 Niagara 8개, 기존 공격 프로필 6개)만 반영했다. 기존 몬스터 스탯·난이도·특성·보상·애니메이션 데이터는 보존한다.
- 격리 QA 최종 110검증·실패0을 확인했다. 원본 통합 빌드는32.42초에 성공했다. 통합 플레이 및 기존 F6 UI 회귀 결과는 feature 결과 문서에 기록한다.

검토 결과: 현재 범위의 차단 결함 없음. 패키징·네트워크 이펙트 전달은 이번 로컬 단일 플레이 요청의 검증 범위에 포함되지 않는다.
