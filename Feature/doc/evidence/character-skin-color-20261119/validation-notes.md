# 작업 중 확인한 실패와 대응

- 첫 정규 빌드는 별도 체크아웃 에디터의 공용 Live Coding 잠금에서 멈췄다. 다른 에디터가 사용 중인 프로젝트와 출력 로그를 확인한 뒤, 현재 체크아웃만 `-NoHotReload -NoHotReloadFromIDE`로 빌드했다.
- 첫 격리 빌드에서 제어부의 로컬 `Slot`이 `UWidget::Slot`과 이름이 겹쳐 C4458이 발생했다. 이름을 역할별로 수정했다. 출시 위젯에서 생성 패널은 Border여서 기존 피부색 버튼의 직접 부모 Canvas를 기준으로 배치했다. 후속 빌드는 통과했다.
- 첫 UV 조사에서 Geometry Script의 UV 함수 이름을 바로잡았다. 두 번째 실행은 외형 6종의 UV를 모두 기록한 뒤 `FPythonScriptPlugin::ShutdownPython()`에서 접근 위반으로 종료됐다. 읽기 전용 실행이었고, 출력 파일별 종족과 삼각형 및 목 경계 UV를 별도로 대조한 뒤 보정 입력으로 사용했다.
- 첫 두 재질 생성 실행은 애셋 저장 전에 중단됐다. Clamp 입력의 실제 이름은 빈 문자열이었고, 머리 재질 기본 마스크로 참조하려던 엔진 텍스처를 해당 프로젝트에서 불러올 수 없었다. 확인된 입력 핀과 새 피부 마스크로 변경했다.
- 세 번째 실행의 에디터 API는 재질 파라미터를 설정한 뒤에도 `false`를 반환했다. 엔진 구현을 확인하고 값을 다시 읽어 판단하도록 바꿨다. 네 번째 실행은 115개 패키지를 저장했고 출력 로그 오류는 0건이었다.
- 첫 실제 게임 실행에서 341개 검사와 로그가 통과했고, 초기 생성 캡처에는 셰이더 준비 중 회색 프리뷰가 남았다. 같은 세션에서 셰이더 완료 후 자동으로 다시 캡처했다. 대표 화면은 셰이더가 준비된 후 같은 흐름을 다시 검증한 실행에서 골랐다.
