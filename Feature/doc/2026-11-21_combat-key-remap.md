# 대시와 무기 아이덴티티 키 변경

| 동작 | 현재 키 |
| --- | --- |
| 회피·대시 | 왼쪽 `Ctrl` |
| 너클 질풍투기 | `V` |
| 외형 확인 카메라 | `C` (외형 확인이 가능한 카메라 모드) |

A안 HUD에서 왼쪽 회피 슬롯에 `Ctrl`, 오른쪽 무기 아이덴티티 배지에 `V`를 표시한다. 오른쪽 배지는 수동으로 고유기를 발동하는 너클을 장착하면 나타난다. 기존 슬롯 프레임과 좌표를 사용하며 키 이름은 실제 입력 정의에서 읽는다. 플레이 안내와 스킬트리 도움말도 실제 키와 일치한다.

## StartHub 검증

- UE 5.8 Editor 빌드와 1024×512 HUD 아틀라스 가져오기를 통과했다. 첫 가져오기는 공유 빌드의 SDK 점검을 기다리다 시간 초과했다. 재시도에서는 Win64 빌드를 끝낸 뒤 같은 환경의 자동 플랫폼 점검만 생략하고 새 아틀라스를 저장했다.
- 1672×941과 1280×720에서 72개 검사에 통과했다. Unreal 플레이어 컨트롤러에 왼쪽 `Ctrl`, `V`, `C`, 왼쪽 `Alt` 이벤트를 각각 보내 대시와 쿨다운, 너클 질풍투기, 지원되는 모드의 외형 확인 카메라, 기존 Alt 비발동을 확인했다. QA 저장 슬롯을 분리해 기존 루트 저장 파일 510개의 SHA-256을 보존했다. [입력과 HUD 검증 기록](evidence/combat-key-remap-20261121/runtime-contract.txt)
- 너클 캡처에서 왼쪽 `Ctrl`과 오른쪽 `V`가 각 프레임 안에 들어간다. 대검 캡처에서는 수동 아이덴티티 배지가 보이지 않는다. 새 글자와 겹치는 영역 밖의 픽셀 54,515개가 승인 아틀라스와 정확히 같고, 슬롯 좌표 차이는 0px이었다. [너클 화면](evidence/combat-key-remap-20261121/knuckle-key-labels.png) · [픽셀 비교](evidence/combat-key-remap-20261121/visual-comparison.txt)
- 격리 게임을 시작할 때 기존 UE Python 도구 초기화 오류 58줄이 기록됐다. 테스트 구간과 아틀라스 임포트 재시도의 오류는 0건이다.

최신 통합본은 자원 감소 연출을 포함한 상태에서 84개 검사를 통과했다. 위 캡처, 입력 기록과 픽셀 비교는 최종 통합본에서 얻었다.
