# 콘솔 없이 조절하는 1인칭 표현

기존 `AppearanceCamera`가 이미 1인칭이다. 이번 기능은 시점을 3인칭에서 교체하는 작업이 아니라, 이전에 추가한 선택형 FPHeavy의 무게감·안정화를 설정 메뉴에서 켜고 되돌리는 마무리다. 너클은 사용자 답변대로 현재 맨손 표현을 유지한다. 새 무기 모델·에셋·구매·생산 맵 변경은 없다.

## 사용자 경로와 유지 범위

캐릭터로 입장하고 O / Esc / F10을 눌러 **1인칭 표현** 카드를 연다. **무게감 사용** 체크박스로 켜고, **무게감 동작 강도**를 0~100%로 조절한다. OFF에서는 강도 슬라이더를 비활성화하되 선택값을 기억한다. **기존 표현으로 돌아가기**는 FPHeavy0/Motion1/FOV override0으로 복원한다. 두 모드 모두 1인칭이다. 강도0은 추가 손·머리 동작을 없애며, ON의 FOV86은 유지한다. OFF는 원래 FOV(현 QA90)를 쓴다.

이번 실행의 CVar만 변경하며 캐릭터 진행 저장, 키 바인딩, 전체 UserSettings를 쓰지 않는다. 창을 닫았다 다시 열면 실제 값을 재조회한다. 재실행 기본은 OFF다. 수동 필드 완주·장시간 조작성/멀미·전체 클리핑 및 기존 콜드 공격 hitch의 원인이 아직 검증되지 않아 기존 안정 표현을 기본으로 보존했다. 사용자는 콘솔 없이 새 표현을 시험하고 즉시 복원할 수 있다.

## 구현과 보호

- Controller h/cpp: 설정 컨텍스트의 토글·finite/clamp 강도·3필드 복원 API. 닫힌 메뉴/포기 확인/제출/결과창에서 거부하며 NaN은 부분 변경 없이 거부한다. UI 변경은 기존 CVar source priority에 맞춰 실제 값에 반영된다.
- AbandonMenuWidget h/cpp: 한국어 카드, checkbox/slider/value/restore, 실제값 재조회 가드. 포기 확인창에서는 카드가 숨겨지고 세 컨트롤이 비활성화된다. 기존 포기 정책·키·게임 시간·일시정지 규칙은 변경하지 않는다.
- RuntimeTest/VerifyFirstPersonSettings: 새 QA 프로필/성장 prefix/키 슬롯 3종의 정확한 라벨, 소유 프로세스만 종료, 기존 sav SHA256 감시, 실제 UMG delegate와 프로그램 입력, PNG·raw frame/PP 수치 보존. 사진01~06은 Hub, 07~08/이동 계측은 임시 충돌 바닥이다.

## 실제 검증

UE5.8.3 CL58210709, MSVC14.44, SDK10.0.22621.0. 최종 Editor Development 빌드D PASS(11.06초). 독립 정적 검토에서 수정 필요한 문제 없음. `git diff --check`와 생성물 경로 검사는 커밋 전 수행한다.

- `FpUiHeadB1029`: **560 확인항목 PASS**, 1635프레임. 프레임 반복 검사를 포함한 항목 수이며 560개의 독립 기능을 뜻하지 않는다. 네 구간 OFF→ON→ON→OFF에서 실제920cm/s·순XY1380cm 이상·grounded 유지, 카메라/trace 일치, 기존 PP 전체 동일성. 메뉴 토글·0/.4/1·NaN·복원·재열기·modal/result guard 포함.
- `FpUiMenuF1029`: 기존 포기 저장 실패·재시도·중복방지·귀환 **97항목 PASS**. 비렌더 프로그램 검증이다.
- `FpUiRenderC1029`: 실제 D3D11 PNG8장. UI 변경·복원·확인창 검사는 통과하고 사진01~06의 가독성을 검토했다. **전체 실행은 556항목 중5실패**로 PASS가 아니다. 세 번째 구간에서 W/Shift가 함께 해제돼 sprint가 풀리고 PP0이 된 데 따른 실패다. 다른 세 구간은 실제 이동 및 PP 조건을 통과했다. 입력 해제의 정확한 원인은 미확정이다. 렌더 성능/전체 ABBA의 성공 근거로 쓰지 않는다.

첫 `FpUiHeadA1029`는 메뉴 종료와 같은 프레임에 W를 주입했고 이동4건이 실패했다. `FpUiRenderB1029`는 실제 착지 후에도16건이 실패해 충돌 원인 가설을 철회했다. 가속이2프레임 뒤0으로 사라져 메뉴 포커스 전환과 주입 시점을 분리했다. UE `SetInputMode`/Slate 및 `LostFocus→FlushPressedKeys` 경로를 정적으로 확인했지만 당시 실제 Flush 호출은 계측하지 않았다. .3초 후 새 입력을 주입한 최종 HeadB는 통과했으며, RenderC의 한 구간 입력 해제는 별도 미해결 관측으로 남긴다. 게임의 포커스/input flush 규칙을 비활성화하거나 키를 반복 재주입해 실패를 가리지 않았다. QA 바닥 추가 중 빌드B는 UE5.8 SetBase(nullptr) 오버로드 모호성으로 실패했고 명시적인 FMovementBaseInterfaceData API로 교정했다. 실패 로그·사진은 삭제하지 않는다.

## 달리기 블러와 프레임 정지의 구분

기존 `PlayerFeedbackComponent::ApplyPostProcess`가 priority50 소유 PP에 sprint blur0.35, fringe0.6을 적용한다. 새 UI/FPHeavy가 이 값을 생성·변경하지 않는다. HeadB 네 구간의 전체 `FPostProcessSettings`와 priority/blend가 같았고, RenderC의 정상 이동 세 구간에서도 같은 값을 확인했다. 따라서 현재 보이는 달리기 블러·색 번짐은 기존 효과로 분리된다. 새 프로필의 FOV/머리 안정화 차이와는 별개다.
