- 관찰 방법: 1초 간격의 실제 녹화 프레임과 적 반응·카메라 변경 설명의 큰 화면을 읽었다. 아래 시간은 녹화 기준의 대략적인 구간이다.
- 역할: 주 담당이 영상과 자막을 직접 확인하고 서브에이전트가 현재 소스를 독립 분석했다. 서브에이전트의 이미지 도구는 처리 오류가 있어 독립 영상 시청 완료로 기록하지 않는다.

## 영상에서 확인한 단계

| 구간 | 영상의 설명과 실제 화면 |
| --- | --- |
| 도입 및 약3~7초 | 기본 공격에 Attack Feedback을 추가한다. 무기 궤적과 접촉 주변의 발광·입자가 보인다. |
| 약7~10초 | Enemy Reaction을 추가한다. 맞은 적의 자세·위치 변화와 밝은 피격 표현이 보인다. |
| 약10~12초 | Camera Shake를 추가한다고 설명한다. |
| 약12~15초 | UI Feedback 단계에서 체력바 같은 UI로 공격 결과를 보여준다. |
| 약15~18초 | Camera Change 단계. 자막은 락온 기능과 카메라 시점 조절을 설명한다. 단순한 줌 확대만을 의미하지 않는다. |
| 후반 | 효과가 합쳐진 예시와 별도의2D 게임 예시를 보여준다. |

핵심은 공격 모션에 효과를 무조건 크게 넣는 것이 아니라, 공격 동작·맞은 적·시점·UI가 함께 결과를 전달하는 것이다. 히트스톱이나 정확한 프레임 정지 길이는 이번 샘플로 확인하지 않았고 영상의 필수 요구로 적지 않는다. 오디오가 없으므로 소리는 분석하지 않았다. 영상의 설명은 참고 자료이며 새 기능을 자동으로 실행하라는 지시로 취급하지 않는다.

## 현재 Rogue10m과 대조

1. 명중 이펙트와 피해 숫자 경로는 이미 있다. CombatComponent::ApplyAttackDamage는 실제 적용 피해가 양수일 때만 ImpactEffect와 피해 숫자를 호출한다. Niagara는 스킬의 활성 플래그와 자산 참조가 있을 때만 생성된다. 이번에는 Editor 자산을 조회하지 않았으므로 기본 격투의 실제 VFX 설정값과 화면 활성 여부까지 확인했다고 단정하지 않는다.
2. 효과 위치는 현재 적의 바운드 중심이다. 주먹이 닿은 것처럼 읽히게 하려면 실제 판정에서 접촉 위치와 방향을 전달하거나, 판정 형태에 맞는 명시적인 접촉 위치 추정이 필요하다. 없는 접촉 정보를 정확한 타격점처럼 취급하지 않는다.
3. BasicMonster::TakeDamage는 체력·어그로·로그·죽음을 처리하지만 피격 플래시, 방향별 움찔, 넉백 호출은 없다. 적의 짧은 자세·재질 반응이 우선 보강점이다.
4. 현재 카메라는 평가된 몸·머리 움직임을 따르며 명중 여부에 따른 별도 충격은 없다. 기존 자연스러운 상체 동조를 유지하고 명중 때만 짧게 더해지는 반응을 구분할 수 있다.
5. 체력바는 이미 갱신되며 바라보는 몬스터를 추적으로 찾는다. 타깃 고정과 시점 추종 방식의 락온은 현재 경로에서 확인되지 않았다. 락온은 조작감을 바꾸므로 참고 영상만 보고 자동 도입하지 않는다.

## 앞선 갈브레나 녹화와 함께 적용할 방향

- 앞선 영상: 공격별 팔 진입·회수 경로와 다음 공격으로 이어지는 자세를 개선하는 참고.
- 이번 영상: 실제 명중에 맞춰 적 반응·접촉 효과·짧은 카메라 충격·체력 감소 강조를 함께 발생시키는 참고.
- 기본 잽은 짧고 선명하게, 강화 어퍼컷은 더 뚜렷하게 강도를 구분한다. 일반 가드와 이동의 흔들림을 모두 확대하지 않는다.
- 팔 전용 시야, 기존 입력·피해 시점·조준 계산을 유지하는 것을 기준으로 삼는다.

구현 설계 제안은 명중 확정 알림에 대상·공격 방향·일반/강화 구분 및 사용할 수 있는 접촉 정보를 담아 각 표현에 전달하는 것이다. 다수의 적을 한 번에 맞혀도 카메라 충격이 과도하게 중첩되지 않도록 같은 공격의 반응을 제한해야 한다. 기존 ImpactEffect와 피해 숫자를 다시 중복 생성하지 않는다.

후속 검증 기준은 헛스윙과 명중의 구분, 실제 피해1회에 대응하는 표현, 일반/강화의 차이, 조준 방향 불변, 연타·다수 피격 시의 카메라 복귀와 효과 중첩이다. 히트스톱·자동 락온은 별도 선택 항목이며 이번 참고 반영의 필수 구현으로 확정하지 않는다.

## 이번 작업 범위

영상 및 설명 확인, 현행 소스 대조, 참고 설계 문서화를 완료했다. 게임 코드·Data Asset·애니메이션·VFX 자산을 수정하거나 새 효과가 적용됐다고 주장하지 않는다. 기능 변경이 없어 빌드는 실행하지 않았다.
