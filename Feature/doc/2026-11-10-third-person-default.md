# 3인칭 기본 플레이 전환 결과

## 적용 범위
- `ARogue10mCharacter`에 캡슐 기준 스프링 암과 별도 3인칭 카메라를 추가했다.
- 기본 거리 320cm, 우측 어깨 오프셋 85cm, 피벗 높이 58cm, FOV 90도이다. 최초 기본 pitch는 -12도이며 이후 마우스 조준을 덮어쓰지 않는다. 카메라/회전 지연은 꺼서 마우스 회전을 직접 반영한다.
- `ECC_Camera` 14cm 구체 검사로 벽 앞에서 카메라를 당긴다. 충돌이 사라지면 정상 거리로 복귀한다.
- 기존 1인칭 카메라·외형·팔·설정 코드는 보존한다. 기본 3인칭일 때 1인칭 외형/팔/카메라 흔들림 정책만 비활성화한다. 1인칭 검수도 재개하지 않았다.
- 전신과 머리, 외형 부품은 소유자에게 표시한다. 원본 애니메이션 소스/리타게팅과 무기 갱신 이벤트는 유지했다. 3인칭 플레이어와 외형 부품은 바닥 경고 데칼을 받지 않는다.
- 공격 범위 원점은 몸의 눈높이이다. 카메라 뒤쪽에서 공격이 시작되지 않고 화면 중앙 지점을 향해 방향을 수렴시킨다.
- 새 카메라는 추가 키를 차지하지 않는다. 이동·점프·달리기·회피의 기존 키는 변경하지 않았다. 맵과 저장된 레벨도 변경하지 않았다.

## 검증
- 통합 빌드 B2: `Scripts/BuildEditor.ps1`, 성공. `Feature/doc/evidence/humanoid-boss-npc-20261110/build-B2.log`.
- 변경 diff 공백 검사: 성공.
- 전용 런타임 테스트: `Rogue10m.TestThirdPersonGameplay`와 `Scripts/VerifyThirdPersonGameplay.ps1`.
- 최종 TP_D1 렌더링 QA: 성공. 786개 체크/실패0, 663개 POV 유한 값 샘플, 실제 캡처5장, 엔진 Error/Ensure/Fatal0. 별도 정적 상태 체크에서 FOV90/전신·머리 표시/기존 1인칭 비활성/메뉴 복귀를 확인했다.
- 격리된 새 저장 네임스페이스와 일시 바닥/벽만 사용한다. 기존 저장은 실행 전후 SHA256으로 보존 여부를 확인한다.

## 최종 실측과 남은 범위
- TP_D1: 카메라 피벗 거리 331.247650→140.780243→331.247650cm. 실제 W 이동169.615646cm, 자유 회피248.077042cm, 벽 앞 회피39.971264cm.
- 실제 DA_Dodge_Unarmed 제작 값은 거리1000cm/지속0.16초이다. 거리 값은 초기 속도를 정하는 값이며 실현 이동거리와 같다고 주장하지 않는다. 회피 값과 타이밍은 수정하지 않았다.
- 실제 D 캡처5장을 직접 확인했다. 기본/이동/회피에서 캐릭터는 화면 왼쪽에 있고 중앙 시야가 비어 있다. 벽 수축 시 카메라는 벽 앞에 유지되며 낮은 몸 부분은 프레임 밖으로 잘린다. 회피 중 모션 블러도 보인다.
- 기존 저장390개 해시가 보존됐고 새 격리 QA 저장2개만 추가됐다.
- 근접 보스·무기의 실제 접촉/시야 가림, 장비별 모션 품질은 별도 보스/무기 검수 범위이다. 이 fixture에는 가까운 적 타깃이 없다.
- 물리 키보드/마우스 입력, 저장 후 재시작, 장시간 수동 전투와 전체 런은 미검증이다. 일반적인 모든 벽/자세의 클리핑 없음도 인증하지 않는다.
## 보존한 실패 후보와 후속 수정
- TP_A1: QA 이름 13자가 제작 제한 12자를 넘어 프로필 생성 전 실패했다. 386개 기존 저장 해시가 모두 보존되었다. 테스트 이름을 ThirdQa로 수정했다.
- 별도 엔진 초기화 문제: -game은 Editor Toolset의 AgentSkill 클래스를 로드하지 않아 Python init_unreal.py가 실패했다. C++ 게임 QA에서만 엔진 공식 -DisablePython을 적용하며 Python 에디터/에셋 제작에는 적용하지 않는다.
- 보스 Human3P_A1 실제 이미지: flat 카메라에서 근접 보스 가림, 바닥 데칼의 몸 투사, 미완료 셰이더의 임시 머티리얼을 확인했다. C 후보는 85cm 어깨/초기 -12도/플레이어 데칼 수신 중단/첫 캡처 셰이더 완료 대기를 적용했다. 아직 최종 시각 통과는 아니다.
- C 후보에는 마우스 중재와 13개 실제 Controller InputKey 경로 검사가 추가되었다. 별도 입력 계획 문서 참조.
