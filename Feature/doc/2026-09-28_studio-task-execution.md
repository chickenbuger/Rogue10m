# 일정 등록에서 개발 실행까지

작성: 2026-09-28 / Sprint#4-45-studio-task-execution

## 변경

스튜디오 일정에 자동 검토·실행, 시작 가능 시각, 선행 작업을 추가했다. Codex 앱의 현재 채팅 heartbeat가 5분 간격으로 `Studio/EXECUTION.md`와 `queue.mjs`를 사용한다. 우선순위·목표일 순으로 실행 가능한 작업 한 개를 선택하고 검토 → 개발 → 검증 → 완료를 기록한다. 목표일과 실행 시작 시각은 별개다. 기존 일정도 자동 검토 대상으로 유지하고 자동 검토를 끄면 수동 관리한다.

현재 실행은 편집/삭제를 막는다. 전체 일시정지나 개별 중단은 작업자가 다음 안전한 지점에서 반영한다. 실패·중단·확인 필요 상태는 자동 재실행하지 않으며 내용 보완 후 다시 검토를 요청한다. 실행 기록에는 요약, 실제 검증 내용, 산출물, 단계별 로그가 남는다. 완료 표시에는 검증 단계와 실제 존재하는 프로젝트 산출물이 필요하다.

## 저장과 복구

`tasks.json`은 등록 원문, `execution.json`은 실행 상태이며 두 파일 모두 Studio/data 아래 Git 제외 영역이다. 모든 변경은 같은 배타 파일 잠금과 원자적 교체를 사용한다. 독립 프로세스 간 중복 claim을 차단하며 화면에 worker token을 노출하지 않는다. 웹 API는 제어만 허용하고 worker의 claim/progress/finish는 파일 명령으로 제한한다. 실행이 중단돼도 원문과 기록을 유지하며 오래된 실행을 자동 덮어쓰지 않는다.

스튜디오 HTTP 서버가 꺼져 있어도 예약 작업자는 파일 대기열을 읽을 수 있다. PC와 Codex 앱은 켜져 있어야 한다. 스튜디오 일시정지는 대기열 실행만 정지하며 Codex 예약 자체를 삭제하거나 중지하지 않는다. 사용량 한도·승인·활성 턴에 따라 검토가 지연될 수 있고 화면은 최근 검토 시각과 지연을 표시한다.

## 검증

- Node 구문 검사 통과.
- 기존 4건과 대기열 5건, 총9개 자동 검사 통과: 입력/문서, 의존성·미래시각·우선순위, 서로 다른 프로세스의 단일 claim, 실행 소유권, 실행 중 편집 차단, 중단·재검토, 완료 증거, HTTP worker 명령 차단과 토큰 비노출.
- 기존 5개 화면의 UI 회귀 통과.
- 실제 Edge 별도 임시 저장소에서 자동 검토 기본값, 미래 시작, 재개, claim 화면 반영, 편집 차단, 중단, 재검토, 검증 완료 열, 결과 내용, 390px 모바일 검사 통과. 이 검증의 실행 단계는 테스트 작업자 시뮬레이션이며 실제 AI 개발 검증과 구분한다.
- 첫 UI 검사의 실패는 클릭 직후 저장 응답을 기다리지 않은 검증 경합이었다. HTTP 응답 완료를 기다리도록 고친 뒤 통과했다.
- 실제 기존 등록 작업 `무기 별 애니메이션 기획 작성`을 같은 대기열로 처리해 작업자 연결과 결과 반영을 추가 확인했다. 최초 실작업은 현재 턴에서 같은 claim/progress/finish 프로토콜로 처리했으며 예약 시각 도래에 의한 기동 테스트와는 구분한다. 5분 예약은 앱 도구의 ACTIVE 응답과 저장된 설정으로 확인했다. 결과는 `Feature/doc/2026-09-28_weapon-animation-plan.md`와 실행 레코드를 참조한다.
- 게임 로직/에셋 변경이 없어 UE 빌드 생략. 커밋·푸시 없음.
