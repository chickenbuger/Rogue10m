# OpenRunMap 플레이 영역 축소

요청 이미지의 자연 절벽 안쪽을 기존 `OpenRunMap`의 플레이 구역으로 확정했다. 보관 후보와 같은 X 5–13, Y 10–14 컴포넌트가 세 마을, 두 동굴, 중앙로와 최종 보스 구역을 포함한다. 남긴 지형은 **1,012.5×562.5m**이고, 기존 1,800×1,800m 지형에서 면적의 **82.4%**를 줄였다.

Unreal의 Landscape Manage/Delete로 외곽 컴포넌트 211개를 제거했다. 렌더와 충돌 컴포넌트는 각각 45개가 남았다. 유지 타일의 합성 높이 해시와 Landscape·편집 레이어 GUID는 작업 전과 같았다. 별도 물리 작업 폴더의 같은 맵 패키지에서 편집했고, 계획과 복구 기준은 [작업 계획](../architect/2026-11-22_openrun-playable-footprint.md)에 남겼다.

첫 자동 입력은 정확한 외곽 211개를 선택했지만 삭제 명령으로 이어지지 않았다. 후보 디스크에 변경이 없음을 확인하고 닫았다. 이어진 실행에서 Unreal 뷰포트의 기본 입력 경로로 삭제한 뒤 유지 타일을 확인하고 지형 패키지 16개를 저장했다.

StartHub 포탈은 원래 설계의 남쪽 입구 S인 `(15000, 32550, 9750)`으로 연결된다. 입구의 시작 대검, 선택 사냥 구역의 기존 스포너 5개, 내비게이션 볼륨과 숨김 충돌 경계를 새 범위에 맞췄다. 절단 외곽에 있던 강·교량·옛 캠프·도로 판·수목 타일과 진입 데칼 등 918개 액터를 Unreal에서 정리했다. 세 마을, 중앙로, 동굴과 보스의 기존 패키지를 보존했다.

독립 재로드에서 Landscape와 충돌 컴포넌트 각각 45개, 제거한 지면의 충돌 조회 211건 중 충돌 0건, Map Check 오류·경고 0건을 확인했다. 유지 영역의 합성 높이 해시가 다시 일치했다. 현재 브랜치의 실제 Unreal Editor에서도 카메라 구체 충돌 48회와 외곽 캡슐 충돌 12회를 검증했다. 세 마을과 중앙로의 지면은 Z=9600cm다.

별도 QA 저장에서 StartHub 포탈 보행·필드 도착 17개 검사, 시작 대검 생성, 최종 보스 타격과 결과 화면·귀환을 포함한 77개 검사, 별도 프로세스의 귀환·세이브 17개 검사를 통과했다. 보스 자동 시나리오는 전투 구역에서 최종 타격을 검증하는 픽스처를 사용했다.

[현재 프로젝트의 에디터 뷰포트](../../DevLog/20261122_OpenRunPlayableFootprint/openrun-trim.png)에서 절벽 밖 지형이 제거된 모습과 세 마을·중앙로의 배치를 확인했다.
