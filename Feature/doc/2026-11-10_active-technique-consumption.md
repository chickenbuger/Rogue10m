# 활성 기술 카탈로그 소비 패치

2026-11-11 재개 확인: 소비 패치는 공유 소스에 이미 반영됐고 CatalogSharedA의 카탈로그/소비/정책3개와 기존성장3개가 모두 Success/경고0/오류0이다. 이전 격리 콘텐츠 부재 실패는 아래의 과거 기록이며 현재 공유 회귀가 실패한 상태로 해석하지 않는다. 실제20개 독립 기술 데이터의 활성화는 별도 미완료다. 이번 재개 작업은 새 격리 사본에서만 수행하며 공유 소스·에셋·에디터·빌드 프로세스는 변경하거나 사용하지 않았다.

## 구현

- 선택 가능 기술 조회를 전체 성장트리 조회와 분리했다. 기존 해금·숙련·패시브 기록과 기본공격은 유지한다.
- 명시 카탈로그가 있으면 전체 검증을 통과한 10개만 장착·바운드 실행·기본 장착·저장 복원에 허용한다. 마지막 항목만 잘못돼도 정상 앞 항목을 부분 공개하지 않는다. 빈 카탈로그는 기존 선택 정책을 유지한다.
- 공용4/동시1/차징1의 기존 6칸과 정책 검사를 유지한다. 뉴비는 선택 기술이 없고 Staff 빈 카탈로그는 기존 입력을 보존한다. 새 마법사 입력·밸런스는 추가하지 않는다.
- 무기교체 중 나가는 무기의 프리셋은 AppliedProfileWeaponType, 저장된 비활성 프리셋은 해당 무기 프로필로 검사한다. 현재 무기만 사용해 다른 무기의 선택을 삭제하지 않는다.
- Hybrid/기존 UI의 드래그와 QER 선택기를 같은 장착 정책에 연결했다. 성장 노드 자체는 숨기지 않는다.

## 검증 범위

새 CatalogConsumption 자동검사는 콘텐츠 없는 구체 native 테스트 캐릭터와 임시 DataAsset으로 실제 Combat 소비 경로를 확인한다. 전체13노드/선택10개, 학습과 선택 분리, 여섯 슬롯, 범위 밖 기본바인딩/장착/실행 차단, 잘못된 카탈로그의 전체 차단, 양무기 프리셋, 비활성 프리셋 변조, 복원 거절 후 전체 snapshot 보존, 기본공격·패시브·뉴비·Staff 예외를 검사한다.

Scripts/VerifyCatalogConsumption.ps1는 카탈로그1/소비1/정책1의 핵심3개를 엄격한 개수로 확인한다. -IncludeGrowth는 실제 콘텐츠가 있는 통합 환경에서 기존성장3개를 추가한다. 2026-11-11 격리 후속에서는 -PreflightOnly와 성장 에셋/DLL 선행검사를 구현해 엔진 실행 전에 환경 누락을 보고한다. 실제 UI 인스턴스·물리입력·실제 세이브 재시작·풀런·모션/VFX 시각검수는 이 검사에 포함하지 않는다.

과거 격리 검증: tmp/CatalogPatch20261110/Delivery/VALIDATION.md의 CatalogElevC 핵심3개는 clean 성공이었다. 당시 기존성장 검사는 실제 ChargedShockwave 에셋 부재로 실패1/외부 HTTP 경고 포함 성공1/clean 성공1이었다. 이후 실제 콘텐츠가 있는 Feature/doc/evidence/catalog-consumption-20261110/CatalogSharedA/{Catalog,Consumption,Policy,Growth}/report/index.json과 summary.json에서 전체6개 clean 성공을 확인했다. 이 후속 성공 기록과 과거 실패를 함께 보존한다. 이번 재개에서는 엔진·빌드를 재실행하지 않았으며 runner의 새 사전검사7개를 별도로 검증했다.

## 통합과 실제 데이터 후속

이전 source.patch는 현재 공유 소스에 reverse-check가 성공한다. 중복 적용하지 않는다. 이번 격리 후속의 runner·테스트·문서 변경만 별도 패치와 기준 해시를 검토한 후 담당자가 통합한다. C++ 소비 코드와 공유 에셋은 이번 변경에 포함하지 않는다.

실제 에셋을 명시 목록에 넣기 전 기본공격과 독립된 10개 기술, 명시 AllowedSlotPolicy와 안정 ID를 확정하고 현재 저장의 장착 참조를 점검해야 한다. 이전 장착기술이 새 카탈로그 밖이면 Restore는 원자적으로 거절한다. 저장 이관 없이 기존 프로필에 카탈로그를 활성화했다고 완료 보고하면 안 된다. K01/기본공격 분리·K10과 대검 신규5개의 독립 콘텐츠·기존 전용정책 재연결은 아직 남았다.
