# 기본 격투가 동작 자연스러움 개선 설계

- 날짜: 2026-09-10
- 작업 브랜치: Sprint#4-26-natural-brawler-motion
- 엔진: Unreal Engine 5.8.2
- 상태: 기획 확정, 구현·실게임 검증 예정
- 선행 기능: Sprint 4-25 기본 Unarmed 좌우 연타·차징 어퍼컷·일반 점프

## Scope Gate

사용자는 기존 구현에 더 자연스러운 움직임을 요구했고 computer-use 플러그인으로 직접 YouTube 링크를 확인하도록 지정했다. 이번 작업은 기존 입력과 타격 규칙을 유지하면서 실제 손·상체·머리와 표시용 카메라의 시간 관계 및 복귀 궤적을 개선한다. 기본 Unarmed 분기에만 적용하고 Knuckle/StoneFist의 소스 포즈, HUD, 자산, 공격력·비용·연계 규칙을 변경하지 않는다. C++ 수정이 있으므로 Editor 빌드와 실제 플레이 검증이 필요하다.

기획 1, 개발 2, 검증 2 역할로 진행한다. 동시 실행 슬롯에 맞춰 기획 담당은 계획 작성 후 독립 소스 검증으로 전환하며, 별도 시각 검증 담당은 결과가 준비되면 실행한다. 개발 1은 FistAnimInstance, 개발 2는 FirstPersonPresentationComponent의 기본 Unarmed 카메라 추종을 소유한다. 기존 CameraManager는 표시용 POV 호출 경계를 유지한다. 통합 담당은 빌드, 런타임 검증, 결과 문서와 DevLog/SprintChangeLog를 소유한다.

## 현재 부자연스러움의 코드 근거

현재 EvaluateBasicPose는 왼손·오른손에 단일 AttackEnvelope를 사용한다. 가드와 타격 목표를 직선 보간하고 같은 선으로 돌아온다. 몸·머리·이동량도 동일한 Extension을 곱하므로 운동이 한 덩어리처럼 동시에 시작하고 멈춘다. 어퍼컷은 전체 재생 시간의 38% 동안 Loaded에서 Apex로 올라가고 나머지 구간에서 그대로 가드로 돌아오므로 짧은 가속과 팔꿈치 회수의 구분이 약하다.

손에는 28/s, 몸·머리에는 같은 18/s의 지수 보간을 적용한다. 이는 불연속을 줄이지만 타격 리듬 자체를 설계하지 않는다. 차징 진입은 손 35%, 몸 45%의 준비 목표부터 시작하므로 짧은 tap과 연계 전이에서 큰 목표 변경이 발생한다. 현재 프레임의 손을 새 동작 시작점으로 사용해 전이를 이어야 한다.

이 분석은 소스와 기존 검증 자료에 근거한다. 외부 영상 관찰 결과로 표현하지 않는다.

## 확정 표현 계약

| 구간 | 손·팔 | 몸·머리 | 카메라 |
| --- | --- | --- | --- |
| 왼 잽 준비 | 현재 가드에서 짧게 힘을 싣는다. 오른손은 가드 유지 | 상체가 손 신전보다 약간 먼저 반응 | 실제 머리 변화를 제한된 범위로 추종 |
| 왼 잽 방출 | 타격 직전 짧은 구간에 빠르게 전진 | 왼어깨 전진·몸통 회전 뒤 머리가 약간 후행 | 손과 동떨어진 늦은 흔들림을 만들지 않음 |
| 오른 스트레이트 | 왼손 회수 중 현재 포즈에서 오른손 신전 시작 | 반대 방향 몸통 회전으로 2타 연결 | 축별 연속성 유지 |
| 타격 이후 | 팔꿈치를 먼저 접고 바깥·아래 호를 거쳐 가드 복귀 | 작은 후속 움직임 뒤 안정 | 오래 진동하지 않고 부드럽게 정지 |
| RMB 차징 | 오른손을 낮추는 준비 자세로 연속 진입 | 오른쪽 상체 회전, 머리는 작은 변화로 전방 유지 | 실제 조준 방향을 돌리지 않음 |
| RMB release | 낮은 준비 자세에서 짧게 가속해 상승, 이후 접어서 회수 | 몸통 풀림이 먼저 시작하고 머리가 뒤따름 | 상승과 흡수를 머리 움직임에서 유도 |
| 점프 | 기존 이륙·공중·착지 자세 유지 | 실제 운동 상태만 반영 | 기본 추종 개선을 통해 착지 복귀도 연속 처리 |

초기 설계에서는 타격 시점을 보존했으나 실제 연속 영상 QA에서 어퍼컷의 release 후 준비가 길게 느껴지는 문제를 확인했다. 최종 수정은 기본·강화 어퍼컷 두 자산의 AnimationPlayRate를 1.5로 올려 포즈와 타격을 함께 당긴다. 현재 주먹 첫 피해는 자산 기준 0.34초, 어퍼컷은 0.633초이며 공격 속도와 AnimationPlayRate로 보정된다. 공속 1의 실제 어퍼컷 피해는 release 후 약 0.422초다. LMB 연계창은 변경하지 않는다. 연계창은 0.40~0.55초다. 손의 접촉에 가까운 구간이 이 실제 지연 피해 시점과 대응해야 한다. 정규화된 포즈 정점 0.34/0.38만으로 일치를 단정하지 않고 현재 몽타주 길이와 런타임 타임스탬프로 검증한다.

초기 표현 튜닝은 마지막 약 0.12초의 빠른 신전, 약 0.26~0.34초의 접기·회수, 손보다 약 0.04초 빠른 몸통과 약 0.035초 늦은 머리 반응으로 시작한다. 이는 실게임 확인 전의 초기값이며 고정된 외부 영상 계측값이 아니다. 공속이 바뀌면 전체 재생과 함께 비례해야 하며, 유효 구간 길이는 제한한다.

## 구현 경계와 불변 조건

- 새로운 공격 accepted serial에서 현재 양손 위치를 보존해 다음 동작의 시작점으로 사용한다. 거절된 입력은 포즈 단계를 진행시키지 않는다.
- 차징과 공격 취소는 기존 입력 컴포넌트가 소유한다. 표현 개선을 위해 새 피해·입력 타이머를 만들지 않는다.
- 팔 도달 거리는 실제 상완·하완 길이 합의 94% 이내다. 기존 어퍼컷 높이 164cm, 준비 손 노출과 목 숨김을 보존하며 뒤틀림을 키우는 목표를 추가하지 않는다.
- 닫힌 주먹과 해부학적 엄지·손목 방향 계산을 유지한다. 궤적 변화 때문에 손 회전을 임의로 좌우 반전하지 않는다.
- 몸과 머리의 위상을 분리하되 실제 평가된 머리 delta를 카메라 입력으로 유지한다. 별도의 임의 흔들림을 중복 합산하지 않는다.
- CameraComponent와 ControlRotation은 타격 판정의 기준이므로 불변이다. 최종 표시 POV만 바뀐다.
- 카메라는 기본 Unarmed에서 임계 감쇠 응답을 사용하고 기존 오프셋·회전 상한을 유지한다. 프레임 간격 변화에 안정적인 적분 또는 해석적 응답을 사용한다.
- pose 머리 지연과 카메라 필터 지연의 합을 실제 영상에서 확인한다. 머리와 POV가 손 이후에 오래 흔들리면 강도 증가 대신 지연을 줄인다.
- 자연스러운 idle 복귀는 목표 0으로 감쇠한다. 사망·무기 변경·효과 강도 0·뷰 대상 변경 등 명시적 비활성은 잔여 위치·회전과 속도 상태까지 정리한다.
- 게임 스레드에서 UObject 상태를 snapshot으로 복사하고 포즈 worker는 값만 사용한다. 새 튜닝은 UPROPERTY로 노출한다.

## 완료 판정과 레퍼런스 한계

숫자상 손 이동량이나 카메라 변화가 0보다 크다는 사실만으로 자연스러움을 판정하지 않는다. 준비와 방출의 속도 차이, 접기·회수의 다른 궤적, 몸과 머리의 짧은 위상 차이, 오른손으로 이어지는 전환, 완충 및 tap release의 연속성, 착지 후 안정화가 연속 프레임에서 보여야 한다. 타격 로그와 손 정점 시각을 대조하며 손이 복귀한 뒤 피해가 발생하는 어긋남을 허용하지 않는다.

사용자 영상은 https://www.youtube.com/shorts/cci0hNBFiZI 및 https://www.youtube.com/shorts/M_4S6WFM-wM 이다. 이번 기획 시점에 지정 computer-use 초기화가 Windows sandbox ACL 오류로 실패해 실제 영상 프레임을 아직 보지 못했다. 도구 복구 후 시청 결과만 외부 레퍼런스 관찰로 추가한다. 접근 실패를 이유로 기존 구현의 개선을 중단하지 않으며, 원본과 동일하게 재현했다고 주장하지 않는다.


## 구현 단계 검토 기록

2026-09-10 검증 1에서 개발 1·2의 변경을 tmp/natural-brawler에 보존된 작업 시작본과 대조했다. 카메라 구현의 실제 소유 영역은 Components/Rogue10mFirstPersonPresentationComponent.h/.cpp이며 CameraManager의 기존 호출·뷰 대상 정리 경계는 변경하지 않았다.

최종 초기 코드값은 공격 재생 시간의 비율이다. 방출 0.14, 회수 0.30, 몸 선행 0.04, 머리 후행 0.035를 사용한다. 현재 기본 자산의 길이가 잽·스트레이트 1.0초, 어퍼컷 1.6667초이므로 공속 1에서 방출은 각각 약 0.14초와 0.233초, 회수는 약 0.30초와 0.50초다. 위 설계의 초 단위 초기 예상과 구분하며 실제 사용자 체감은 연속 영상으로 판정한다.

현재 자산 길이에서 손 정점 0.34/0.38은 첫 피해 0.34/0.633초와 대응하며 모두 공격 속도×재생 속도의 역수로 조정된다. 입력·피해 지연 값은 이번 표현 수정으로 바꾸지 않았다. 0.08~0.22 방출 비율, 0.20~0.45 회수 비율, 최대 0.08 몸/머리 위상 제한을 코드에서 적용해 분모와 준비 구간이 양수가 되도록 유지한다.

카메라의 해석적 임계감쇠 계산, 100ms 프레임 간격 제한, 축별/거리 상한, 제한 바깥으로 나가는 속도 제거, 0 설정·사망·무기/뷰 변경의 잔여 속도 초기화를 확인했다. 기본 Unarmed의 자연 복귀만 0 목표로 감쇠하고 기존 Knuckle 응답은 유지한다. 소스 검토에서 즉시 수정이 필요한 중대·중간 결함은 발견하지 못했다. 빌드·런타임·시각 결과는 통합 결과 문서에 별도로 기록한다.

정규화된 시간으로 포즈와 피해는 함께 빨라지지만 고공속과 낮은 프레임 속도의 조합에서는 짧은 방출 구간의 일부가 렌더 프레임 사이에 놓일 수 있다. 기본 스폰 30Hz 검증만으로 모든 공속·프레임 조합의 자연스러움을 보장하지 않는다.


## 시각 QA 후 어퍼컷 속도 수정

실게임 연속 프레임에서 어퍼컷 release 후 0.633초 동안 준비하는 구간이 길게 느껴졌다. 이를 개선하기 위해 전용 RightUppercut와 ChargedRightUppercut 자산의 AnimationPlayRate만 1.5로 조정한다. LeftJab와 RightStraight는 1.0, 강화 문턱 0.85초, 피해·자원 비용·쿨다운·사거리와 LMB 연계창은 유지한다. 이 수정은 자연스러운 동작 요구에 대한 후속 튜닝으로 P2의 명시 자산 영역에 두 어퍼컷 재생 속도와 Scripts/Editor/ConfigureBasicBrawler.py를 추가한다. rollback은 두 자산의 재생 속도 1.0 및 스크립트 대응 값으로 한정한다.

ConfigureBasicBrawler.py는 두 어퍼컷만 1.5를 설정하고 검증하며 기존 몽타주나 원본 Unarmed 자산을 수정하지 않는다. 전용 4개와 프로필을 저장하는 기존 스크립트 경계를 유지하므로 실제 변경 자산 목록은 별도 SHA256 대조로 확인한다. 스크립트의 charge_seconds 검증은 양수만 확인하므로 0.85초 보존은 Editor 실제 값 기록으로 추가 확인해야 한다.

검증 1에서 Combat의 지연 피해와 BasicBrawler snapshot의 AttackDuration이 동일한 공격 속도×AnimationPlayRate로 나눠지는 것을 확인했다. 따라서 기본 공속 1에서 어퍼컷 전체 재생은 약 1.111초, 손·타격 정점은 약 0.422초, 방출 구간은 약 0.156초, 회수는 약 0.333초가 된다. 기본·강화의 준비 시간을 같이 줄이되 완충 대기와 release 입력 의미는 바뀌지 않는다. 피해를 시각 포즈와 별개로 앞당기는 타이머 수정은 하지 않는다.

소스·스크립트 계약에서 이번 수정으로 타격 시점과 포즈 정점이 어긋나는 결함은 발견하지 못했다. 기존 쿨다운 수치가 같아도 첫 피해가 더 빨라지는 플레이 변화는 있으므로 결과 문서에 실제 release→hit 변경을 명시한다. Editor 저장 성공, 차징 0.85초 보존, 실게임 tap·충전 피해 시각 일치와 부드러운 회수는 최종 런타임 및 시각 QA로 확인한다.
