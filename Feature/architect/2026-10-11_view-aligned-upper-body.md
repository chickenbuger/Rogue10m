# 플레이어 시선에 맞추는 상체 애니메이션

- 날짜: 2026-10-11
- 작업: Sprint#5-29, 시선에 맞춘 상체 포즈
- 요청: 현재 외형 메시의 상체와 팔 애니메이션이 플레이어가 보는 위아래 방향으로 진행되도록 한다.
- 기존 작업 보존: 이동 공격 상체 합성, 제자리 전신 공격, 가드, 실제 외형 리타깃, 머리 카메라, V키 검사 시점과 손바닥 보행 보정을 유지한다.

## Scope Gate

현재 `ABP_Common_Unarmed`는 숨겨진 Manny 소스를 평가하고 외형 메시가 이를 리타깃한다. 이동 공격은 FootIK·가드 이후 보행 캐시와 기존 DefaultSlot 몽타주 캐시를 합성하고, 최종 TwoWayBlend가 전신/상체 공격을 선택한다. 이전 `Rogue10mFistAnimInstance`의 조준 보정은 비활성 First Person Mesh 경로이므로 현재 외형에 영향을 주지 않는다.

카메라는 외형 머리의 실제 위치와 원본 머리 회전을 읽고, 회전 안정화를 거친 애니메이션 움직임에 ControlRotation을 곱한다. 상체의 조준 회전을 머리가 그대로 상속하면 마우스 pitch가 카메라에 다시 합성된다. 따라서 몸에 시선을 적용하되 원래 포즈의 머리 component 회전은 보존한다. 머리 위치와 목·몸의 로컬 위치·스케일은 강제로 고정하지 않는다.

이번 변경은 C++ 런타임·집중 QA·문서다. Animation Blueprint 그래프, 원본 시퀀스, 몽타주, 공격 Data Asset, 피해 타이밍, HUD와 레벨은 수정하지 않는다. 새 Actor Tick이나 매 프레임 동기 에셋 로딩은 추가하지 않는다. 커밋·푸시는 별도 사용자 지시가 있을 때 진행한다.

## 설계

`URogue10mFighterCombatStanceAnimInstance`의 native `FAnimInstanceProxy`에 최종 포즈 보정을 추가한다. `Evaluate_WithRoot`에서 실제 `GetRootNode()`에 대해서만 `EvaluateAnimationNode_WithRoot`로 기존 그래프를 정확히 한 번 평가하고, 결과의 상체 회전을 보정한다. `EvaluateAnimation_WithRoot`를 호출하면 같은 override로 재귀하므로 사용하지 않는다. 연결 애니메이션 레이어 등 다른 root는 기본 평가에 맡긴다.

게임 스레드의 `PreUpdate`에서 소유 캐릭터 유효성, 컨트롤 조준 pitch, 실제 소스 메시 회전, 캐릭터 오른쪽 축과 조정값을 값 타입으로 복사한다. 워커 평가에서는 UObject, 컨트롤러, 월드에 접근하지 않는다. 포즈의 bone container가 제공하는 compact 인덱스를 이용하고, 누락 본이나 유효하지 않은 입력은 안전하게 보정을 생략한다. 고정 skeletal 인덱스나 이전 LOD 인덱스를 재사용하지 않는다.

pitch는 플레이어와 몸의 상대 pitch를 정규화하고 기본 ±75도 한계 내에서 처리한다. yaw는 현재 캐릭터가 마우스 방향을 따라 회전하는 기존 입력 경로를 유지하며, 몸과 컨트롤 시선 사이에 남은 각도만 기본 ±45도 내에서 상체에 적용한다. 실제 캐릭터 오른쪽·위쪽 축을 source mesh component 좌표로 변환해 회전하므로, 수입한 복싱 포즈의 root 회전이나 Manny의 +Y 전방을 조준 축으로 오인하지 않는다. Unreal의 양의 pitch가 위를 바라보도록 축 회전 부호도 확인한다. 기본 시선의 -20도도 동일하게 적용하고, 갑작스러운 시선 변화는 snapshot의 제한된 평활화로 연결한다.

상체 보정은 척추 25%와 양쪽 upperarm 75%에 회전량을 나누어 적용한다. 기본 척추 분배는 `spine_01/02/03`에 5%/8%/12%이며, 필요한 본 개수 변화에도 전체 상체 회전량이 잘못 증폭되지 않게 처리한다. 쇄골의 원래 자세와 로컬 translation·scale은 바꾸지 않고 원래 팔꿈치·손목·손가락 회전은 유지한다. pelvis, root, 다리·발·발 IK는 수정하지 않는다. 조준 후 머리의 원래 component 회전을 부모 역회전으로 복원하고 FK 손의 최종 component 포즈와 손 IK 목표를 맞춘다. 보정은 매번 원래 그래프 결과에서 계산하므로 프레임 누적이나 반복 평가로 자세가 더 꺾이지 않는다.

범위는 현재 플레이어 Common source 애니메이션의 idle·가드·지상 공격·이동 공격과 유효한 시선 상태다. 사망·컨트롤러 부재·차단 UI 등 게임플레이 불가 상태의 적용 정책을 명시하고 QA한다. 회피·점프 등 전신 동작은 과도한 척추 꺾임을 피하는 정책을 구현 단계에서 확인한다. 기존 시야각·머리 카메라 안정화 수치는 변경하지 않는다.

## 수락 기준과 독립 검증

1. 생산 source와 실제 외형 모두 위·정면·아래 조준에서 상체/타격손 방향이 바뀐다. actor yaw가 90도인 경우에도 월드 오른쪽 축을 기준으로 같은 결과가 나온다. 원본 보정 비활성 대조가 방향 변화를 따라가지 못하는 것도 확인한다.
2. 같은 프레임 원본 그래프 대조와 root·pelvis·다리·발 component 포즈가 허용 오차 내에서 일치한다. 로컬 translation/scale, 팔 길이, 손목·손가락 상대 자세의 보존을 별도로 확인한다. IK 목표는 수정된 FK 손과 일치한다.
3. 조준 전후 머리 component 회전 차이는 허용 오차 이내다. 머리 위치 변화는 관측한다. 실제 카메라와 독립 카메라 계산을 비교해 ControlRotation이 두 번 더해지지 않는지 검사한다. 검사 V키 POV와 전투 판정 카메라를 구별한다.
4. 맨손/너클의 실제 좌클릭 콤보, 우클릭 스트레이트·차징 훅, 이동 공격·정지 복귀에서 포즈 보정이 최종 슬롯에 적용되고 피해·입력·보행이 유지된다. 급격한 시선 변화·극단 pitch·입력 NaN/유효하지 않은 문맥은 비정상 quaternion이나 뼈 뒤집힘을 만들지 않는다.
5. 기존 가드·보행·카메라 계약을 관련 회귀 fixture로 확인하고 실제 1인칭/3인칭 렌더를 육안 확인한다. 기존 회귀가 중립 조준 포즈를 전제로 한다면 변경한 기대값의 근거를 기록하고 하체·판정 검사 자체는 유지한다.
6. Editor 빌드와 집중 QA 통과, 생성 파일 검사, 콘텐츠 사전/사후 해시 비교로 이번 작업의 에셋 변경 0을 확인한다. 실제 관측 범위 밖의 모든 공격/종족/모드까지 검증했다고 주장하지 않는다.

## 주요 위험

- source와 리타깃 머리 회전이 같게 보존되더라도 외형의 목 체인·손 체인 설정에 따라 작은 위치 차이가 생길 수 있다. 실제 외형에서 확인해야 한다.
- 과도한 pitch를 척추 전체에 적용하면 머리 위치와 카메라 이동이 커진다. 척추/upperarm 분배와 clamp로 제한하고 수치를 기록한다.
- 병렬 평가나 연결 레이어에서 보정을 두 번 적용하면 자세·카메라가 누적된다. 실제 root gating과 순수 입력 snapshot을 리뷰한다.
- 기존 QA와 미커밋 작업이 많다. Git HEAD로 복원하지 않고 시작 상태의 좁은 checkpoint만 사용한다.
