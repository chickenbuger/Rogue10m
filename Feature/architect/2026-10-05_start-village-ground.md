# 시작마을 바닥 텍스처 개선 계획

`Sprint#5-12-start-village-ground`에서 StartHub의 잔디·흙길·광장 바닥을 개선한다. 기존 생성기는65회/6회 반복을 요청하지만 부모 머티리얼에 반복 파라미터가 없어 적용하지 않았다. 120m 바닥과 비균일하게 늘린 길의 UV가 원본 텍스처를 크게 늘리는 것이 확인된 원인이다.

범위는 마을 전용 머티리얼과 바닥 슬롯, 생성기의 재현성 보강이다. 원본 구매/StarterContent 재질·텍스처, 액터 배치·충돌·포탈과 OpenRunMap을 보존한다. 그래픽 전역 설정은 변경하지 않는다. C++·Build.cs 변경이 없어 Editor 타깃 재빌드는 필요하지 않다.

1. Architect: 공식 MCP로 StartHub를 열고 플레이어 높이의 수정 전 화면, 실제 부모/파라미터·텍스처 크기·바닥 상태·Content 기준선을 조사한다.
2. Implementer: 마을 전용 World XY 좌표 기반 재질을 작성한다. 원본 텍스처를 참조하고 `TileSizeCm`으로 물리적 반복 크기를 지정한다. 잔디·흙길은 기존 전용 인스턴스에 적용하고 광장/바닥 패드에는 전용 돌 인스턴스를 연결한다. 전체 마을 생성기를 실행하지 않는다.
3. Builder/Reviewer: 머티리얼 컴파일 결과, 같은 카메라의 전후 화면, 지형 크기·충돌·포탈 보존과 저장/재로드를 확인한다. 동서/남북 길의 동일한 질감 크기를 점검한다. 역할 분담 검토와 AST·diff·하네스 검사를 수행한다.
4. Doc Writer: 결과 문서·한국어 DevLog·SprintChangeLog에 실제 검증과 변경 범위를 기록한다. 커밋·푸시는 하지 않는다.

되돌릴 경계는 기존 전용 잔디/흙 인스턴스의 부모·값, 광장과 준비 구역 바닥 슬롯, 신규 전용 재질, 생성기의 재사용 보호 수정이다. 미저장 외부 액터 패키지는 `modify()`로 변경 표시한 뒤 현재 레벨에서 저장한다. 저장 성공 반환뿐 아니라 맵 해제·재로드의 연결값을 완료 조건으로 사용한다.
