## 근거와 한계

사용자는 UI의 크기와 구조가 무너졌다고 보고했다. 이번 진단은 현재 소스·생성 스크립트·과거 캡처의 조사 결과다. 최신 PIE에서 문제를 재현하거나 화면을 실측한 결과는 아니다.

Saved/ClassBottomHUDPreview는 PNG와 UMG 좌표를 합성한 과거 프리뷰다. Saved/Screenshots/WindowsEditor/MartialArtistSkillTree.png는 과거 실제 게임 스킬창 캡처다. 전자는 런타임 UI 정상 여부의 증거로 사용할 수 없다.

## 디자인 방향

로스트아크 느낌은 하단 중앙 정보 집중, 얇은 금속 테두리, 어두운 반투명 바탕, 선명한 아이콘과 직업 문장으로 표현한다. Rogue10m의 1인칭 카메라와 기존 입력 구조에 맞춘다. 큰 날개·두꺼운 석조 외곽·전체 폭 불투명 장식은 줄인다.

공식 로스트아크 접근성 안내는 HUD 글자 배율과 UI 노출 조절을 제공한다. 이 프로젝트에도 글자 크기와 주변 정보 노출을 조절하는 방향을 제안한다. 아래 제안 수치는 로스트아크 실측치가 아니다.

## 1920×1080 기준 제안 규격

모든 좌표는 100% 디자인 기준이다. 실제 적용 크기는 DPI와 사용자 배율을 반영한 최종 화면 픽셀로 검증한다. 생성 이미지의 픽셀을 규격으로 사용하지 않는다.

| 요소 | 제안 크기/위치 | 표시 원칙 |
| --- | --- | --- |
| 하단 전투 코어 | 1000×160, x460 y896, 화면 아래 여백24 | 중앙 anchor와 alignment. 모든 직업 동일 geometry |
| 체력·현재 자원 | 각각 약 352×20, 코어 상단 | 수치와 막대 함께 표시. HP 적색, MP 청색, 스태미나 황금색 |
| 행동 슬롯 | 56×56 ×5, 간격8 | 좌클릭·우클릭·좌 차징·우 차징·E 회피 순서 |
| 중앙 아이덴티티 | 76×76 | 직업 문장·진행도. 확인되지 않은 Z/X 키 추가 금지 |
| 아이템 표시 | 48×48 ×4, 간격8 | 현재 View에 맞춰 잠금/미연결 상태. 사용 가능한 물약처럼 그리지 않음 |
| 레벨 | 코어 아래쪽 작은 LV 표시 | 경험치 숫자는 상세/포커스 상태로 이동 제안 |
| 경험치 | 화면 끝 4px 선 | 장식 패널 없이 전체 폭. 입력 차단하지 않음 |
| 대상 정보 | 약 520×52, 상단 중앙 | 대상 없음은 숨김. 이름·체력 우선, 상태 보조 |
| 타이머 | 상단 우측 | 런 남은 시간. 시안 숫자는 예시 |
| 시스템 로그 | 좌하단 최대2줄, 코어 상단보다 위 | 1080p x24 y816 시작 제안. 작은 화면에서는 접힘/최근1줄 |
| 획득 알림 | 우측 중하단 최대3건 | 시간 경과 소멸, 중앙 조준 영역 침범 금지 |

코어 내부 두 그룹은 동일한 폭의 열에 넣고 중앙 문장을 화면 중심에 고정한다. 오른쪽이 4칸이어도 임의의 다섯 번째 기능 슬롯을 추가하지 않는다. 긴 입력명은 마우스 기호+차징 표시 및 상세 툴팁으로 처리한다. 핵심 수치는 20px 전후, 한글 본문 16~18px를 출발점으로 한다.

### 개념 배치

```text
                 대상 이름 / 체력                         남은 시간

                        중앙 전투 시야

                                                        획득 알림
  시스템 로그
                   HP                        MP / 스태미나
          [좌][우][좌차징][우차징][E] [직업 문장] [잠금][잠금][잠금][잠금]
                   LV
  ───────────────────────── 경험치 4px ─────────────────────────
```

## 기능 정합성

- 공격 4칸 + E 회피 1칸은 현재 코드 기준이다. 로스트아크의 8개 스킬 체계로 변경하지 않는다.
- 공격 4칸은 같은 공격 쿨다운 값을 받는다. 독립 쿨다운을 구현된 것처럼 표시하지 않는다.
- 캐릭터에 1~5 소모품 입력 바인딩은 있으나 HUD 아이템 getter는 잠긴 4칸을 반환한다. 사용 입력과 표시 연결은 별도 해결 항목이다.
- 미니맵은 Main HUD에서 의도적으로 비활성이다. 이번 필수 HUD에 넣지 않는다.
- I/P/K 메뉴 입력은 존재하지만 HUD 안내는 숨겨져 있다. 메뉴 안내 추가는 신규 노출 제안이다.
- 테마는 문장·선·재질만 변경한다. HP와 슬롯 위치, 기능 색상은 고정한다.
- 마법사 청보라/은, 전사 적금/흑철, 권사 비취/청동, 도적 녹색/은을 제안한다.
- 생성 그림의 적, 던전, 스킬명, 수치, 로그는 예시다. 실제 콘텐츠 제작·데이터 변경을 의미하지 않는다.

## 해상도 정책 및 구현 방향

현재 BottomHUD 단일 소유권과 MainHUD의 View 전달 구조는 유지한다. 장식과 실제 콘텐츠를 같은 중앙 레이아웃 아래 구성한다. 전체 폭 XP와 모서리 정보는 독립 배치한다. 가로 폭이 늘어도 전투 코어를 잡아 늘리지 않는다.

DPI 및 사용자 배율 적용은 한 지점에서 관리한다. 작은 화면에서 전체 텍스트를 무조건 비례 축소하지 않고 주변 로그 축약과 패널 여백 축소를 우선한다. 720p에서는 최종 화면상 본문14px·키16px·핵심수치18px 이상을 목표로 별도 compact 프리셋을 검증한다. 100%와 110% 사용자 배율에서 화면을 벗어나지 않도록 한다. 이 값은 설계 목표이며 아직 검증된 설정이 아니다.

공통 슬롯 크기와 padding은 프리뷰/런타임 생성에서 동일하게 적용한다. 고빈도 갱신은 기존 View 경로를 유지하고 Tick이나 매 프레임 위젯 재생성을 추가하지 않는다. UObject 참조, UPROPERTY, C++ 로직 소유 규칙은 AGENTS.md를 따른다. 바이너리 수정은 Unreal Editor에서만 진행한다.

## 구현 완료 기준 — 이번에 통과한 것으로 해석하지 말 것

- 1280×720, 1920×1080, 2560×1440, 3440×1440 및 100%/110% 배율에서 실제 PIE 캡처.
- HUD 중심 오차2px 이내, 슬롯/라벨/패널 겹침과 화면 밖 잘림0건.
- 생성 이미지, 좌표 설계, Designer 프리뷰, 실제 PIE 증거를 각각 구분.
- 4직업 전환, 자원0, HP 저하, 대상 없음, 긴 한글 이름/콤보명, 잠금, 쿨다운, 연속 알림 검사.
- 인벤토리·장비·스킬창과 툴팁/드래그 영역 충돌 검사.
- 21:9에서 문장·아이콘 비율 유지, 720p에서 최소 글자 크기 충족.
- 구현 시 Widget Blueprint/Editor 빌드와 기존 전투 입력·갱신 검증 통과.
