# 맨손·너클 전용 애니메이션 제작과 1인칭 시야 개선

작성: 2026-09-29 / 작업 브랜치: Sprint#5-1-unarmed-knuckle-animation
기준 커밋: b7ab6b6 / 역할: 기획1

## 목표

무기별 기획서의 맨손·너클 항목을 실제 전용 파생 애니메이션과 게임 연결로 제작한다. 맨손은 빠르고 자연스러운 좌우 잽·스트레이트·훅, 너클은 짧고 묵직한3타·어퍼컷·차징 강타로 구분한다. Appearance 전신의 동작, 머리에 연결된 카메라, V 관찰, 머리를 포함한 전신 그림자를 함께 유지한다.

사용자의 최신 요청은1인칭 머리 흔들림을 줄이고 시선을 조금 더 정면으로 조정하는 것이다. 이전 기획의 카메라 변경 제외 조건보다 이번 요청을 우선한다. 다만 손발 본의 오류를 카메라 조절로 가리는 것은 완료로 인정하지 않는다. 본·리타깃 정상 검증과 시야 편안함 검증을 분리한다.

## 확인한 기준선

- `Docs/LazyCodexHarness.md`의 ULW 역할 분리와 검증·기록·종료 기준을 적용한다.
- 기준 기획: `Feature/architect/2026-09-28_weapon-animation-plan.md`. 해당 문서의 동작 길이 범위는 제안이며 이번에 피해 타이밍을 바꾸는 허가가 아니다.
- Unarmed는 `Rogue10mBasicBrawlerComponent` 전용 입력이다. 좌클릭은 왼잽→오른잽, 우클릭을 놓는 시점에 짧으면 Special 스트레이트, 완충이면 ChargedSpecial 훅이다.
- Knuckle의 ClassCombat 생성기에는 Primary01→02→03, Special, ChargedPrimary 구성이 있으나 실제 게임은 MartialArts progression 경로를 사용하므로 활성 DA·프로필·해금 연결을 Editor 감사로 확정한다. 생성기 목록만 보고 다른 DA를 바꾸지 않는다. 현재 해금과 입력은 유지하며 맨손 전용 우클릭 홀드 입력으로 바꾸지 않는다. 기획상의3타·어퍼컷·강타를 실제 활성 슬롯에 연결한다.
- 현재 최초 시선은 `InitialFullBodyViewPitch=-30°`이고, Appearance raw head motion을 카메라에 직접 반영한다. 최초 시선은 한 번만 적용하며 사용자의 이후 마우스 회전을 덮어쓰지 않는다.
- 이전 안정화는 실제 root 분리, Source FootIK→DefaultSlot, Appearance 추가 IK 비활성, 오른잽 하체 보존·손 IK 정렬을 확립했다. 이전 Human Male 훅에는 머리57.771°/frame·오른손130.522°/frame의 원본 큰 회전이 남았다. 이번 제작의 개선 대상이며 이를 정상적인 최종 연출로 자동 승인하지 않는다.

## 자산과 코드 경계

1. 원본 FBX·Preview·Manny 공용 클립·공용 몽타주를 보존한다. 이번 두 무기의 전용 폴더에 파생 Sequence/Montage를 만들고 생성·검증 스크립트를 남긴다. 기존 파생본을 덮을 필요가 있으면 원본 해시와 복구본을 먼저 확보한다.
2. 모든 `.uasset` 생성·변경·저장은 Unreal Editor API로 수행한다. 런타임은 기존 Source→Appearance ABP와 montage 경로를 사용한다. 별도 FP Mesh/FP AnimInstance를 재활성화하지 않는다.
3. 입력 슬롯, 콤보 순서·창, damage, range/shape, resource costs, hit count/interval/max-per-target, charge duration, cooldown, AnimationPlayRate, HitStartDelaySeconds를 적용 전후 비교한다. 이번에는 gameplay 필드와 공격속도 배율을 보존한다. 다만 기존 HitStartDelaySeconds가0이라 즉시 피해와 눈에 보이는 접촉을 맞출 수 없는 경우에만, 접촉에 필요한 최소 지연 보정을 허용한다. 변경 대상 DA·기존0값·새값·클립 접촉시각·실제시각을 명시하고 피해량/횟수/차징/콤보 정책은 그대로 둔다.
4. 우선 현재 피해 시점에 새 동작의 접촉 피크를 맞춘다. 위0초 지연 예외 외에는 피해 시각을 변경하지 않는다. 필요하면 전용 클립의 준비·타격·회수 시간을 재매핑하되 gameplay hit-delay를 무작정 바꾸지 않는다. 재생속도는 단 한 번 적용하고 실제 경과시간과 클립 시간을 함께 기록한다.
5. 본 local translation/scale은 해당 스켈레톤의 길이를 보존한다. 새9개 클립은 rotation-only bake를 기본으로 하며 상체 회전의 부모·자식 중복 적용을 피하고 quaternion을 정규화한다. 미러는 필요한 손·팔 동작에 한정하고, 하체 스탠스와 root motion 정책을 유지한다.
6. ik_hand_l/r, ik_hand_gun 및 발 IK 목표는 최종 손·발 포즈에 동기화한다. FootIK는 locomotion 앞단에 유지하고 공격 원본을 다시 후처리하지 않는다. Appearance 추가 IK나 잘못된 accessory chain mapping을 재활성화하지 않는다.
7. 맨손/너클 생성기가 최신 전용 연결을 덮어쓰지 않도록 재실행 경로를 점검한다. 다른10무기의 gameplay 또는 asset을 일괄 재생성하지 않는다.

## 카메라와 초기 시선

- 먼저 새 공격 포즈에서 불필요한 머리·가슴의 급회전을 줄인다. 추가 head-motion 조정은 맨손·너클에만 적용한다. raw 머리 회전 기여0.15, 최종 애니메이션 회전 영향 최대8°를 초기 구현값으로 삼고 AppearanceCameraComponent의 UPROPERTY로 노출한다. 다른 무기와 비owner 경로에 적용하지 않는다.
- 카메라 위치의 기준은 실제 Appearance head를 유지한다. 캡슐 고정 카메라나 별도 팔 전용 화면으로 바꾸지 않는다. 애니메이션 머리 회전의 영향도 조절과 마우스 조작은 분리하여 마우스 응답을 지연시키지 않는다.
- 초기 시선은 -30°에서 -20°로 조정하고 화면을 검증한다. 최종값은 정면 표적과 손·하체 가독성의 실제 화면으로 결정하며 한 번만 적용한다. V 왕복이나 무기 교체가 사용자의 조준 pitch를 초기화하지 않아야 한다.
- 카메라 표현이 바뀌면 공격 trace는 실제 최종 머리 카메라와 같은 계산 결과를 사용한다. 렌더 화면만 별도 감쇠하여 조준과 화면이 어긋나지 않게 한다. V 관찰은 기존과 같이 최종 화면 POV만 변경한다.
- head 추종식이 의도적으로 바뀐 경우 과거의 raw head 회전1:1 검사 대신 새 명세의 기대값과 PlayerCameraManager cache를 비교한다. 과거 테스트를 무조건 완화하지 않고 변경된 계약을 기록한다.

## 완료와 후속 범위

맨손과 너클 모두 실제 플레이어 입력에 연결되고1인칭/V 영상과 수치 검증이 준비되어야 제작 완료다. 단순 자산 생성·빌드 성공만으로 완료하지 않는다. 입력·피해를 바꿔 애니메이션을 맞추거나 모션이 나빠진 것을 카메라 감쇠만으로 숨긴 결과는 재설계한다. 같은 실패가2회 반복되면 동일 bake/튜닝을 반복하지 않고 기획·원인 분석으로 돌아간다.

다른10무기 전용 제작, 새로운 돌진/가드/패링/무적, 신규 장비 모델링, 전체 네트워크·경사면 접지·RT 그림자 확장은 이번 범위에 포함하지 않는다. 확인하지 못한 체형·상태·플랫폼은 결과 문서에 명시한다. DevLog/Sprint 결과 갱신은 통합 담당자가 수행하며 커밋·푸시는 별도 사용자 승인 없이 실행하지 않는다.
