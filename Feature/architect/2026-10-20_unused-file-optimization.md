# 과거 제작 파일과 중복 산출물 최적화 계획

작성: 2026-10-20 / 작업 브랜치: `Sprint#6-2-unused-file-optimization`
기준: `77a52b6a` — Sprint5 완료 작업은 기존 번호를 유지하며 신규 Sprint6 작업은 무기 작업 6-1 다음 6-2를 사용한다.

## 목표와 범위

과거 제작에서 생긴 중복 파일과 사용을 마친 산출물의 디스크·체크아웃 부담을 줄인다. 현재 게임 코드·설정·Unreal 바이너리와 Fab 원본을 보존한다. 런타임 프레임 성능 개선과 저장소 과거 이력 축소는 이번 작업의 목표가 아니다.

초기 추적 파일 조사에서 Content 약4,273MiB, Feature 약2,495MiB, Art 약687MiB를 확인했다. Source/Scripts/Config 독립 조사에서 현재 참조와 제작·검증 도구 연결이 확인되어 삭제하지 않는다. 아린 최종 RefinedV3 편집 원본·최종 FBX/GLB/텍스처·모션 원본 및 입력 이미지도 보존한다. Fab 자산의 새 반입·활성·변경은 없으므로 보유 제품 재조사는 필요하지 않다.

## 구현 가드

- 파일명·오래된 날짜·텍스트 참조0만으로 미사용을 판정하지 않는다.
- `.uasset/.umap` 직접 편집·삭제와 생성/캐시 폴더 수정은 하지 않는다.
- `tmp` 안의 worktree·의존성·도구·원본·동시 무기 작업을 보존한다.
- 삭제는 SHA-256이 같은 보존 사본이 확인된 경우를 우선한다. 유일한 과거 검증 자료는 무손실 보관 및 복구 검증 후에만 원시 사본을 정리한다.
- 경로가 프로젝트 안에 있는지 확인하고 reparse/junction 경로를 거부한다. 폴더 일괄 삭제·git clean·강제 푸시는 사용하지 않는다.
- 병행 공개 게시 작업의 AGENTS/Git/Lazy 문서 변경은 이번 스테이징에 섞지 않는다.
- C++/Config/Content 변경이 없으면 Editor 전체 빌드 대신 파일 무결성·스크립트 구문·복구·경로 검증을 수행한다.

## 완료 기준

정리 전후 파일/바이트·보존 해시·복구 방법과 최적화 한계를 보고한다. 한국어 일일 로그와 Sprint 기록을 갱신하고 사용자 상시 승인에 따라 검증된 변경을 커밋·통합한다. 원격 차단이나 병행 통합 충돌은 실제 결과를 기록하며 완료를 주장하지 않는다.
