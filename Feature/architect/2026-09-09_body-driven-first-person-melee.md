# 전신 움직임을 반영하는 1인칭 근접 공격 설계

- 날짜: 2026-09-09
- 브랜치: Sprint#4-24-body-driven-first-person-melee
- 사용자 요구: Mixamo의 box 검색 모션처럼 전신의 체중 이동과 휘두르기가 보이고, 카메라도 동조하는 몰입감 있는 1인칭 공격.
- 대상 엔진: Unreal Engine 5.8.2
- 상태: 구현·빌드·실제 120프레임과 추가 활성 상태 회귀·시야 3조건·독립 검증 완료. 외부 영상 직접 재생은 미확인. 최종 수치와 범위는 paired Feature/doc 문서에 기록했다.
- 범위: 현재 프로젝트의 몽타주와 네이티브 C++ 표현을 개선한다. 우선 자산 수정 없이 작업한다.

## 레퍼런스 접근 상태

사용자가 직접 확인을 요청한 영상은 [YouTube Shorts 레퍼런스](https://www.youtube.com/shorts/O2poybuky-M)다. 현재 세션에서 웹 조회는 실패했고 브라우저 도구도 Windows sandbox ACL helper 오류로 재생에 실패했다. 영상을 직접 보았거나 특정 프레임의 동작·각도·타이밍을 측정했다고 주장하지 않는다.

따라서 이 문서는 사용자가 설명한 체중 이동·휘두르기·카메라 동조 요구와 현재 프로젝트 소스에 근거한다. Mixamo에서 특정 box 모션을 가져왔거나 그 파일을 적용했다고도 표현하지 않는다. 추가 자료가 확보되면 실제 재생을 확인한 범위만 비교하며, 현재 작업은 프로젝트에 있는 전신 몽타주의 움직임을 활용한다.

## 확인한 원인

현재 Rogue10mFistAnimInstance는 DefaultSlot의 전신 포즈를 Animated에 평가하지만, 최종 Output의 몸통·어깨는 MM_Idle 기반이다. 그 뒤 AnimatedHand.Y−RestHand.Y를 0~1로 제한하고 두 개의 고정된 손 위치를 Lerp해 IK 목표로 사용한다.

이 흐름은 다음 정보를 최종 표현에서 버린다.

- 원본 pelvis·spine·clavicle의 이동과 회전
- 펀치 전에 손을 당기는 음수 전진량
- 손의 좌우·상하 움직임과 곡선 경로
- 공격하는 어깨가 앞으로 나가고 반대 어깨가 뒤로 물러나는 관계

양손과 닫힌 주먹은 보이지만 몸은 고정된 채 손만 같은 직선 위를 왕복하기 쉬운 구조다. 이번 작업은 실제 몽타주 평가 결과를 최종 FP 포즈와 표시용 카메라에 제한적으로 전달한다.

## 핵심 설계

### 전신에서 팔로 이어지는 움직임

기존 idle 가드와 닫힌 손·엄지 방향 보정은 기본 상태로 유지한다. 몽타주가 활성화되면 AnimatedCS와 IdleCS의 차이에서 몸통 이동, 척추 회전, 쇄골의 전진·후퇴를 얻는다. 이를 FP 메시의 해당 뼈에 제한적으로 적용하고, 그 결과로 바뀐 어깨 위치를 기준으로 팔 IK를 계산한다.

모든 source 움직임을 그대로 확대하지 않는다. FP에서 읽히는 몸통·어깨 연동을 확보하면서 화면 중앙을 가리는 과도한 상체 회전이나 모델 내부 노출을 제한한다. 원본 pelvis/root 이동은 FP 표현용 뼈에만 적용하며 capsule·실제 캐릭터 위치에 적용하지 않는다.

상위 뼈를 바꾼 후에는 팔의 component-space 부모 변환을 새로 계산해야 한다. 이전 IdleCS의 어깨 캐시를 재사용하면 팔이 몸통에서 떨어질 수 있다. 부모 순서로 변환을 적용하고 안전한 component-space→local 변환을 사용한다.

### 직선 왕복에서 준비·신전·복귀 경로로

기존 손 전진량은 공격 강도의 한 기준으로 유지하되, source 손의 X/Z 잔차와 음수 Y 성분을 별도로 제한해 반영한다. 손이 뒤로 빠지는 준비 자세, 전진하며 살짝 안쪽으로 향하는 궤적, 원래 가드로 돌아오는 회복을 표현한다. 반대 손은 원본 상대 어깨·손 움직임을 따라 가드를 조금 당긴다.

임의의 주기적 흔들림이나 공격과 무관한 사인파를 넣지 않는다. 실제 몽타주마다 다른 좌우 움직임을 사용하고 공격이 끝나거나 취소되면 현재 가드에 수렴한다. 손가락 굴곡 100/100/75도와 해부학적 엄지 방향 보정은 계속 적용한다.

### 가중치와 원본 모션

AnimatedCS는 이미 DefaultSlot 평가 과정에서 SlotWeight가 반영된 포즈다. AnimatedCS−IdleCS 차이에 다시 SlotWeight를 곱하면 움직임이 이중 감쇠될 수 있다. 각 값이 이미 가중된 delta인지 원본 delta인지 명시하고 gain과 clamp를 한 번만 적용한다.

카메라에 전달하는 motion weight도 같은 규칙을 따른다. 위치·회전 delta가 이미 가중된 값이면 추가 envelope는 가시성 종료나 안전한 복귀를 위한 용도로만 정의하고, 포즈 강도를 다시 곱하지 않는다.

### 표시용 카메라 동조

현재 CombatComponent는 타격 시 CameraComponent의 ComponentLocation·ForwardVector·Quat를 직접 판정 기준으로 사용한다. CameraComponent 자체의 위치나 회전을 흔들면 타격 방향과 원점까지 바뀐다.

동조는 CameraModifier 또는 최종 POV와 같은 표시용 view 계층에서만 적용한다. ControlRotation, CameraComponent의 기본 transform, capsule과 실제 캐릭터 위치는 유지한다. 손의 신전·어깨의 체중 이동을 따라 작은 전진과 pitch/yaw/roll을 추가하되, 별도 카메라 애니메이션이 손과 다른 박자로 움직이지 않도록 같은 최종 pose snapshot을 사용한다.

worker의 AnimProxy는 위치·회전·weight만 계산한다. 게임 스레드의 PostEvaluate 등 안전한 전달 지점에서 immutable snapshot을 공개하고, 카메라 측은 유효한 로컬 캐릭터의 snapshot만 읽는다. worker가 CameraComponent나 PlayerController를 직접 변경하지 않는다.

## 초기 튜닝 범위

아래는 영상에서 측정한 수치가 아니라 첫 실제 캡처를 위한 제한값 제안이다. 구현 담당자는 원본 몽타주와 FP 투영을 확인해 최종값을 정하고 차이를 기록한다.

| 표현 | 시작 범위 | 확인점 |
| --- | --- | --- |
| FP 몸통 이동 | 전체 최대 약4cm | 모델 내부 노출·팔 분리 없음 |
| 척추·쇄골 회전 | 약8~12도 이내 | 어깨 체중 이동이 읽히면서 조준 중앙 확보 |
| 손 경로의 좌우 추가 잔차 | 최대 약8cm | 손 교차와 순간 뒤집힘 없음 |
| 손 경로의 상하 추가 잔차 | 최대 약6cm | 대상·HUD 판독 |
| 카메라 표시용 이동 | 최대 약2cm | 판정용 camera transform과 분리 |
| 카메라 pitch/yaw | 각각 약1.5도 이내 | 타격과 같은 방향·박자로 연동 |
| 카메라 roll | 약0.8도 이내 | 수평선이 과도하게 기울지 않음 |

새 튜닝값은 필요한 범위에서 UPROPERTY로 노출한다. 원본이 해당 방향으로 움직이지 않을 때는 보정값도 0이어야 한다. 정지 상태에서 임의의 잔여 camera motion이나 상체 오프셋이 남지 않아야 한다.

## Ultrawork Packets

### P1 — 원본 전신 delta와 손 경로 복원

- 목표: 몸통→어깨→주먹으로 이어지는 실제 몽타주의 움직임을 FP에 반영한다.
- 입력: DefaultSlot의 Animated 포즈, idle 기준 포즈, 현재 가드/손가락 캐시.
- 수정 위치: Character/Rogue10mFistAnimInstance.h/.cpp.
- 완료 조건: 공격 준비 후퇴, 어깨 전진, 손의 비직선 경로와 복귀가 실제 영상에서 보인다. 손목·손가락 형태가 유지된다.
- 검증 명령: Scripts/BuildEditor.ps1 -NoHotReload, 기존 또는 확장된 Rogue10m.TestFistPresentation.
- 되돌릴 경계: 이번 body delta·곡선 경로 적용만. 기존 손 방향과 clench 구현은 보존한다.

### P2 — 표시용 카메라 동조 연결

- 목표: 실제 조준·타격 기준을 바꾸지 않고 전신 공격의 움직임을 시야에 전달한다.
- 입력: 최종 FP pose의 game-thread motion snapshot.
- 수정 위치: 필요한 presentation component/카메라 표시 계층과 캐릭터 연결.
- 완료 조건: 실제 화면에는 작은 동조가 보이지만 ControlRotation과 판정용 CameraComponent transform은 동일하다. 공격 종료·취소·무기 교체 후 오프셋이 0으로 복귀한다.
- 검증 명령: 실제 runtime에서 baseline 대비 transform·control rotation 불변 검사, 표시용 POV delta 측정.
- 되돌릴 경계: view modifier 및 snapshot 전달 연결만.

### P3 — 통합 동작 및 회귀 검증

- 목표: 움직임의 숫자 증가와 실제 몰입감 있는 동작을 분리해 확인한다.
- 입력: 실제 공격 3회, 연속 프레임, 위·아래 시선과 ultrawide 조건.
- 수정 위치: runtime test와 검증용 캡처만.
- 완료 조건: 어깨 delta·손의 준비 후퇴/상하좌우 변위·카메라 view delta를 기록하고, 영상에서 동일한 공격 흐름으로 읽힌다. 공격 취소와 무기 재진입에서도 포즈·카메라가 복원된다. 손/목/몸통 clipping과 중앙 대상 가림이 없다.
- 검증 명령: 확장된 runtime test, 독립 소스 검토, 독립 시각 검토.
- 되돌릴 경계: test fixture만. 게임플레이 데이터를 테스트를 위해 영구 수정하지 않는다.

### P4 — 결과와 한계 기록

- 목표: 무엇을 실제 적용했는지와 원본 영상 접근 한계를 명확히 전달한다.
- 입력: 빌드/실행 로그, 실제 게임 GIF 또는 영상, 독립 리뷰.
- 수정 위치: paired Feature/doc 문서, DevLog/20260909.txt, Docs/SprintChangeLog.md.
- 완료 조건: 실제 프로젝트 몽타주 기반이라는 점, 직접 보지 못한 외부 영상, 실제 body/view 연동 결과를 기록한다.
- 검증 명령: git diff --check, Scripts/CheckGeneratedChanges.ps1.
- 되돌릴 경계: 이번 문서 항목과 캡처만. 커밋과 푸시는 하지 않는다.

## 역할과 불변 조건

기획 1, 개발 2(전신 포즈/카메라 전달), 검증 2(소스·판정 불변/시각)를 동시 실행 슬롯에 맞춰 배정한다. 루트는 통합 빌드·실게임 캡처·결과 기록을 맡는다.

공격 입력, 차징 기준, 몽타주 재생 속도, 쿨다운, 연계 시간, 피해 발생 시점과 사거리는 유지한다. 현재 타격 시퀀스는 ExecuteAttackSkill에서 몽타주를 시작한 뒤 StartAttackHitSequence로 이어지는 구조이며, 보여주는 신전 프레임에 맞추려고 타격 로직을 새로 지연하지 않는다.

추가적인 영구 Tick이나 매 프레임 asset load를 도입하지 않는다. 카메라가 매 프레임 읽는 경로는 엔진의 기존 view 업데이트를 활용하고, 포즈 평가에서 필요한 뼈·자산은 캐시한다. 성능 문제는 역할을 나눠 측정하고 같은 실패를 두 번 반복하면 표현 구조부터 다시 검토한다.

## Exit Gate

- 원본 전신 움직임의 일부가 실제 FP 몸통·어깨·손 경로에 보인다.
- 공격과 같은 박자의 제한된 카메라 view 동조가 보인다.
- ControlRotation, 판정용 CameraComponent, 피해 타이밍과 사거리가 보존된다.
- 손 형태, 중앙 대상 판독, 기존 HUD 배치와 비율 대응이 유지된다.
- 종료·취소·무기 전환·재진입 시 포즈와 view 오프셋이 정상 복원된다.
- UE 5.8.2 빌드, 관련 runtime 검사, 독립 소스·시각 검토를 완료한다.
- 실제 영상과 결과 문서·한국어 로그를 남긴다.
