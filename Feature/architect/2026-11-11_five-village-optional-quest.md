# 다섯 마을 선택 회수 의뢰 수직 구현

2026-11-11 UTC. 사용자의 전체 Work 재개 지시에 따라 실제 콘텐츠 연결의 첫 수직 흐름을 구현한다. 다른 Codex의 공유 프로젝트 작업과 충돌하지 않도록 모든 신규 C++는 `Feature/implementation/five-village-quests-20261111/Source/Rogue10m/`에 둔다. 현재 작업 브랜치는 `Sprint#9-29-humanoid-boss-npc`이며 공유 브랜치를 전환하지 않는다. 공유 Source·에셋·설정과 UE/UBT는 담당자 인계 전 변경/실행하지 않는다.

## 현재 확인

- 현재 후보 맵과 별도 Hub 입구, 방문 관측 Component가 존재한다. 기존 일반 Quest/Objective 구현은 찾지 못했다.
- 실제 `TravelSpeedD`는 정상 포털 여행·같은 프로필/RunId·인벤토리·1200초까지 확인했으나, 기본 신발 +20으로 실제620인 상태를600으로 고정한 fixture에서 중단됐다. 직행·재방문·정산·귀환 통과 결과는 아니다. 다른 담당자의 수정 중인 travel Source와 증거는 수정하지 않는다.
- 기존 TutorialNPC의 상점은 StartHub+WaitingToStart 조건이다. 필드 마을에 복제해도 현재 서비스 계약상 사용할 수 없다. 이번에 기존 NPC의 조건을 완화하지 않는다.
- `Inventory.TryAddGridItem`은 실제 인벤토리 추가 성공 여부를 돌려준다. 의뢰 보상은 기존 HealthPotion DataAsset1개를 이용하는 런 임시 아이템으로 한정한다. 새 세이브/로비 보상은 만들지 않는다.

## 이번 콘텐츠

V1의 선택 의뢰 `V1_SupplyRecovery`: 게시판에서 수락 → V3 쪽의 분실 보급품을 F로 회수 → V1로 돌아와 F로 보고 → 회복 물약1개. 수락 전에 보급품을 회수해도 같은 런의 사실을 인정한다. 보급품 액터를 파괴하거나 상태를 그 액터에 저장하지 않아 재방문/액터 재로드에서 사실이 중복되지 않는다. 마을 미방문·미수락 상태는 실패가 아니며 보스나 도로를 잠그지 않는다.

PlayerState의 전용 ActorComponent가 의뢰 상태를 갖는다. 데이터는 DataAsset에 둔다. 상태는 미수락→수락/완료조건 충족→지급중→수령이다. 지급 중에는 재진입을 잠그고 실제 아이템 추가 실패는 완료 표시 없이 다시 시도할 수 있게 한다. 성공한 보상만 수령으로 확정한다. 새 RunId에서는 사실·수락·보상 상태가 초기화된다. 활성 런·권한·현재 소유 Pawn·생존·후보 맵 조건을 벗어나면 변경을 거부한다.

상호작용은 작은 월드 표식과 F 안내로 제공한다. 대화창/메뉴를 띄우거나 pause를 걸지 않으며 기존 런 시계가 흐른다. 기존 입력·카메라·피격 취소·면역 정책은 수정하지 않는다. 보급품은 충돌 없는 프로토타입 표식이며 기존 도로와 중앙 직행 통로를 막지 않는다.

## 재사용 자산

`Docs/FabAssetReuseGuide.md`를 읽었다. 실제 로컬 `Content/DataAsset/Item/Starter/DA_Item_HealthPotion.uasset`를 보상 후보로 재사용한다. 표식은 엔진 BasicShapes Cube와 TextRender만 쓴다. vendor 에셋·새 모델·팩 다운로드는 없다. Fab 현재 계정 소유권/버전/약관을 확인했다고 주장하지 않으며 신규 Fab 반입도 없다. 기존 물약의 현재 런 효과와 인벤토리 추가는 UE 통합 단계에서 실제 확인해야 한다.

## 인수와 한계

이번 Exit Gate는 격리 구현·독립 컴파일 가능한 모델·정적/독립 API 리뷰·짝 문서/한국어 DevLog이다. UE UHT/C++ 전체 빌드, 실제 F 입력, 후보 맵의 additive 배치·저장/재로드·아이템 효과·정산, 프레임/시각 품질은 공유 담당자의 통합 작업이다. Source가 존재하지 않는 설치 전 상태에서 완료를 과장하지 않는다.

현재 GameMode/ProgressComponent는 정확한 후보 패키지 조건을 사용한다. 통합 담당자의 사용권에서 원래 후보에 두 액터만 좁게 추가하는 방식을 준비하며, 이번에 맵이나 조건을 수정하지 않는다. 별도 레벨을 선택한다면 해당 클래스들의 지원 맵 계약을 먼저 명시적으로 확장해야 한다. 신규 맵을 원래 후보 이름으로 가장하지 않는다.

다섯 마을 전체 고유 품목/상점/던전/몬스터/보스, 마을 안전 메뉴, 실제60초·15분, Windows cook/패키지는 이번 수직 구현과 별도다. 새 면역은 사용자 결정 전 보류한다.
