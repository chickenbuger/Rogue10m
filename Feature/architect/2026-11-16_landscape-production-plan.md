# Rogue10m 월드 구성 및 Landscape 제작 기획서

2026-11-16 · Sprint#9-32 · 1차 기획 제시 / 2차 native 외곽 정리·cold 보존 검증 완료, 통행 QA 미인수

**목표는 큰 마을 3곳·전문 초소 5곳을 잇는 선택형 탐험 필드를, 실제 Landscape 1,012.5×562.5m 안에 구성하는 것이다.** 남쪽 진입점부터 북쪽 보스 입구까지 중앙 300m를 유지하고, 서쪽 수렵·너클 / 동쪽 장비·대검 / 북동쪽 기록·마법의 선택 동선을 둔다.

![좌표 기반 제작 배치도](../doc/evidence/landscape-production-20261116/landscape-plan.png)

이 그림은 실제 좌표로 그린 제작 배치도다. Unreal 캡처나 완성된 지형을 뜻하지 않는다. 전체 구성의 분위기는 [보존 콘셉트 PNG](../../Docs/References/WorldMap/rogue10m-world-map-concept-20261112.png)를 함께 참조한다.

## 1. 적용할 기존 결정

- StartHub는 준비·영구 성장용 별도 맵이다. 필드의 큰 마을 수에 포함하지 않는다.
- 필드 런은 최대 20분. 중앙 직행로는 시작부터 개방하고, 기본 보행으로 보스 **입구**까지 약 60초 이내를 목표로 한다.
- 성장 탐험 경로는 전투·수련·발견을 포함해 약 15분에 보스 입구에 도착하도록 검증한다. 모든 마을 방문이나 중간보스 처치를 강제하지 않는다.
- 일반 몬스터 최소 15종, 선택 중간보스 4종, 최종보스 아자토르 1종을 구분한다.
- 중·상위 비급은 현장 탐험에서 발견한다. 입문·하위 책만 간단한 수련·의뢰의 명시적 보수로 허용한다. 발견·학습·장착은 별도다.
- 무기별 동시 입력·차징 지원을 유지한다. 마법사의 Ctrl→첫 Q에서 고정 기한 시작→QQQ 자동 발사를 바꾸지 않는다.
- 필드 메뉴에서는 시간이 흐른다. 안전 구역에서 해당 메뉴를 열 때만 게임·AI·런 시계를 함께 멈춘다.

기준 우선순위는 최신 사용자 지시 → [제작 기준](../../Docs/WorldMapProductionGuide.md) → [배치 JSON](../../Docs/References/WorldMap/world-layout-20261112.json)·[획득 JSON](../../Docs/References/WorldMap/acquisition-catalog-20261112.json) → 이번 지형 세부안 → 이미지 → 과거 초안이다. 이번 지형 세부안은 기존 좌표·획득·입력 규칙을 대체하지 않는다.

## 2. 현재 상태와 이번 제작 범위

기존 WorldLayout20261112에는 1,800×1,800m Landscape와 도로·건물·콘텐츠 표식이 있다. Compact20261113A에는 후속 NPC/의뢰와 편집 변경이 누적되어 있다. 11/14에 독립 WorldLayoutCompactCrop20261114A를 복제했지만 당시 실제 외곽 삭제는 0회였다. 현재 저장본·컴포넌트 수·레이어·dirty 상태는 에디터에서 다시 확인한다.

이번 2차 작업은 독립 Crop 후보의 실제 Landscape 외곽 정리, 유지 구역 보존, 경사·충돌·통행 확인이다. 원본 맵·StartHub·포털 목적지·런타임 코드·기존 패키지는 이 과정에서 변경하지 않는다. 기존의 배치 표식을 실제 15종 AI·12명 NPC·23권 비급 완성으로 보고하지 않는다.

## 3. Landscape 수치와 좌표 계약

| Landscape | 기존 원점 (-90000,-90000,0)cm와 Z scale 256 유지 |
| 보존 인덱스 | 컴포넌트 X5..13 / Y10..14, inclusive 정점 X315..882 / Y630..945 |

900m 폭은 동쪽 BG 중간보스의 기존 반경18m 대지가 경계를 넘기 때문에 채택하지 않는다. 9×5는 해당 대지와 도로 어깨를 포함하고 최종보스장 북단 뒤에 52.5m를 남긴다. 기존 대비 지형 면적 감소는 약 82.42%의 **치수 산술**이며, 체감 밀도·FPS 개선의 실측값이 아니다.

정점 수는 유지 사각형의 고유 표본 환산값이다. 새 568×316 heightmap을 import하는 절차가 아니다. 현재 레이어·높이·페인트를 유지하는 native 컴포넌트 편집을 사용한다.

## 5. 도로·고도·통행

- 중앙 S→J100→J180→J240→B는 평면 길이300m. 기존 설계 고도50→96m와 연속 완경사를 유지한다. 기본 이동속도나 액터 스케일을 바꿔 시간을 맞추지 않는다.
- 전체29개 간선은 양방향이다. 중앙 외 경로는 서쪽 H→P→W→Q→J240, 동쪽 M→A→G→T→J240, 북동 G→F→Z→O→T와 각 중간보스 샛길로 구성한다. 정확한 간선 목록은 JSON을 따른다.
- 통행 폭8m, 평탄하게 정리한 지형 어깨 포함 총14m, 그 바깥12m에서 주변 지형으로 부드럽게 연결한다. 총14m를 도로 한쪽 폭으로 해석하지 않는다.
- 도로 종·횡·합성 경사 목표는12° 이하. 기존 표본 종경사 통과와 달리 일부 셀 합성경사15.095° 기록이 있으므로 재검사한다. crop 전후 유지 데이터 불변 검증을 먼저 통과한다. 경사 실패가 남으면 별도 국소 보정 패킷으로 변경 구역·최대 높이 차를 기록하고 보정 전후를 보존하며, 비보정 구역의 불변을 확인한다.
- 건물 평탄대와 길 사이에 돌출 턱·급경사·장식 충돌을 두지 않는다. 직행로, 갈림길, 서비스 앵커, 보스 입구에서 실제 Character capsule 통행을 확인한다.
- 중앙로에 필수 전투 트리거를 두지 않는다. AI 스폰·추적 경계는 후속 콘텐츠 작업에서 중앙로와 서비스 공간을 분리해 검증한다.
- 강·물길은 시각 방향성을 줄 수 있으나 필수 도하를 만들지 않는다. 실제 물·다리는 이번 지형 외곽 정리의 필수 산출물로 포함하지 않는다. 동굴·지하실·수직 절벽의 돌출부는 Landscape 높이장만으로 만들 수 없으므로 후속 메시 공간으로 분리한다.

## 6. NPC·무기·책이 들어갈 자리

획득 카탈로그의 우선3계열, 너클10권·대검10권·마법3권의 **총23권**과 특정 무기3개를 유지한다. 입문 보수3권과 현장 발견20권을 구분한다. 후속8직업은 장소 예약이다.

무건은 Q, 도겸은 G, 세란은 O에 대응한다. 유하는 T의 정보 NPC다. 붕권은 W 수련자 유품이며 Q의 반복 초급 보수로 되돌리지 않는다. F 대장간과 Z 제련로를 구별한다. 이번 지형 단계에서는 해당 장소의 접근 가능 공간을 보존하며 새 보상·학습 코드를 추가하지 않는다.

## 7. 자산 재사용과 편집 경계

[Fab 재사용 가이드](../../Docs/FabAssetReuseGuide.md)에 따라 기존 프로젝트의 Landscape 재질·layer info와 Stylized_Village의 현 배치 건축·수목·바위를 보존한다. 이번 단계는 이미 놓인 에셋의 참조 보존과 지형 편집이다. 신규 팩 반입·구매·vendor 수정은 없다. 과거 보유 카드와 로컬 존재를 현재 계정 소유·새 라이선스 검증으로 표현하지 않는다. 새 에셋 활성화가 필요해지면 해당 제품 소유·UE5.8/포맷·의존성을 그때 확인한다.

## 8. Ultrawork Packets와 실행 순서

### P0 에디터 실행 복구 (2026-11-16 추가)

사용자가 에디터 실행 실패 점검·계속 진행을 요청했다. 호스트의 정확한 프로세스와 최초 종료 사유·UBT 로그를 함께 확인한다. 일반 sandbox 프로세스 조회를 호스트 전체 상태로 해석하지 않는다. 현재 확인된 VS 실패는 종료 중 잔류한 `-game` PID21224의 Live Coding 잠금이다. 이전 로그를 보존하고 정확한 해당 프로세스만 종료한 뒤, 중복 UBT/컴파일러가 없는 상태에서 정규 Editor 빌드→`-game` 없는 정상 에디터 실행→공식 MCP read-only identity를 확인한다. 사용자 VS 세션·다른 프로세스·원본 콘텐츠는 보존한다. 실패가 반복되면 로그를 기준으로 재설계하며 플러그인을 추측으로 비활성화하지 않는다.

P2/P3은 연결된 공식 Unreal MCP와 에디터 Landscape UI로 실행한다. 읽기 전용 helper `Rogue10mCrop20261114WorldAuthoring`의 Inspect/Load/Select/Snapshot/Dependencies를 사용한다. helper의 guard를 완화하거나 private EdMode, 임의 DestroyComponent, CollapseAllLayers, 과거 R16 재Import로 현재 편집을 교체하지 않는다. 저장 전 외곽 참조와 유지 지형 의존성을 확인한다.

2026-11-16 live 검사에서 전역 reflection walker는 UE5.8의 deprecated lazy/opaque bag/Optional·FieldPath 미지원1,156건으로 실패했다. 이 실패를 보존하며 성공으로 바꾸지 않는다. 독립 리뷰에 따라 백업된 후보의 정식 native crop 시도에 필요한 별도 범위 검사(1361 descriptor 로드·직접지형참조0,18개package 전체7종referencer 조회,1361개액터/1986개컴포넌트의terrain authoring의존 확인,정확한211/45선택)를 추가했다. 전역·native custom 참조 전체의 안전성 인증으로 확대하지 않으며, 실제 결과는 Undo/Redo·retained 데이터·저장/재로드로 검증한다. Source helper의 미지원 항목·guard·원문 결과는 수정하지 않았다.

C++/Build.cs를 바꾸지 않으면 새 정규 빌드를 반복하지 않는다. 실제 helper 누락·ABI 불일치가 확인될 때만 Architect로 돌아가 필요한 범위를 빌드한다. 같은 실패가2회면 재시도 대신 설계·리뷰로 돌아간다.

## 9. 검증 명령과 인수 기준

문서 기하 검사:


최종 지형 완료에는 다음 실측이 필요하다.

1. 현재 후보의 실제 Landscape 45개 지형·충돌 컴포넌트와 경계 일치. proxy 수는 crop 후 실제값을 기록하고 임의 예상하지 않는다.
2. 유지 구역의 현재 height/paint/layer metadata/GUID 및 액터 transform·참조가 전후 일치. 계획 원본 수치와 현재 저장본을 혼동하지 않는다.
3. 정상 Undo/Redo, 후보만 저장, 독립 재로드 후 동일 결과. 외곽 삭제로 남은 dangling 참조가 없는지 점검한다.
4. 29개 길의 지면·충돌·도로 투영 확인. 정상 프로필·기본장비로 실제 Pawn 기본보행 중앙3회 모두≤60초, 순간이동0·가속 조작0을 기록한다. 프로그램 입력과 물리 키보드 검증을 구분한다.
5. 삼각형 경사 검사와 시점별 화면 확인. 사람이 진행한 서로 다른 성장 경로 최소5회와15분 성장·20분 완주는 전투 콘텐츠까지 연결한 후 별도 인수한다.

기존48.537초는 과거 후보에서 프로그램 입력1회로 얻은 결과다. 이번 후보의 통과나 물리 플레이 검증으로 인용하지 않는다. 계획 기하 검사가 성공해도 live 지형 제작 완료로 표시하지 않는다.

## 10. 1차와 2차의 상태

1차 기획·좌표 보충 JSON·배치도·기하 검사를 먼저 제시했다. 이후 에디터 실행 문제를 복구하고 사용자의 “외곽 211개 삭제 후 검증 진행” 승인에 따라 2차 native 지형 편집을 실행했다. 독립 Crop 후보는 지형·충돌 각45개로 저장됐으며 새 에디터에서 보존 비교26항목이 통과했다. Undo/Redo 직후 composite 보존 실패는 공개 native 재합성1회로 최종 상태를 복구했지만 즉시 보존 합격으로 바꾸지 않는다. 29도로 검사의 정확한 격자선 레이2점은 실패로 유지하고, 별도 구체·오프셋 진단과 프로그램 보행을 구분해 기록한다. 실제 결과와 남은 인수 항목은 [제작 결과서](../doc/2026-11-16_landscape-production-result.md)를 따른다. 기존 소스·콘텐츠 WIP와 미완료 지형 검증을 묶어 커밋·승격하지 않는다.
