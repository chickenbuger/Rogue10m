# Sprint#4-21 참조 이미지 기반 금속 전투 HUD

- 날짜: 2026-09-08
- 브랜치: `Sprint#4-21-reference-metal-hud`
- 단계: Architect / 구현 계약
- 입력: 사용자가 첨부한 검은 금속 전투 HUD 이미지, Sprint#4-20 화면 비율 대응 구현
- 목적: 기존의 단순한 직사각형 패널을 참조 이미지의 은색 금속 테두리, 중앙 원형 문장, 얇은 생명력·자원 바, 그림 중심 슬롯으로 구성한다.

## 범위와 기존 상태

이번 요청은 실제 프로젝트의 UI를 수정하라는 지시로 해석한다. C++ 위젯 표현, Editor 생성·검증 스크립트, HUD 아트와 Editor 저장 UI 에셋, 검증 코드 및 문서가 변경 대상이다. 첨부 이미지 안의 예시 수치·아이템·층 표시는 게임 기능 요구나 실제 데이터로 취급하지 않는다.

`Rogue10mBottomHUDWidget`는 현재 1000×160 디자인 공간을 하나의 ScaleBox로 감싸며 DPI를 상속하고 DownOnly로 축소한다. MainHUD는 하단 공간을 이 위젯의 높이와 하단 여백으로 계산한다. 기존 안정화된 반응형 계층을 유지하면서 디자인 공간과 내부 위젯 구성을 확장한다.

현재 행동 View는 공격 4개와 회피 1개이며 아이템 View는 잠긴 4칸이다. 스킬의 SkillIcon이 없는 경우 기존 위젯은 이미지를 숨긴다. 아이덴티티는 자원 유무와 정규화 값, 직업/무기 정보를 View로 전달한다. 디자인을 채우기 위해 실제 자원, 쿨다운, 아이템 개수나 해금 여부를 만들어내지 않는다.

기존 레벨·카메라·무기·전투·아이템 기능을 이번 UI 작업에서 변경하지 않는다. 첨부 이미지의 폐허 배경과 적 모델은 UI 스타일 참고 배경이다. 5번째 아이템 슬롯, 소모품 사용, 8칸 스킬바, 층 진행 기능은 범위 밖이다.

## 시각적 방향

- 외곽: 검은 금속 몸체, 얇은 밝은 은색 모서리, 제한된 금색 장식. 중앙 원형부와 좌우 프레임이 하나의 구조로 연결되도록 한다.
- 체력/자원: 왼쪽 붉은 체력 바, 오른쪽 금색 스태미나 바. 마력 사용 시 같은 위치에서 해당 자원과 색을 표시한다.
- 중앙: 156×156 원형 문장과 실제 정규화 값을 따르는 외곽 게이지. 문장 위에 직업명 등 긴 문구를 겹치지 않는다.
- 행동 슬롯: 프레임 내부에 큰 그림 영역을 두고 키 라벨을 그 아래 별도 줄에 배치한다. 쿨다운 숫자와 잠금은 그림 영역의 상태 표현으로 유지한다.
- 보조 정보: 레벨은 프레임 왼쪽 아래, 경험치는 화면 아래 전폭의 얇은 선. 상단 중앙 대상 정보, 우상단 남은 시간은 기존 데이터로 표시한다.
- 중앙 게임 시야를 확보하기 위해 정보의 대부분을 아래로 모은다. 외곽 장식이 체력 수치와 키 라벨의 가독성을 가리지 않게 한다.

## 공통 레이아웃 계약

| 항목 | 디자인 단위 / 정책 |
| --- | --- |
| CombatDesignSize | 1200×208 |
| 코어 화면 아래 여백 | 56 |
| 좌우 최소 여백 | 24 |
| MainHUD 하단 예약 높이 | 264 = 208 + 56 |
| 중앙 아이덴티티 | 156×156, 가로 중앙 |
| 행동 / 아이템 수 | 5 / 4 |
| 경험치 | 코어 외부, 화면 전폭, 얇은 높이 |
| ScaleBox | ScaleToFit / DownOnly, 중앙·아래 정렬 |
| DPI | 현재 UE 설정 상속, 추가 배율 곱셈 없음 |

Main BottomHUD는 anchors(0,1)-(1,1), alignment(0,1), offsets(0,0,0,264)로 배치한다. Combat ScaleBox는 같은 하단 앵커와 alignment를 사용하고 offsets(24,-56,24,208)로 둔다. SizeBox의 1200×208 공간 안에 프레임, 바, 문장, 슬롯, 라벨을 함께 넣는다. 화면 폭이 부족하면 장식과 콘텐츠가 같은 배율로 줄어들고, 넓은 화면에서는 가로로 늘어나거나 확대되지 않는다.

이 값들은 UMG 논리 좌표이며 실제 픽셀 크기는 DPI와 ScaleBox 배율에 따라 달라진다. 같은 데이터를 화면마다 독립 좌표로 다시 배치하거나 매 프레임 SetRenderScale로 보정하지 않는다. 슬롯 및 바의 세부 좌표는 아래 최종 구현 계약에 확정했으며 Editor 생성기와 검증 코드가 같은 계약을 사용한다.

## 그림이 없는 스킬의 표시

실제 SkillIcon이 있으면 그 자산을 우선 표시한다. 아이콘이 없는 해금 행동은 공격·보조 공격·차징·회피를 구별하는 간결한 기본 그림 또는 심벌을 표시한다. 이는 스킬 데이터나 성능을 대신하는 UI용 기본 표현이며, 슬롯 입력 정보와 툴팁의 실제 이름은 유지한다.

잠긴 아이템 4칸에는 회색 슬롯과 잠금 표시를 사용한다. 참조에 보이는 포션·폭탄·스크롤을 실제 보유 아이템처럼 그리거나 5칸으로 늘리지 않는다. 기본 그림과 실제 그림 전환, 잠금 및 쿨다운 레이어의 순서가 서로 겹쳐 정보를 지우지 않도록 한다.

중앙 원형 게이지는 IdentityView의 실제 정규화 값을 사용하고, 자원이 없으면 비활성 상태로 둔다. 참조 이미지의 72%나 예시 체력·스태미나 수치를 고정하지 않는다. 새 시각 자산은 UI 전용 디렉터리에 두고 Unreal Editor의 공식 에셋 임포트·저장 흐름으로 처리한다.

## Unreal 구현 원칙

- 수치와 상태 갱신은 기존 C++ View 전달 경로를 사용한다. 새 Tick이나 별도 폴링 루프를 추가하지 않는다.
- 원형 게이지는 NativePaint에서 Slate 선분으로 그리며 View 변경 시 기존 경로에서 갱신한다. 원형을 흉내 내는 수평 막대를 중복 노출하지 않는다.
- 선택 바인딩은 BindWidgetOptional 및 GC 추적 가능한 UPROPERTY/TObjectPtr을 사용한다. 새 표현이 없는 기존 위젯도 동작해야 한다.
- 바 색·프레임·기본 그림 등 시각 튜닝은 Blueprint 기본값이나 데이터 기반 설정으로 노출한다.
- 입력 이름과 전투 바인딩을 유지한다. 하단 키 라벨은 LMB/RMB/HOLD LMB/HOLD RMB/E 계열의 실제 입력을 읽을 수 있어야 한다.
- 아트의 알파 배경과 실제 위젯 트리를 분리한다. 수치·슬롯 그림·게이지가 아트에 구워져 실제 상태와 불일치하지 않도록 한다.
- 재생성 스크립트는 변경 대상 경로를 명시적으로 저장한다. 기존 대량 미커밋 변경과 다른 에셋은 보존한다.

## 검증 계획과 완료 조건

1. 설치된 UE 5.8 Editor 타깃 빌드에 성공한다. 원형 표시나 새 바인딩을 Python 문법 검사만으로 완료 처리하지 않는다.
2. Editor에서 대상 에셋을 재생성한 뒤 native 부모·변수 바인딩·ScaleBox 계층·CDO 크기·슬롯 개수·저장 성공을 확인한다.
3. 기존 실제 게임 시험의 1280×720, 1920×1080, 2560×1440, 3440×1440, 800×900에서 UI 배율 125%, 복귀 1920×1080의 6조건을 새 계약으로 검사한다. 마지막 복귀 조건에서 배율과 배치가 정상 복원되는지도 확인한다.
4. 중앙 정렬, 1200:208 코어 비율, 원형 문장 정사각형, 화면 경계 내 배치, 5+4 슬롯 간격, 아래 여백, XP 전폭, 주변 정보가 core에 가려지지 않는지 측정한다.
5. 실제 게임 캡처에서 프레임 알파, 금속 테두리, 수치 가독성, 슬롯 그림/대체 그림, 키 라벨, 원형 게이지 레이어를 확인한다. 구조 검증과 화면 검증 결과를 구분해 기록한다.
6. 마력 활성화와 스태미나 사용, 아이덴티티 자원 유무 및 대표 값, 잠금, 쿨다운 표시를 가능한 범위에서 확인한다. 시험 값은 일회성 테스트 프로세스에만 주입하며 게임 기본 데이터를 변경하지 않는다.
7. 대상 Widget/Texture 외 바이너리 변경 여부를 확인하고 기존 미커밋 자산과 구분한다. 생성/캐시 파일 및 바이너리를 직접 편집하지 않는다.
8. 한국어 DevLog와 Sprint 변경 기록을 갱신하고 실제 결과 캡처를 전달한다. 커밋·푸시는 별도 사용자 확인 전까지 수행하지 않는다.

## 최종 구현 계약 정합성 갱신 — 2026-09-09

현재 `ApplyReferenceMetalHUD.py`와 `ValidateReferenceMetalHUD.py`의 최종 계약을 반영했다. 구현 시작일을 유지하기 위해 이 문서의 파일명은 2026-09-08로 둔다. 아래는 저장 자산·소스 계약이며 실제 실행 검증 완료를 뜻하지 않는다. 실행 결과는 개발 결과 문서에 별도로 기록한다.

### 전투 코어 좌표

아래 좌표는 모두 `UI_CombatCanvas` 안의 x, y, 폭, 높이다.

| 요소 | 최종 좌표 |
| --- | --- |
| 체력 | 60, 42, 420, 24 |
| 스태미나 / 마력 | 720, 42, 420, 24 |
| 아이덴티티 | 522, 24, 156, 156 |
| 행동 5칸 그룹 | 50, 82, 360, 84 |
| 아이템 4칸 그룹 | 790, 82, 286, 84 |
| 레벨 | 30, 180, 90, 20 |
| 직업 색상 장식 | 563, 183, 74, 2 |
| 직업명 | 534, 186, 132, 18 |

각 슬롯은 64×84로 그림 영역 64×64와 아래 입력 라벨 공간을 가진다. 슬롯 사이 간격은 10이고 마지막 슬롯 뒤 여백은 0이다. 키 라벨의 내부 좌표는 (0,66,64,18), 실제 그림은 (6,6,52,52)다. 잠금과 쿨다운 숫자는 그림 위에, 불투명한 기존 슬롯 장식은 실제 그림 뒤에 둔다.

아이덴티티 내부 아이콘은 (38,32,80,80), 백분율은 (24,113,108,24)다. NativePaint의 원형 게이지는 실제 View와 같은 정규화 값을 사용하며 기존 갱신 경로에서 재그리기를 요청한다. `IdentityBarWidget`는 BottomHUD 트리에 생성하지 않아 별도 수평 아이덴티티 바가 중복 표시되지 않는다.

### 프레임 원본과 UV 영역

ImageGen으로 새로 생성한 금속 프레임 원본은 1920×819다. 한 장 전체를 1200×208로 강제 변형하는 대신 `URogue10mAtlasImage`의 직렬화된 UVMin/UVMax를 사용해 좌우 날개와 중앙 문장 영역을 각각 배치한다. 원본의 중앙 원형 장식이 전체 HUD 폭을 따라 찌그러지는 것을 방지한다.

| 위젯 | 원본 영역 (좌, 위, 우, 아래) | 코어 배치 (x, y, 폭, 높이) |
| --- | --- | --- |
| UI_ReferenceMetalWingLeft | 0, 272, 800, 553 | 0, 0, 510, 208 |
| UI_ReferenceMetalWingRight | 1120, 272, 1920, 553 | 690, 0, 510, 208 |
| UI_ReferenceMetalCrest | 725, 104, 1195, 643 | 512, 0, 176, 202 |

UV는 원본 폭 1920, 높이 819로 각 픽셀 좌표를 나눈 값이다. 원본 텍스처 한 장을 공유하고 프레임을 물리적으로 분할 편집하지 않는다. 설치 엔진에서 `Rogue10mAtlasImage`를 컴파일한 후 생성기가 이를 로드하고, validator가 클래스·텍스처 참조·UV·좌표를 검사한다.

`WBP_ReferenceMetalIdentityBar`는 텍스트 없는 호환용 자산으로만 생성하며 현재 BottomHUD에는 연결하지 않는다. 새 프레임 텍스처는 `/Game/UI/HUD/ReferenceMetal/T_HUD_ReferenceFrame` 1개다. 기존 Responsive 위젯, 공용 Gothic 슬롯 프레임, StoneFist 스킬 아이콘 5개는 재사용하며 수정하지 않는다.

스킬 아이콘이 없는 해금 슬롯은 순서대로 기존 Jab, Straight, ChargedShockwave, JumpSlam, Dodge 그림을 UI 대체 이미지로 사용한다. 실제 SkillIcon이 있으면 우선하고, 아이템 슬롯이나 잠긴 행동에는 이 대체 그림을 적용하지 않는다. 실제 스킬의 속성·이름·무기 데이터를 이 그림에 맞춰 변경하지 않는다.

### 주변 정보와 검증 상태

대상 정보는 전용 MonsterInfo 위젯으로 구성해 상단 중앙 (0,24,420,68)에 둔다. 타이머는 우상단 (-24,24,140,32), 시스템 로그는 좌하단 (24,-288,360,48), 획득 알림은 화면 우측 높이 65%의 (-24,0,260,72)를 사용한다. 로그의 하단 여백 288은 하단 예약 높이 264에 24를 더한 값이다. XP는 코어 밖에서 화면 전폭, 높이 4를 유지한다.

런타임 시험은 실제 AttributeSet 값을 사용하는 일회성 fixture로 아이덴티티 0%, 72%, 100%, 35%, 자원 없음 상태를 설정한다. 마력 사용 조건도 시험 상태에서 명시적으로 활성화한다. 이 값들은 디자인 미리보기 고정 수치가 아니며 게임 기본값에 저장하지 않는다. 현재 이 문서 갱신 시점의 실제 게임 실행 결과는 대기 중이다.

## 2026-09-09 최종 시각 보완 계약

최초 UV 배치표 이후 실제 캡처 검토에 따라 좌우 날개 출력 영역을 (0,10,600,188), (600,10,600,188)로 수정한다. 중앙 장식(512,0,176,202)이 위에서 접합부를 덮는다. 원본 UV 범위는 유지한다. 이 배치가 이전 날개 좌표를 대체한다.

중앙 실제 아이콘과 같은80×80 영역에 선택 바인딩 UI_IdentityFallbackIcon을 두고, 실제 soft icon이 유효하지 않거나 로딩 중인 경우에만 기존 돌주먹 문장을 장식으로 표시한다. 실제 게임 데이터는 변경하지 않는다.
