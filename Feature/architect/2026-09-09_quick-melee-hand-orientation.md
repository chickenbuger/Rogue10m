# Quick melee 주먹 방향 개선 설계

- 날짜: 2026-09-09
- 작업 브랜치: Sprint#4-23-quick-melee-hand-orientation
- 사용자 요구: 양손 각도가 돌아가 보이는 문제를 고치고 오버워치 근접 공격의 느낌을 참고한다.
- 엔진: Unreal Engine 5.8.2
- 상태: 구현·빌드·실제 120프레임 및 시야 3조건·독립 소스와 최종 시각 6장 검증 완료. 최종 결과는 paired Feature/doc 문서에 기록했다.

## 근거와 참고 범위

[Blizzard 공식 Animation Station](https://news.blizzard.com/en-us/article/24239492/weekly-recall-animation-station)은 자주 보이는 기본 자세와 기본 공격을 먼저 완성하고 플레이테스트로 반복 개선한다고 설명한다. Wuyang의 quick melee는 정해진 시간과 사거리 안에서 짧고 강한 동작을 보여주기 위해 one-inch punch를 참고했으며, 느리게 보면 의도한 개별 포즈를 볼 수 있다고 설명한다. 이 작업은 그 원칙을 참고한다.

해당 글에 게임의 손목·전완 각도 수치, 세부 애니메이션 커브, 본 좌표는 없다. 아직 확인하지 않은 첨부 영상의 특정 프레임을 측정했다고 주장하지 않는다. 영상이 확인되면 준비 자세, 최대 신전, 복귀 구간을 나누어 비교한다. 다른 게임의 애니메이션 파일이나 캐릭터 아트를 가져오지 않는다.

## 수정 전 문제의 구조적 원인

Rogue10mFistAnimInstance.cpp는 기존 MM_Idle과 MM_Attack_01 손가락 포즈를 사용하고, 실제 DefaultSlot 몽타주의 손 전진량을 읽어 IK 가드와 신전 목표를 보간한다. 카메라는 안정된 capsule 기준이고 손 위치와 공격 복귀는 지난 작업에서 검증했다.

수정 전에는 solved lowerarm 회전과 샘플 hand 로컬 회전을 합성한 뒤, hand−lowerarm 축에 PI를 추가했다. 같은 180도 회전을 lowerarm과 hand 양쪽에 매 프레임 적용해 손목 경계의 상대 회전은 보존했지만, 전완 전체의 회전각은 기본 자세·공격 진행도·좌우 엄지 방향과 무관하게 고정되었다. 이번 구현에서는 그 고정 PI 보정을 제거했다.

양손이 모두 시야에 들어온다는 것, 손목이 끊어지지 않는다는 것, 실제 공격 중 손이 움직인다는 것만으로 올바른 손 방향을 증명하지 못한다. 이번 검증은 엄지 위치, 손등 방향, 전완의 연결을 독립적으로 확인한다.

## 표현 및 해부학적 기준

- 준비 자세: 양쪽 주먹이 화면 아래 좌우에 있고 엄지가 상대적으로 위·안쪽에 읽히는 중립 가드를 출발점으로 한다. 두 손이 동일한 방향으로 복제되어 보이지 않도록 실제 좌우 뼈와 엄지 위치를 기준으로 판단한다.
- 손목: 샘플 hand의 lowerarm 상대 회전은 초기 기준과 basis가 없는 경우의 fallback에 사용한다. 최종 손 회전은 실제 손 골격에서 측정한 Forward·Thumb basis를 목표 전완 방향·엄지 방향에 맞추어 계산한다. 따라서 원본 손목 로컬 회전을 그대로 보존한다고 설명하지 않는다.
- 전완: 필요한 회전은 각 팔의 길이 방향 축을 따라 적용한다. zero-length 축은 회전시키지 않으며 quaternion은 정규화한다. upperarm·손가락과 보조 뼈의 로컬 관계를 보존한다.
- 공격: 준비 자세에서 큰 예비 동작 없이 중앙 방향으로 짧게 내밀고, 공격이 끝나면 동일한 가드로 돌아온다. 실제 공격 중 손 이동은 현재 몽타주 평가를 따른다.
- 시야: 주먹이 중앙 목표의 얼굴·상체를 지속해서 덮지 않으며 HUD를 읽을 수 있어야 한다. 카메라 위치나 FOV를 바꾸어 손 방향 문제를 숨기지 않는다.

## 최종 구현과 보정값

아래 값은 외부 영상에서 측정한 수치가 아니라 프로젝트 실제 메시를 보며 정한 표현용 기본값이다.

1. ReadHandBasis는 hand→middle_01을 전방으로, index_01−pinky_01의 수직 성분을 엄지 쪽으로 측정하고 thumb_01 위치로 부호를 검증한다. 왼손·오른손의 로컬 축 차이를 실제 골격 기준으로 보정한다.
2. OrientAnatomicalFist는 SourceBasis를 TargetBasis로 정렬한다. 엄지는 가드에서 안쪽 15도, 최대 신전에서 안쪽 35도로 이동한다. lowerarm에는 원래 엄지 방향에서 목표 엄지 방향까지의 signed twist만 적용한다. 매 평가마다 idle→IK에서 다시 계산하므로 회전이 누적되지 않는다.
3. 카메라, 가드 목표 (20, 43, 148), 신전 목표 (10, 64, 148), SourcePunchTravel 32는 기존 작업 값을 유지한다. 손 방향을 맞추기 위해 FOV나 게임플레이 판정을 바꾸지 않았다.
4. 기존 손가락 샘플이 빈 C자 그립으로 보여 CloseFingerPose를 추가했다. 검지·중지·약지·소지의 MCP/PIP/DIP 굴곡 기본값은 각각 100/100/75도다. 이는 생성 입력값이며 실제 로그의 다른 축 기준 측정 각도와 일치한다고 간주하지 않는다.
5. 손가락의 실제 부모−자식 길이를 유지하며 측정한 Forward·Palm 평면에서 각 마디 방향을 계산한다. 엄지는 별도 two-bone IK로 접힌 검지 바깥쪽을 목표로 하고 stretch를 사용하지 않는다. 원본 애니메이션 자산은 수정하지 않는다.
6. 최종 손가락 로컬 변환, 손 basis, 손목 기준 회전은 FistAnimation·굴곡값·bone container serial이 바뀔 때만 다시 만든다. 대응하는 bone index와 transform 배열은 같은 재구축 분기에서 함께 갱신한다. 매 프레임 손가락 샘플을 다시 추출하거나 뼈 이름을 검색하지 않는다.
7. zero-axis, 없는 뼈, 빈 IK 변경 배열은 기존 방어 경로를 유지한다. 자산은 AnimInstance의 UPROPERTY 강한 참조로 보존하고 worker는 PreUpdate에서 복사한 설정을 사용한다.

## Ultrawork Packets

### P1 — 양손 기준 방향과 보정 분리

- 목표: 고정 180도 회전에서 벗어나 좌우 손의 실제 방향에 맞는 가드를 만든다.
- 입력: 현재 소스, 기존 실제 가드/공격 프레임, 사용자 피드백.
- 수정 위치: Character/Rogue10mFistAnimInstance.h/.cpp.
- 완료 조건: 양쪽 엄지·손등·전완 방향을 실제 캡처에서 독립 확인한다. 손목 단절과 비틀림이 없다.
- 검증 명령: Scripts/BuildEditor.ps1 -NoHotReload 및 Rogue10m.TestFistPresentation.
- 되돌릴 경계: 이번 회전 파라미터와 적용 계산만. 기존 카메라·HUD 작업은 유지한다.

### P2 — 빠른 공격의 준비·신전·복귀 검증

- 목표: 짧은 전진 동작과 자연스러운 회전 연결을 보여준다.
- 입력: 실제 DefaultSlot 몽타주, 연속 렌더 캡처.
- 수정 위치: 필요한 시각 파라미터와 런타임 검증.
- 완료 조건: 공격 직전, 신전 초기, 최대 신전, 복귀 초기, 최종 가드의 손 방향이 연속적이다. 실제로 해금된 공격 입력 3회의 몽타주와 손 이동을 확인한다.
- 검증 명령: Rogue10m.TestFistPresentation; 결과 GIF/영상과 선정 프레임 독립 시각 검토.
- 되돌릴 경계: 시각 보간만. 입력 처리와 피해 판정을 수정하지 않는다.

### P3 — 시야 각도 및 기존 기능 회귀

- 목표: 기본 시야에서만 자연스러운 임시 보정을 방지한다.
- 입력: 같은 캐릭터에서 수평 시선과 위·아래 시선, 기존 비율 대응 조건.
- 수정 위치: 필요할 경우 테스트 캡처 시나리오.
- 완료 조건: 수평 시선, pitch 약+25도/−25도에서 양손과 손목이 정상이고 카메라가 애니메이션에 끌려가지 않는다. 16:9와 ultrawide에서 중앙 대상·HUD 판독을 확인한다. Knuckle→다른 무기→Knuckle 후 방향이 누적되지 않는다.
- 검증 명령: 실제 런타임 캡처와 기존 Rogue10m.TestResponsiveHUD 중 변경에 관련된 조건.
- 되돌릴 경계: 테스트 fixture만. 프로필·몬스터·UI 자산을 새로 수정하지 않는다.

### P4 — 독립 검증과 기록

- 목표: 사용자에게 손 방향이 바뀐 실제 결과를 보여준다.
- 입력: 최종 소스, 빌드/런타임 로그, 실제 영상.
- 수정 위치: paired Feature/doc 문서, 한국어 DevLog/20260909.txt, Docs/SprintChangeLog.md.
- 완료 조건: 기획 1, 개발 2, 검증 2의 역할을 슬롯에 맞춰 순차 배정한다. 소스 검증과 시각 검증을 분리한다. 미완료나 제한 사항을 결과에 명시한다.
- 검증 명령: git diff --check, Scripts/CheckGeneratedChanges.ps1.
- 되돌릴 경계: 이번 문서 항목 및 캡처만. 미커밋 선행 작업은 보존한다.

## 게임플레이 보존

공격 입력, 차징 기준, 쿨다운, 연계 시간, 몽타주 재생 속도, 피해 발생 시점, 타격 판정 중심과 사거리는 변경하지 않는다. 특정 자세를 보여주려고 시간을 늘리거나 공격 타이밍을 지연하지 않는다. 표시용 방향은 실제 몽타주 진행과 연결하되 원래 전투 시스템의 값을 작성하지 않는다.

## Exit Gate

- 중립 가드에서 양손의 엄지·손등·전완 방향이 자연스럽다.
- 공격과 복귀의 회전이 연속적이고 손목 스킨 비틀림이 없다.
- 수평 및 위·아래 시선과 서로 다른 화면 비율에서 중앙 시야를 확보한다.
- 무기 교체 후 회전 보정이 누적되지 않고 정상 복원된다.
- 빌드 및 관련 실제 런타임 검증을 통과한다.
- 최종 영상, 변경 범위, 근거의 한계, 한국어 로그를 남긴다.
- 커밋과 푸시는 사용자 확인 전 실행하지 않는다.

## 참고 영상 접근 상태

공식 글의 두 번째 근접 공격 임베드는 [공식 quick melee 클립](https://www.youtube.com/watch?v=oSC3CAONGFw)으로 확인되었다. 이번 세션에서는 브라우저 도구의 Windows sandbox ACL helper 오류로 직접 영상 재생을 확인하지 못했다. 따라서 영상 프레임의 각도·시간을 측정했거나 동일하게 재현했다는 표현을 사용하지 않는다. 공식 글의 설명 원칙과 우리 프로젝트의 실제 UE 렌더 프레임을 근거로 검증한다.


## 시각 검증 후 보완

해부학적 손목 방향과 실제 공격 3회, 상하 시선·ultrawide 수치 검증 이후에도 원본 MM_Attack_01의 손가락 포즈가 C자 빈 그립으로 보여 완성 판정을 보류했다. 이에 FP 로컬 손가락 굽힘과 엄지 IK를 추가했고, 실제 프레임 비교 후 기본값을 100/100/75도로 정했다. 원본 animation asset과 게임플레이 타이밍은 유지했다. 최종 이미지에서 엄지가 손 안으로 끼지 않는지, 손가락이 관통하지 않는지, C자 빈 공간이 남지 않는지를 독립 확인한다.


## 최종 소스 검토와 실행 증거

- 최종 기본값이 header와 proxy 양쪽에서 100/100/75도로 일치함을 확인했다.
- 독립 소스 검토에서 현재 Manny 골격·기본값 기준의 중대·중간 회귀는 발견하지 못했다. 손가락 길이 보존, parent 순서의 안전한 CS→local 변환, 캐시 배열 결합, GC 참조를 확인했다.
- tmp/quick-melee/runtime-final.log에서 RESULT=FIST_PRESENTATION_PASSED frames=120 failures=0 및 VIEW_AUDIT completed=3을 직접 확인했다.
- 최종 로그의 네 손가락 PIP 측정은 양손 모두 100도이며, 손가락 segment 길이도 기록된다. 이 수치는 뼈 변환 검증 자료이며 스킨 관통 여부를 대신 판정하지 않는다.
- 이 문서의 상태는 구현·최종 소스 및 시각 검증 완료으로 유지한다. 최종 이미지 판정, 결과 문서, DevLog와 SprintChangeLog는 통합 담당자가 마무리한다.
