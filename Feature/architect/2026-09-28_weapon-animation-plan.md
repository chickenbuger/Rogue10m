## 목표

같은 공용 공격을 빠르기만 바꿔 재생하는 단계를 넘어 무기의 무게, 사거리, 손 역할이 동작만으로 구분되게 한다. 실제 Appearance 전신과 머리 카메라를 기준으로 1인칭 타격 가독성과 V키 3인칭 동작의 일관성을 함께 확보한다. 공격 판단과 피해 시점은 기존 C++/Data Asset 계약을 유지한다.

## 공통 동작 계약

1. 대기 → 준비 → 접촉/방출 → 회수 → 대기 흐름을 한 번의 행동으로 읽을 수 있어야 한다. 모든 무기에 같은 속도를 강제하지 않는다.
2. 무기 접촉 또는 발사 프레임을 먼저 선정하고 `HitStartDelaySeconds`, `HitInterval`, `HitCount`, 콤보 창과 재생속도를 함께 검증한다. 원본 시간과 실제 재생 시간을 구분하고 공격속도 배율을 중복 적용하지 않는다.
3. 왼손·오른손의 접촉 프레임이 다른 동작은 별도 판정 의도로 정의한다. 같은 프레임 손 두 개가 움직인다는 이유만으로 피해를 두 번 주지 않는다.
4. 공격 중 머리의 불필요한 큰 회전과 무기/팔의 중심 가림은 모션 소스 단계에서 줄인다. 카메라 감쇠나 별도 FP 메시로 결함을 숨기는 작업은 이번 범위에 넣지 않는다.
5. 무기 소켓·그립을 확정하기 전에는 팔 IK 값을 고정하지 않는다. 양손 무기는 오른손 기준과 왼손 보조 그립을 명시하고 체형별 관통/늘어남을 검사한다.
6. 기존 Root Motion 이동 정책을 유지한다. 발 디딤을 보이게 하려면 시각 포즈와 실제 캡슐 이동을 구분하고, 새 돌진 이동/무적/방어 판정은 별도 기능 작업으로 분리한다.
7. 1인칭과 V 관찰은 같은 동작·무기·피해 이벤트를 사용한다. V 관찰 중심과 실제 머리 공격 조준에 시차가 있다는 현재 특성을 QA 기록에 남긴다.

## 리듬과 수치 초안

아래 값은 **새 전용 클립을 선정할 때 비교할 제안 범위**다. 현행 Data Asset 값을 변경하거나 성능 목표 달성을 검증한 수치가 아니다. 실제 접촉 시간과 공격속도 배율을 확인해 결정한다.

|분류|기본 동작 전체 길이 후보|준비 / 접촉 / 회수의 인상|차징 정책|
|---|---|---|---|
|단검·쌍단검|0.35~0.60초|빠른 준비, 짧은 접촉, 즉시 다음 가드|긴 홀드로 빠른 무기 정체성을 없애지 않음|
|맨손·너클|0.40~0.70초|손 도달과 회수 명확, 하체 축 보존|맨손은 현재 입력 시간을 기준선으로 유지|
|장검·쌍검·버클러|0.55~0.90초|궤적을 읽을 준비, 다음 공격 방향으로 회수|접촉 전 충분한 예고, 후딜은 기본보다 명확|
|대검·방패|0.85~1.30초|큰 준비, 확정 접촉, 무게 회수|새 전진/돌진 정책과 혼합하지 않음|
|활·표창·지팡이|0.45~0.90초|방출 시점이 가장 명확, 손/도구 재정렬|활 Draw/Hold 분리는 기존 차징 상태와 맞춰 별도 설계|

모든 공격에 임의의 고정 ‘명중 프레임’을 배정하지 않는다. 후보 원본을 프레임 단위로 확인하고 실제 재생속도에서 피해 타이밍을 기록한다. 숫자 조정만으로 접촉이 맞지 않으면 원본/몽타주 구성을 고친다.

## 제작 목록과 데이터 연결

- 기존 11종 × 5슬롯 = 55개 공격 변형을 교체 대상 목록으로 삼는다. 이는 새로운 원본 클립55개가 반드시 필요하다는 뜻이 아니다. 같은 소스로 충족되는 변형은 재사용한다.
- Unarmed는 별도 기준선이다. 현재 좌우 잽·스트레이트·훅 4동작을 보존하고 새11종 제작 검증에서 회귀를 확인한다.
- 무기별 대기, 장착/해제, 이동 중 공격 블렌드, 차징 진입/유지/취소/발사/회수를 점검 목록에 포함한다. 기존 자산으로 충족할 수 있는지 확인한 뒤 새 제작량을 확정한다.
- 소스 Animation Sequence → 무기별 Montage → Attack Skill Data Asset → Skill Profile 순으로 연결한다. 기존 자산을 전역 덮어쓰지 않고 전용 파생 자산과 생성 스크립트를 함께 남긴다.
- `AttackMontage`, `AnimationPlayRate`, `HitStartDelaySeconds`, `AttackCooldown`, `ChargeSeconds`, `ComboWindowOpenSeconds`, `ComboWindowCloseSeconds`, `NextComboSkill`을 한 행의 제작 명세로 관리한다.
- 다단히트 무기는 `HitCount`, `HitInterval`, `MaxHitsPerTarget`도 같이 기록한다. 무기 사거리·피해·자원 비용 조정은 모션 교체와 분리해 비교 가능하게 한다.
- 애니메이션과 VFX는 독립 설정이다. 화면 효과가 세다는 이유로 손 궤적이나 무기 접촉이 검증됐다고 판단하지 않는다.

## 다음 구현 전 확인할 사항

전용 무기 메시와 클립 보유 여부, 활 시위/화살 표현 방식, 표창 특수의 다중 투사체 여부, 방패 방어/패링 판정 범위가 필요하다. 이번 문서는 의도를 제시하며 해당 시스템을 새로 구현하도록 승인 범위를 확대하지 않는다. 클립 확보가 안 된 무기는 대체본임을 명시하고, 하나의 무기를 끝까지 검증한 후 다음 무기로 확장한다.
