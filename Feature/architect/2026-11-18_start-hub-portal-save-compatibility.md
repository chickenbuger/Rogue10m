# 시작 마을 포탈과 이전 진행 저장 호환

실제 플레이 로그에서 메뉴가 `StartHub`를 정상적으로 연 뒤 캐릭터 진행 저장을 거절했다. 이어 다섯 차례의 포탈 접촉이 맵 전환 전에 중단됐다. 현재 선택된 프로필의 이전 저장에는 프로필 ID와 진행 데이터가 있지만, 당시 기본값과 같아서 기록되지 않은 저장 버전 필드가 있다. 새 코드의 기본값이 적용되면 이전 저장에 없는 런 ID까지 요구하므로 기존 포탈의 진입용 저장이 실패한다.

| 작업 | 변경 범위 | 완료 조건과 검증 | 되돌리기 경계 |
| --- | --- | --- | --- |
| 이전 저장 복원 | `Rogue10mProgressionSubsystem`의 로딩과 마이그레이션 | 버전 필드가 실제로 빠진 파일의 저장 형식을 구분한다. 원래 성장·장비·스킬·특성 정보를 적용하고 기존 경로로 새 버전 저장을 생성한다. 지원하지 않는 버전, 다른 프로필 ID, 검증을 통과하지 못한 데이터는 기존과 같이 거절한다. | 로딩 변경만 되돌릴 수 있다. 이전 파일은 제 위치에 남는다. |
| 포탈 회귀 | 격리 검증 슬롯과 기존 StartHub 배치 포탈 | 일반 로드와 Pawn 겹침 이벤트로 실제 월드가 열리는지 본다. 런 ID와 시작 타이머, 복원된 데이터와 이전 파일의 해시를 대조한다. 에디터 대상 빌드와 실제 로그 검사를 수행한다. | 검증 슬롯과 실행 프로세스만 이번 검증에 사용한다. |

포탈은 기존대로 입장 시점의 재화를 저장하고 성공했을 때 이동한다. 기존 맵 경로와 포탈 배치는 유지한다. 사용자 저장 파일을 수동으로 편집하지 않으며, 로딩 성공 후 기존 마이그레이션 흐름만 새 슬롯에 기록한다.
