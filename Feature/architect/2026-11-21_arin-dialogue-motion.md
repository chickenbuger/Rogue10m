# 아린 대화 자세 전환

작업 브랜치 `Sprint#17-5-arin-dialogue-motion`. `2011e0de`에서 렌더를 검증하고 최신 통합 기준 `2666013d`에서 수치 검사를 반복했다.

## 원인과 기존 리소스

`Rogue10mTutorialAnimationComponent::RefreshAnimation`은 상태에 따라 메시의 단일 재생 클립을 즉시 바꾼다. 보존한 아린 포즈 표본에서 `A_Arin_Talk`의 0.8초 자세와 `A_Arin_BreathingIdle`의 첫 자세는 왼쪽 손목 31.037cm, 오른쪽 손목 9.689cm 차이가 있었고 루트와 양발은 같은 위치였다. 이는 서로 다른 클립의 자세 비교다. 실제 게임의 연속 자세는 별도로 측정한다. 원본은 `DevLog/20261110_HumanoidBossNpc/NPC/ViewportA/manifest.json`에 있다.

에디터의 `DA_StartVillageGuide`가 선택하는 프로젝트의 Idle·Walk·Talk를 사용한다. Blender의 아린 원본과 이전 Idle도 확인했다. Talk 첫 자세는 이전 Idle과 맞았으나 현재 Breath Idle과는 양손이 각각 8.192cm, 10.695cm 다르다. 대화는 어느 시간에서도 닫을 수 있어 기존 애셋의 첫·끝 키만 맞추면 종료 시 각기 다른 자세에서 생기는 급변이 남는다. 기존 클립이 가진 보행과 제스처는 현재 용도에 맞으며 추가 Fab 또는 Mixamo 클립이 필요하지 않다.

안내인 전용 네이티브 그래프에서 반복 시퀀스 플레이어 하나를 유지한다. 클립을 바꾸면 직전의 실제 출력 자세와 새 클립의 진행 자세를 0.18초에 걸쳐 이어간다. 블렌드 도중 다시 바뀌면 그때까지 화면에 출력한 자세를 시작점으로 쓴다. Unreal의 자세 보간으로 뼈·커브·커스텀 속성을 함께 섞는다. LOD 변경 시 공통 뼈는 메시 인덱스로 이전 자세를 찾아 이어주고 새로 평가할 뼈와 현재 레이아웃의 커스텀 속성은 목적지 값을 쓴다. 같은 클립의 걷기 속도 변경은 클립 시계를 유지한다. 대화 우선순위, 기존 보행 감지, 호환성 검사와 Idle 대체를 애니메이션 컴포넌트에서 처리한다. 에디터의 액터 미리보기는 기존 단일 클립을 사용한다.

첫 후보는 Unreal Inertialization을 C++ 프록시에 직접 연결했다. UE 5.8의 Development Editor에서 애니메이션 트레이스가 블루프린트 그래프의 `NodeData`를 요구해 StartHub 로드 중 `AnimNodeBase.h:825` assertion이 발생했다. 프로젝트 전용 블렌드로 전환했다. 첫 소프트웨어 렌더에서는 대화를 연 직후 필요한 뼈를 다시 계산할 때 블렌드가 풀려 손목 이동 11.025cm를 기록했다. 이후 뼈 목록 변경을 처리할 수 있게 자세 저장 방식을 보완했다. 공용 Live Coding 점검 때문에 격리 빌드가 거부되면 기존 에디터를 종료하지 않고 UBT의 `-NoHotReloadFromIDE`를 사용한다.

## 검증 기준

실제 `StartHub`에서 `DA_StartVillageGuide`를 쓰는 아린을 선택하고 새 QA 프로필로 진입한다. 숫자 검증은 네이티브 `BeginDialogue`와 `CloseDialogue`를 호출한다. 평상시 열기, Talk의 0.80~0.84초에서 닫기, 같은 시점에 다시 닫고 새 포즈 3개가 평가된 직후 열기를 확인한다. 뼈 변환 갱신 번호가 달라진 포즈만 집계하고, 각 전환은 60Hz로 고정한 게임 시계 0.25초까지 기록한다. 앞의 닫기 3포즈도 별도로 남긴다. 소프트웨어 렌더링이 필요하면 `-Motion -Offscreen -AllowSoftwareRendering`으로 같은 게임 시간에서 캡처한다.

- 표본 간 게임 시계 간격 0.035초 이하, 전환당 8표본 이상. 재열기 직전 닫기는 3표본을 검사한다.
- 두 손목 중 가장 큰 첫 이동 6cm 이하, 전체 전환의 한 표본 이동은 8cm 이하. 루트와 양발은 시작 위치에서 0.05cm 이내다.
- 대화를 연 자세에서 Talk의 0.8초 자세까지 양손 중 한 손목은 12cm 이상 움직여야 한다. 클립 시계와 실제로 평가된 뼈 움직임을 함께 검증한다.
- 목적지 클립, 플레이어의 클립 시간 진행, 대화와 애니메이션 상태를 함께 확인한다.
- CSV에 게임 시각, 갱신 번호, 클립 시계, 메시 LOD와 루트·머리·양손목·양발 위치를 기록한다. 렌더링과 입력 자동화 방식은 결과에서 각각 밝혀 둔다. 기존 대화 서비스 입력의 회귀 검사는 애니메이션 측정과 구분한다.
