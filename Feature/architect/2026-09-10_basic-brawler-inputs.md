# 기본 격투가 입력·차징 어퍼컷·점프 설계

- 날짜: 2026-09-10
- 작업 브랜치: Sprint#4-25-basic-brawler-inputs
- 엔진: Unreal Engine 5.8.2
- 상태: 구현·실게임·독립 검증 완료. 원본 영상 직접 재생과 비교는 미완료. 최종 결과는 짝 개발 문서 참조.
- 사용자 목표: 기본 직업의 LMB 1타 왼주먹·2타 오른주먹, 자연스러운 머리와 카메라 움직임, RMB 유지 중 오른손 어퍼컷 준비와 몸의 오른쪽 회전, 해제 시 어퍼컷, 일반 점프의 기획과 구현.

## Scope Gate와 현재 구조

기본 직업은 DA_Character_Default가 사용하는 모험가 / Unarmed 경로다. Knuckle 장비 프로필이나 StoneFist 직업의 해금 상태를 기본 직업으로 간주하지 않는다. 이번 기능을 위해 다른 직업의 잠긴 스킬을 일괄 해금하지 않는다.

현재 CombatComponent는 LMB/RMB press 시간을 저장하고 release에서 기본/차징 스킬을 선택한다. Primary의 기존 자산 연결은 3타까지 이어질 수 있으므로 사용자가 요청한 기본 직업의 왼→오른 2타와 구분해야 한다. 공격 성공은 ExecuteAttackSkill에서 자원·쿨다운 검사를 통과해야 확정된다. 단순 마우스 입력 수를 세어 손을 바꾸면 거절된 입력에도 순서가 진행되는 문제가 생긴다.

C++ 기본 차징값은 0.65초지만 Editor에서 읽은 실제 강화 어퍼컷 자산은 ChargeSeconds 0.85초다. 기존 연계창은 0.15~0.55초이며, 실제 왼손 타격 후 오른손으로 연결되도록 새 전용 자산의 시작을 0.40초로 조정한다. 첫 피해 지연은 주먹 0.34초, 어퍼컷 0.633초를 기준으로 재생 속도에 맞춰 보정한다.

Space는 Enhanced Input JumpAction에서 DoJumpStart/DoJumpEnd로 연결되고, 실제 이륙과 착지는 Character의 OnJumped_Implementation/Landed에서 확인한다. 기존 CharacterAnimationComponent는 이때 지면 VFX를 실행한다. 이번 점프는 이 일반 이동 흐름에 자세와 표시용 카메라 움직임을 연결하며, 공중 특수 공격을 새로 추가하지 않는다.

전신 FP 표현, 닫힌 손과 엄지 방향, CameraManager의 표시용 POV 동조는 앞선 작업 결과를 재사용한다. 실제 CameraComponent와 ControlRotation은 타격 기준이므로 표현 때문에 변경하지 않는다.

## 담당 영역과 공통 계약

| 담당 | 소유 영역 | 책임 |
| --- | --- | --- |
| 기획 1 | 이 문서 | 요구별 동작·완료 조건·실행 검증 정의 |
| 개발 1 | Combat 및 기본 격투가 전용 입력 상태 컴포넌트, 필요한 데이터/Editor 스크립트 | 입력 수락·2타 연계·차징/해제·취소·자원/쿨다운 연결 |
| 개발 2 | FistAnimInstance, Presentation, CameraManager, Character의 점프 알림 연결 | 왼/오른손 구분, 오른쪽 준비 자세, 어퍼컷 궤적, 머리/POV 동조, 일반 점프 표현 |
| 검증 1 | 읽기 전용 소스·데이터·상태 전이 검토 | 수락 시점, 중복 타격, 취소 정리, 스레드/GC, 판정 불변 |
| 검증 2 | 실제 플레이 영상·프레임 | 손 순서, 준비·차징·어퍼컷, 점프 이륙·착지, 자연스러운 시야와 HUD 판독 |
| 통합 | 빌드·Editor 적용·실행 로그·문서 | 사용자가 확인할 실제 결과와 회귀 검증 |

입력 소유자는 표현 계층에 읽기 전용 snapshot을 제공한다. 최소 계약은 공격 종류(LeftJab / RightStraight / RightUppercut), 수락된 공격 serial, 차징 상태와 0~1 진행률, 공격 경과/유효 재생 시간이다. 정확한 API 이름은 개발 담당자가 한곳에서 정의하고 두 구현이 공유한다.

snapshot의 accepted serial과 손 단계는 실제 공격이 수락된 뒤에만 바뀐다. pose worker가 Combat·PlayerState·Camera를 직접 수정하지 않는다. 게임 스레드에서 상태를 복사하고 proxy가 로컬 포즈만 계산한다.

## 확정 입력 규칙

| 입력·상황 | 동작 |
| --- | --- |
| 지상 LMB 첫 press | 즉시 왼주먹 1타 시도. release는 중복 공격하지 않는다. |
| 1타의 유효 연계창 안 LMB | 오른주먹 2타를 한 번 실행한다. |
| 연계창보다 조금 이른 LMB | 입력을 1개만 보관하여 창이 열릴 때 재검사 후 실행한다. 반복 입력을 여러 타로 누적하지 않는다. |
| 연계창이 지난 LMB | 왼주먹 1타부터 시작한다. 기존 쿨다운·자원 검사는 유지한다. |
| 오른주먹 2타 이후 | 이번 기본 연계는 종료한다. 3타 자산을 자동 연결하지 않는다. 다음 유효 입력은 왼주먹이다. |
| 공격이 쿨다운·자원·상태 조건으로 거절됨 | 타격과 accepted serial, 다음 손 단계가 진행되지 않는다. |
| RMB press | 오른손을 아래·뒤로 당기고 상체가 오른쪽으로 일부 회전하는 준비 상태를 시작한다. |
| RMB 유지 | 차징 진행률이 증가하며 최대치에서 대기한다. 완충만으로 자동 발사하지 않는다. |
| 짧은 RMB tap/release | 기본 오른손 어퍼컷 1회. 짧은 입력도 소비되지 않고 실제 공격을 시도한다. |
| RMB 유지 후 0.85초 이상 release | 강화 오른손 어퍼컷 1회. 연결 ChargedSpecial의 ChargeSeconds가 있으면 그 값을 우선한다. |
| charge 중 LMB | 충돌하는 기본 연계를 시작하지 않는다. |
| charge 중 이동·시선 조작 | 이동과 조준은 유지한다. 몸의 오른쪽 회전은 FP 표시용이며 실제 이동 방향을 회전시키지 않는다. |
| Space로 이륙 / 지상에서 낙하로 전환 | 보관된 지상 차징을 취소하고 일반 공중 상태로 들어간다. 착지 후 늦은 RMB release가 어퍼컷을 발사하지 않는다. |
| 사망·무기 변경·입력 취소·차단 UI | charge, 보관 입력, 연계 상태, 표시용 준비 자세를 정리한다. 취소된 release는 공격을 생성하지 않는다. |

RMB의 피해 단계는 기본 Special과 강화 ChargedSpecial의 두 단계다. 유지 시간에 따른 새로운 연속 피해 배율이나 추가 넉백·공중 띄우기 효과를 임의로 만들지 않는다. 기존 자산의 피해·범위·비용·쿨다운을 먼저 읽고, 기본 직업 연결에 필요한 변경만 명시적으로 기록한다.

차징 시작 전 사용 가능한 스킬인지 확인하고, release 시에도 사망·무기·공중 상태·차단 UI·자원·쿨다운을 다시 확인한다. 취소와 유지에는 타격 피해를 발생시키지 않는다. 자원 지불은 기존의 수락된 공격 실행 경로를 사용한다.

## 왼·오른 2타 연계 상태

초기 상태는 왼주먹 준비다. 왼주먹이 수락되면 현재 스킬의 연계창을 시작한다. 창 안에서 오른주먹이 수락되면 연계가 종료되고 다음 유효 기본 공격은 왼주먹으로 돌아간다.

이른 입력 보관은 1개만 허용한다. 기본 만료 상한은 연계창 시작까지의 짧은 간격이며, 기본 창 0.15초보다 앞서 누른 경우라도 실행 시 CanUseCombatInput, 스킬 연결, 자원과 현재 무기를 재검사한다. 연계창 종료 이후에는 보관 입력으로 공격을 늦게 발사하지 않는다. 타이머는 취소·무기 전환·사망·EndPlay에서 정리한다.

RMB가 준비를 시작하면 이전 LMB의 보관 입력은 취소한다. LMB 복귀나 새 연계의 시작이 release 어퍼컷과 동시에 실행되지 않도록 하나의 입력 상태 소유자가 충돌을 처리한다.

## 1인칭 자세와 어퍼컷

왼 1타는 왼손이 전진하고 오른손은 가드를 유지한다. 오른 2타는 오른손이 전진하고 왼손이 회수된다. 자산 이름만 왼·오른으로 분리하는 것으로 완료하지 않고 실제 공격 프레임에서 해당 손이 더 크게 움직이는지 확인한다.

RMB 준비에서는 오른손이 아래쪽으로 당겨지고 오른어깨·몸통이 일부 뒤로 돌아간다. 준비 회전은 차징 진행률에 따라 부드럽게 증가하며 완충 시 자세가 유지된다. 조준을 오른쪽으로 돌리거나 capsule을 회전시키지 않는다.

release에서는 오른주먹이 아래에서 위로 올라오는 궤적을 사용한다. 정면 직선 펀치를 재생하고 어퍼컷이라고 표시하는 것은 완료가 아니다. 기존 몽타주와 네이티브 FP 포즈로 실제 손의 상승·몸통 복귀를 보여주며, 왼손은 중앙 시야를 가리지 않는 가드를 유지한다. 강화 단계는 기존 데이터 차이를 적용하고, 필요하면 준비/신전의 표시 강도를 제한적으로 구분한다.

머리와 카메라 움직임은 어깨·상체·타격 방향에 동조한다. 기존 body-motion snapshot과 최종 POV 처리를 확장하되 타격 판정용 CameraComponent의 위치·회전은 유지한다. 새 머리/카메라 보정과 기존 body motion의 중복 가중을 피한다.

## 일반 점프 설계

Space press로 일반 점프를 시작하고 release는 기존 StopJumping을 유지한다. 점프 횟수, JumpZVelocity, 중력과 이동 조작은 현재 기본 Unarmed 프로필 및 CharacterMovement 값을 사용한다. 기본 모험가에 StoneFist의 2단 점프를 잘못 적용하지 않는다.

- 이륙: OnJumped가 실제 발생했을 때 짧은 자세·POV 반응을 시작한다. 점프가 거절된 Space 입력만으로 카메라가 튀지 않는다.
- 공중: 실제 IsFalling과 수직 속도를 사용해 팔 가드를 약간 정리하고 시야의 연속성을 유지한다. 지상 차징이 공중까지 남지 않는다.
- 착지: Landed에서 이전 공중 속도에 따른 제한된 흡수 동작을 실행하고 기본 가드로 돌아온다. 지상에 서 있는 동안 반복 착지 흔들림을 생성하지 않는다.
- 제외 범위: 신규 공중 어퍼컷, 점프 슬램, 추가 점프 횟수, 공중 전용 타격 판정. 다른 기존 직업의 공중 스킬은 이번 입력 변경으로 일괄 제거하거나 해금하지 않는다.

카메라 동조는 기존 CameraMotionScale=0에서 점프 보정까지 꺼질 수 있게 하고, death/무기 전환/뷰 타깃 변경 시 잔여값을 정리한다.

## 명시 튜닝과 재사용

| 항목 | 초기 규칙 |
| --- | --- |
| 2타 연계창 | 연결 자산 우선, 기본 0.15~0.55초 |
| RMB 강화 문턱 | ChargedSpecial.ChargeSeconds 우선, 기본 0.65초 |
| 차징 진행률 | elapsed / threshold를 0~1로 제한 |
| 보관 LMB 수 | 1개, 연계창 종료를 넘겨 실행하지 않음 |
| 어퍼컷 피해 단계 | 기존 Special / ChargedSpecial 두 자산 |
| 손·어깨 자세 | 기존 가드/닫힌 손 기반, 오른쪽 준비 회전과 상승 궤적만 명시적으로 노출 |
| 머리/카메라 범위 | 기존 표시용 2cm·축별 제한을 우선 사용, 새 값은 실제 캡처 후 문서화 |
| 점프 이동값 | CharacterMovement와 기본 Unarmed 프로필의 기존 값 유지 |
| 점프 카메라 | 이륙·착지 최대 오프셋/회전과 복귀 시간을 표현 전용 UPROPERTY로 노출 |

필요한 신규 공격 presentation enum, 준비 회전, 손 목표, camera impulse 값은 코드 안 임의 상수로 분산하지 않는다. gameplay data는 Data Asset, 입력 상태는 전용 ActorComponent, 포즈와 카메라는 표시 계층으로 분리한다.

## Ultrawork Packets

### P1 — 기본 직업 프로필·좌우 2타 입력

- 목표: 기본 모험가에서 LMB 왼→오른 2타가 실제로 동작한다.
- 수정 영역: 입력 컴포넌트/Combat 연결, 기본 직업 프로필과 필요한 Editor 스크립트.
- 완료 조건: 스폰 무기를 강제로 Knuckle로 바꾸지 않아도 동작하며, 정상·빠른 연타·창 종료·자원 부족·쿨다운 상황의 수락/손 순서가 맞는다.
- 검증: Editor 데이터 검사, BuildEditor.ps1 -NoHotReload, 실제 입력 runtime 검사.
- rollback 경계: 기본 Unarmed 입력·명시 저장한 관련 자산. 다른 직업 프로필은 보존.

### P2 — RMB 준비·유지·release·취소

- 목표: 준비 자세와 실제 오른손 어퍼컷이 한 상태 흐름으로 이어진다.
- 수정 영역: 전용 입력 상태, Special/ChargedSpecial 선택과 presentation snapshot.
- 완료 조건: tap 기본 / threshold 이상 강화, 완충 대기 중 피해 없음, release 1회 공격, 반복 release 없음, 이동 중 유지, Space·낙하·UI·사망·무기 변경 취소.
- 검증: 상태/accepted serial/피해·비용 로그와 실제 준비→유지→상승→복귀 영상.
- rollback 경계: RMB 전용 분기와 snapshot, 관련 기본 직업 데이터.

### P3 — 손 순서·머리·카메라·어퍼컷 표현

- 목표: 왼/오른 손과 어퍼컷 방향이 실제 화면에서 구별된다.
- 수정 영역: FistAnimInstance, Presentation, CameraManager.
- 완료 조건: 잘못된 손 재생 없음, 충전 중 오른쪽 상체 회전, release 시 오른손 상승 궤적, 자연스러운 머리·최종 POV 동조, 손목/손가락 형태와 HUD 판독 유지.
- 검증: 독립 소스 검토, 선정 프레임과 실제 연속 영상, ControlRotation/판정용 camera 불변 검사.
- rollback 경계: 이번 기본 격투가 표현 분기와 snapshot 소비.

### P4 — 일반 점프와 전이

- 목표: Space 점프의 실제 이륙·공중·착지가 자세/카메라에 연결된다.
- 수정 영역: Character의 실제 이동 이벤트, Presentation의 점프 상태.
- 완료 조건: 일반 점프 높이/횟수 유지, 거절 입력의 허위 반응 없음, 차징 중 이륙 취소, 착지 1회 반응과 복귀, 카메라 효과 0 설정 및 사망 정리.
- 검증: 실제 jump/land 이벤트, movement mode·수직 속도·POV 측정과 영상.
- rollback 경계: 점프 표시 연결만. 새로운 공중 공격은 생성하지 않는다.

### P5 — 통합 검증·기록

- 목표: 요구별 결과를 사용자에게 실제 게임 영상과 함께 전달한다.
- 수정 영역: runtime test, Feature/doc/2026-09-10_basic-brawler-inputs.md, DevLog/20260910.txt, Docs/SprintChangeLog.md.
- 완료 조건: 요구별 통과·미완료를 숨기지 않고 기록하고, 소스·시각 검증 2역할을 완료한다. 현재 UE 프로그램에 반영된 데이터를 확인한다.
- 검증: 관련 build/runtime, git diff --check, Scripts/CheckGeneratedChanges.ps1, 명시 자산 저장 목록 검토.
- rollback 경계: 이번 테스트 fixture와 문서·캡처.

## 레퍼런스 검증 한계

이번 요청과 관련된 영상 제목/링크가 전달되었지만, 기획 작성 시점에는 두 영상의 실제 재생을 아직 확인하지 못했다. 제목만 보고 동작·각도·박자를 관찰했다고 쓰지 않는다. 재시도 결과가 나오면 확인된 범위만 결과 문서에 추가한다. 현재 설계는 사용자 설명과 실제 프로젝트의 입력·애니메이션 구조를 기준으로 한다.

## Exit Gate

- 기본 직업의 실제 스폰에서 왼 1타·오른 2타와 연계 초기화가 동작한다.
- RMB tap, hold, full charge, release, cancel 상태를 모두 검증한다.
- 오른손 준비 자세와 몸의 오른쪽 회전, release 어퍼컷의 상승 궤적이 실제로 보인다.
- 머리·카메라가 자연스럽게 동조하면서 판정용 조준과 이동을 보존한다.
- Space 일반 점프의 이륙·공중·착지 표현과 차징 취소가 동작한다.
- 사망·무기 전환·UI·반복 release·자원 부족에서 중복 피해나 잔여 준비 자세가 없다.
- UE 5.8.2 빌드와 관련 실제 runtime·독립 시각 검증을 완료한다.
- 결과 문서·한국어 DevLog·SprintChangeLog와 실제 영상/캡처를 남긴다.
- 선행 미커밋 작업을 보존하며 사용자 확인 전 커밋·푸시하지 않는다.
