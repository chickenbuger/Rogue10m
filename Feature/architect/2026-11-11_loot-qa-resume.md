# 전리품 획득 작업 재개와 검증 실행기 보강

## 현재 상태

이전 DroppedItem 구현 두 파일은 현재 공유 프로젝트와 정규화한 내용이 같다. 공유 통합 과정에서 테스트 프로필 초기화와 월드 종료 순서가 보완됐고, 보존된 LootAllA 결과는 8개 성공·경고/실패 0이다. 통합 기록은 저장 쓰기 26개·새 프로세스 읽기 9개 성공과 기존 저장 변경 0을 보고한다. 이는 과거 실행 증거이며 이번 세션에서 UE를 다시 실행한 결과가 아니다.

## 범위

게임플레이 소스·카메라·에셋·빌드 설정은 바꾸지 않는다. 3인칭 유지와 1인칭 보류 지시를 지킨다. 독립 물리 사본 `C:/Users/PC/AppData/Local/Temp/Rogue10m-LootPickup-20261111`, 작업 브랜치 `Sprint#9-29-loot-qa-resume`에서만 편집한다. 공유 에디터·UE 프로세스·빌드는 실행하지 않는다.

## 보완할 경로

- 명령줄을 읽을 수 없는 UE 프로세스와 프로젝트 경로의 대소문자·슬래시·상대 파일명 변형을 실행 전에 차단한다.
- Saved/SaveGames의 모든 파일을 해시로 보존하며, 새 QA 저장 허용은 저장 루트의 정확한 슬롯과 `.sav` 파일로 한정한다. Windows 파일명 대소문자를 동일하게 취급한다.
- 성공한 자동화 보고서가 있어도 실제 전리품 테스트 시작 이후 Error/Fatal/ensure/Python 오류가 있으면 성공으로 판정하지 않는다. 시작 전 엔진 자체 검사의 오류 문구는 따로 기록하며 전체 프로세스 로그 오류 0으로 표현하지 않는다.
- 종료를 요청한 소유 QA 프로세스가 실제로 종료되지 않으면 저장 보존 결과를 확정하지 않는다.

## 검증 원칙

테스트는 새 임시 프로젝트의 빈 Content와 합성 보고서·저장 파일만 사용한다. Start-Process와 Get-CimInstance는 테스트 실행 스코프의 가짜 함수로 교체하며, 실제 UE 실행 파일에는 접근하지 않는다. 실제 엔진 빌드·네이티브 테스트·실게임 검증은 부모 담당자의 공유 사용 조율 후에만 재실행한다. 이번 작업의 자동 검사 수를 기존 UE 8개 통과와 합산하지 않는다.
