# 미사용 파일 정리 — 검증된 중복 임시 파일

작성: 2026-09-28 / 브랜치: Sprint#4-41-unused-file-cleanup / 기획1

## 목표와 범위

사용자의 "사용하지 않는 파일들 정리해줘" 요청에 따라 프로젝트를 조사하고, 현재 실행·빌드·제작·복원에 필요하지 않은 중복 임시 파일을 정리한다. 파일 이름이나 오래된 날짜만으로 미사용을 판정하지 않는다. 정리는 Tier A(동일 SHA-256 보존 사본이 있고 실행 참조가 없는 임시 중복)와 Tier B(현재 보존 원본으로 모든 프레임을 실제 재생성하여 픽셀 일치를 검증하고 최종 MP4도 보존한 임시 자막 PNG)로 나눈다. Tier B는 아래 별도 조건을 모두 만족하는 폴더로 제한한다.

기존 dirty 파일의 내용과 상태는 모두 보존한다. Source/Content/Config/Scripts의 파일 및 Blueprint·동적 경로에 연계될 수 있는 자산은 참조 조사를 통과하지 않았다는 이유만으로 삭제하지 않는다. C++ 문자열 검색 결과가 없다는 것은 Unreal 자산이 미사용이라는 증거가 아니다.

## 제외 대상

- `Intermediate/`, `Binaries/`, `Saved/`, `DerivedDataCache/` 및 generated 코드/엔진 캐시. 정리 목적으로도 수정·삭제하지 않는다.
- `.uasset`, `.umap` 바이너리 및 Git 관리 코드·설정·문서의 기존 변경. 엔진 에디터를 통하지 않고 자산을 변경하지 않는다.
- `tmp`의 고유 백업·복구 스냅샷, decoder/ffmpeg 등 도구, 원본 영상/FBX/분석 입력, 재생성 검증을 통과하지 않은 유일한 출력이나 테스트 재현 자료.
- 현재 프로세스·진행 중 테스트가 쓰는 파일. 활성 프로세스가 필요한 경로는 완료 또는 사용 종료를 확인하기 전 건드리지 않는다.
- SHA-256이 다르거나 보존 사본의 존재를 확인하지 못한 파일. 파일 크기/이름 일치는 중복 판정으로 인정하지 않는다.
- FirstPersonMesh 등 런타임에서 비활성인 기능의 소스 파일. 호환 Blueprint 및 다른 경로의 참조가 남아 있어 단순 미사용 파일로 취급하지 않는다.

## Tier A 삭제 허용 조건

동일 파일 중복 후보는 아래 조건을 모두 만족해야 한다.

1. 삭제 경로가 프로젝트 루트 아래 `tmp`의 일반 파일이고, 절대 경로를 확인했으며 금지 디렉터리를 통과하지 않는다. reparse point/symlink 경로는 자동 대상으로 넣지 않는다.
2. 보존 경로가 삭제 집합 밖에 있으며 실제 일반 파일이다. 예: `Feature/doc/evidence/` 또는 정리 결과로 명시적으로 보존할 자료 위치.
3. 삭제 직전 원본과 보존 파일의 SHA-256 및 크기를 다시 확인해 일치한다. 조사 후 파일이 변경되면 건너뛴다.
4. 현재 실행·빌드·테스트·제작 스크립트의 입력으로 참조되지 않는다. `rg`로 경로/파일명과 관련 실행 스크립트를 조사하고 동적으로 조합되는 경로도 검토한다. 자동 판단이 모호하면 보존한다.
5. 어떤 파일을 없애고 어디에 동일 내용이 남는지 매니페스트에 기록한다. 원래 경로로 복사하여 되돌릴 수 있다.

기존 문서에 남은 과거 로그 경로는 실행 의존성과 구분하되, 그 경로를 삭제한다면 매니페스트에서 동일한 보존 위치를 찾을 수 있어야 한다. 재현에 필요한 실행 스크립트와 입력 자료는 그대로 유지한다.

## 매니페스트와 복구

삭제 전에 JSON 또는 CSV로 원래 절대 경로, 보존 절대 경로, SHA-256, 크기, 참조 조사 요약, 상태를 기록한다. 삭제 결과는 파일마다 성공/건너뜀/실패로 남기고 총 개수·총 바이트는 실제 삭제 결과로 산출한다. 추정량을 실적처럼 쓰지 않는다.

복구는 보존 파일의 해시를 확인한 뒤 원래 디렉터리를 생성하고 원래 경로로 복사하는 방식이다. 원래 경로에 새 파일이 있다면 덮어쓰지 않는다. 복구 스크립트를 제공하는 경우 자동 overwrite를 금지한다. 보존 사본을 삭제나 이동 대상으로 연쇄 처리하지 않는다.

## 실행 안전 규칙

Windows에서는 PowerShell 한 셸 안에서 `-LiteralPath`를 사용하는 개별 파일 작업으로 처리한다. 문자열로 다른 셸의 삭제 명령을 만들지 않는다. 삭제 후보 절대 경로의 루트 경계를 검증한다. 광범위한 recursive 폴더 삭제나 glob 삭제를 하지 않는다. 파일 정리 중 오류가 나면 나머지를 무조건 진행하지 말고 해당 원인·영향 범위를 확인한다.

## Tier B — 실제 재생성 검증을 통과한 임시 자막 PNG

저장 공간 대부분을 차지하는 `tmp`의 labeled 프레임은 단순 이름/스크립트 존재만으로 삭제하지 않는다. 현재 남아 있는 원본 스크린샷과 실제 label 생성 코드를 사용해 **모든 프레임을 재생성**하고 기존 labeled PNG와 픽셀 데이터·해상도·모드가 일치한 폴더만 정리할 수 있다. 검증2 담당의 최종 통과 목록 밖 폴더는 보존한다.

필수 조건:

1. 원본 프레임과 label 스크립트, 입력 로그·폰트·렌더링 조건 등 재생성 입력이 남아 있다. 원본 경로의 `Saved/` 자료는 읽기만 하고 삭제·수정하지 않는다.
2. 전 프레임 수·파일명 대응을 확인한다. 몇 프레임 샘플 비교나 MP4 존재만으로 통과시키지 않는다. 파일마다 원본 PNG 해시, 재생성 전후 픽셀 해시, 크기/모드, 원본 입력 경로를 남긴다.
3. 최종 MP4가 존재하고 ffprobe 등으로 영상 스트림·프레임 수·길이를 확인했다. MP4는 손실 압축 결과일 수 있으므로 PNG 복구의 원본으로 취급하지 않는다.
4. 후보는 label 전용 임시 PNG만이다. 같은 폴더 안의 스크립트·입력·고유 이미지·예외 파일은 삭제하지 않는다. 비디오 인코더 등 downstream 입력은 프레임 재생성을 먼저 수행하면 다시 사용할 수 있도록 생성 명령과 순서를 보존한다.
5. 삭제 직전에 현재 PNG의 바이트 SHA-256을 승인된 매니페스트와 다시 대조한다. 검사 이후 달라진 파일이나 재생성이 불일치한 폴더는 제외한다.
6. 복구는 보존 원본으로 자막 PNG를 다시 만드는 방식이다. 픽셀 일치만 확인했다면 원래 PNG의 메타데이터/압축 바이트까지 똑같이 복원된다고 주장하지 않는다. Tier A의 동일 바이트 복사 복구와 구분하여 기록한다.

Tier A 매니페스트는 `original → keep`를 사용하고, Tier B는 `original → source + generator + validation evidence`를 사용한다. 두 집합은 서로 중복되지 않고 원본·최종 MP4·생성 코드는 삭제 집합에 들어가지 않아야 한다. root만 최종 삭제를 수행한다.
