# 시작마을 튜토리얼 NPC

## 작업 범위

시작마을에 선택적으로 대화할 수 있는 안내 NPC를 추가한다. 최신 요청에 따라 조작 퀘스트 대신 간단한 대화와 기본 아이템 지급을 구현한다. 현재 회피 키가 E이므로 대화는 F를 사용한다. 포탈 사용과 런 시작 여부는 기존 로직을 유지한다.

## Ultrawork Packet

- 목표: 시작마을에서 탐험 안내와 출발 보급품을 받을 수 있다.
- 입력: 기존 InventoryComponent.TryAddGridItem, HealthPotion Data Asset, 보유 Quinn/Manny Idle 모션.
- 수정 위치: 새 World/Tutorial NPC 및 Data Asset/수령 기록 컴포넌트/보급품 전달 Subsystem, UI/Tutorial Widget. RunPortal 및 Inventory BeginPlay에 보급품 전달만 연결한다. 기존 Character/Combat 코드는 수정하지 않는다.
- 완료 조건: F 대화, 실제 아이템 지급, 중복 수령 차단, 가방 공간 부족 안내와 재시도, 북쪽 포탈 안내가 동작한다.
- 검증: BuildEditor.ps1 및 실제 StartHub PIE에서 단계/입력/타이머/충돌 확인.
- 되돌릴 수 있는 경계: 새 NPC 배치와 전용 Data Asset/Widget/수령 기록 컴포넌트만 분리할 수 있다.

## 구현 계약

- 게임플레이 로직은 C++ Actor, 문구/외형/거리 설정은 Data Asset으로 분리한다.
- NPC는 피해를 받지 않으며 플레이어를 막지 않는다. Tick은 사용하지 않는다.
- 플레이어가 감지 범위에 있을 때만 0.1초 타이머를 사용한다. UI는 게임 입력을 차단하지 않는다.
- 지급은 기존 인벤토리 API를 통해 하나의 스택으로 처리한다. 아이템 수량과 MaxStackSize를 확인하고 실패 시 수령 기록을 남기지 않는다.
- PlayerState의 전용 컴포넌트가 현재 세션 수령 기록을 소유한다. 동일 보상 ID를 가진 NPC 복사본이나 같은 PlayerState의 재생성된 Pawn도 중복 지급하지 않는다. 재진입 중복 요청도 예약 상태로 차단한다.
- GameInstance Subsystem은 지급한 스택의 GUID와 남은 수량만 포탈 이동 직전에 확인한다. 사용하거나 버려서 없어진 스택은 수량 0으로 기록한다. 다음 맵의 기존 Inventory 초기화 후 남은 보급품만 일반 추가 API로 전달하고 새 GUID를 추적한다. 목적지 가방이 가득 차면 공간을 비울 때 재시도한다.
- 영구 저장, 일반 인벤토리 전체 보존, 로그라이크 특성 시스템 확장, 능력치 변경을 추가하지 않는다. 게임 세션과 실제 포탈 이동 범위에 한정한다.
- F는 대화 열기 → 보급품 받기 → 닫기로 동작한다. 멀어지면 대화가 닫히고 I로 가방을 정리한 뒤 다시 받을 수 있다.

## 테스트 재설계

PIE 검증에서 그리드 구조체의 InstanceId는 읽기 전용이고 Item Data Asset의 InventorySize는 EditDefaultsOnly임을 확인했다. 테스트는 해당 필드를 직접 쓰거나 임시 아이템 정의를 수정하지 않는다. 실제 인벤토리 API인 RemoveGridItem으로 비우고, 보유 HealthPotion의 실제 1×1 크기를 먼저 확인한 뒤 TryAddGridItem으로 채운다. 테스트 전용 대화 데이터의 보상 ID만 분리하여 정상 수령과 공간 부족 사례를 각각 확인한다. 모든 인벤토리 테스트 상태는 검증이 소유한 PIE를 종료하면서 폐기한다.

## 안내인 이미지 추가 (2026-10-05)

사용자 요청에 따라 길잡이 아린의 전신 시각 콘셉트 한 장을 imagegen 내장 도구로 제작한다. 친근한 성인 안내인 표정, 단정한 초록 여행복, 실용적인 보급 가방과 회복 물약 두 병을 기존 밝은 목조·기와 마을 분위기에 맞춘다. 무거운 갑옷과 위협적인 무기를 추가하지 않는다.

수정 범위는 전용 PNG·생성 프롬프트와 기능 문서·개발 기록이다. 완료 조건은 인물 전신·얼굴·손·물약과 마을 분위기를 이미지로 직접 확인하고 프로젝트에 결과를 보존하는 것이다. 검증은 PNG 무결성·육안 검토·diff 검사이며 C++ 빌드와 PIE는 필요하지 않다. 이미지와 기록만 분리할 수 있으며 이번 이미지 요청은 3D 모델 생성이나 Unreal 메시 교체를 포함하지 않는다.
