# 몬스터 보상 자동 입고와 초과 수량 드롭

## 목표와 계약

처치 전리품은 기존 보상 대상 플레이어의 인벤토리에 즉시 입고한다. 같은 아이템·같은 강화 값의 그리드 스택 빈 수량을 먼저 사용하고, 남은 수량이 빈 그리드 공간에 들어가면 전부 입고한다. 들어가지 못한 수량만 기존 바닥 드롭으로 전환한다. 예를 들어 18/20개 스택과 빈 칸이 없는 가방에 물약 5개를 주면 2개를 합치고 3개만 드롭한다.

기존 플레이어의 직접 버리기·줍기 API와 GUID·강화·저장 형식·골드·경험치 경로는 유지한다. 3인칭을 유지하고 1인칭을 변경하지 않는다. 사용자 요청에 명시된 자동 입고는 대리 처리 없이 실제 사망 처리에 연결한다.

## 중복과 손실 방지

- 보상 대상은 기존 LastDamageInstigator의 PlayerController가 소유한 현재 캐릭터다. 대상 없음·사망·다른 월드·권한 없음은 전량 바닥 경로로 처리하며 player0 대상을 임의 선택하지 않는다.
- 기존 처치 1회·Standalone·테스트 개체·런 종료 가드를 유지한다. 경험치가 0이어도 아이템 처리는 수행한다.
- 기존 TryAddItemStack은 변경하지 않는다. 새 전용 API는 유효 입력과 용량 부족을 구분하고, 중복 GUID를 거부하며 최종 remainder를 확정한 뒤 변경 이벤트를 한 번 보낸다.
- 추첨 결과는 입고·spawn 콜백 전에 UWorldSubsystem의 UPROPERTY 보관 목록으로 인계한다. 처리 중 재진입을 막고 콜백을 가로질러 배열 참조를 들고 있지 않는다.
- 지면 부재·잘못된 배치 값·생성 실패는 잔량을 버리지 않고 같은 GUID·수량으로 보관·저빈도 타이머 재시도한다. 시체가 파괴돼도 보관 목록은 유지한다. 성공한 deferred 바닥 액터로 소유권을 넘긴 뒤 FinishSpawning한다.
- 미획득 바닥 아이템과 보관 중 초과 전리품은 기존과 동일하게 월드/런 수명에 한정된다. 새 세이브 형식은 추가하지 않는다. 입고된 수량은 기존 인벤토리 저장 이벤트를 따른다.

## 검증과 통합

수량 분배 정책은 실제 runtime에서 사용하는 동일 C++ 헤더를 독립 컴파일해 검사한다. UE 자동화는 전체 입고·18/20+5·새 칸·강화 불일치·반복 사망·대상 없음·지면 실패·시체 파괴 후 재시도를 작성한다. 실제 UE 빌드·자동화·실게임 검증은 공유 담당자 조율 후 수행하며 작성만 된 검사를 통과한 것으로 보고하지 않는다.
