# Martelo 2 실제 캐릭터 1인칭 시연 계획

## 요청과 범위

사용자는 제공한 Martelo 2.fbx를 게임 캐릭터에 적용한 실제 1인칭 화면을 보고 싶어 한다. 골격 GIF로 대체하지 않고 Rogue10m 실행 화면에서 기존 HUD, 맵, Manny 팔 표면과 함께 동작을 촬영한다. 이번 요청은 적용 상태의 확인이므로 좌클릭·우클릭 매핑이나 피해·자원·쿨타임 변경은 포함하지 않는다.

원본 분석: `Feature/doc/2026-09-22_martelo-motion-preview.md`. 원본은 메시가 없는 Mixamo 65개 뼈의 1.30초 왼발 높은 발차기이며, 양팔은 균형을 잡기 위해 크게 움직인다. 현재 팔 전용 메시의 전체 89개 뼈는 유지되지만 다리 표면이 없으므로 발차기가 화면에 드러나지 않을 수 있다. 이는 실제 촬영에서 확인하고 결과에 명시한다.

## 구현 경계

프리뷰 전용 리타깃 애니메이션을 새 경로에 생성하고, 별도 개발용 실행 명령에서 현재 플레이어의 1인칭 메시를 SingleNode 재생으로 전환한다. 기존 기본 공격의 절차적 FistAnimInstance는 슬롯 애니메이션을 그대로 통과시키지 않으므로 공격 Data Asset 교체만으로 구현하지 않는다. `.uasset` 생성·변경은 Unreal Editor API로 수행한다.

기본 비교 화면은 현행 팔 전용 메시, 카메라 상대 위치, FOV, FirstPersonScale을 유지한다. 몸 전체를 몰래 보이게 하거나 원본을 다른 공격으로 재구성하지 않는다. 발을 보이는 변형을 추가하면 별도 조정안임을 표시한다. 프리뷰 자산과 명령은 실제 게임 렌더링을 사용하지만 정식 공격 입력이나 판정 연결을 뜻하지 않는다.

SingleNode에서는 현행 `ApplyBodyMotionToView`의 FistAnimInstance 검사가 실패하여 몸-카메라 연동이 0으로 재설정된다. 카메라 연동을 추가하는 경우 원본 머리의 큰 기울임을 그대로 적용하지 않고 별도 조정안으로 구분한다. 원본 또는 리타깃 뼈에서 얻은 변화를 기준 포즈 대비 계산하고, 기존 시야 표현 한도인 이동 2cm, pitch/yaw 2도, roll 1.5도 이내로 제한한다. 조준 CameraComponent와 ControlRotation은 변경하지 않으며, 위치·회전 신호가 유한하지 않으면 0으로 복구한다.

## Ultrawork Packets

### 1. 리타깃 자산

- 목표: 원본 1.30초 동작을 실제 Manny 뼈대에서 재생할 수 있는 독립 애니메이션으로 생성한다.
- 입력: 사용자 Martelo 2.fbx, 기존 분석, Manny 기준 뼈대.
- 수정 위치: 새 Editor 생성 도구와 프리뷰 전용 Content 경로.
- 완료 조건: 대상 스켈레톤 호환, 정상 길이와 샘플 수, 좌우 관절 대응, 원본 준비·신전·회수 흐름 확인.
- 검증: Unreal Editor 도구 실행 로그와 생성 자산 로드; 대표 시각에서 손·발 좌표의 유한성 및 변위 확인.
- 복구 경계: 새 생성 자산과 도구만 제거 가능. 원본 FBX, Manny, 기존 공격 자산은 보존.

### 2. 실제 1인칭 프리뷰

- 목표: 현행 게임 맵/HUD/팔 메시에서 리타깃 동작을 재생하여 촬영한다.
- 수정 위치: 독립 런타임 프리뷰 명령 또는 테스트 파일.
- 완료 조건: 기본 자세, 준비, 신전, 회수, 종료 후 원래 자세가 실제 화면에 나타난다.
- 검증: `Scripts/BuildEditor.ps1`와 개발용 프리뷰 명령의 명시적 PASSED/FAILED 로그. 실행 종료 코드만으로 성공 판정하지 않는다.
- 복구 경계: 임시 런타임 상태를 Finish/실패/월드 종료에서 복원하고 입력·피해 데이터는 변경하지 않는다.

### 3. 독립 검증과 전달

- 목표: 실제 게임 영상과 제한을 사용자에게 정확히 보여준다.
- 수정 위치: Feature/doc, 증거 이미지·MP4, DevLog, SprintChangeLog.
- 완료 조건: 소스 검토와 실제 프레임 검토를 각각 수행하고, 동작의 보임/가림을 관찰 사실로 기록한다.
- 검증: 대표 프레임(기본·준비·신전·회수·복구) 및 영상 재생 확인, `git diff --check`, `Scripts/CheckGeneratedChanges.ps1`.
- 복구 경계: 문서·증거 산출물만 별도로 관리한다. 커밋·푸시는 수행하지 않는다.

## 최소 실행 검증

1. 원본 길이는 1.30초이며 타깃 프리뷰 속도 1.0에서 같은 동작 구간을 보인다. 영상 반복 사이에 기본 자세 또는 명확한 휴지 구간을 둔다.
2. 리타깃 대상이 실제 사용 중인 1인칭 메시와 같은 스켈레톤이며 팔이 움직인다. 좌우 반전, NaN, 비정상 스케일, 손목 뒤집힘, 어깨 찢어짐 여부를 실제 프레임에서 확인한다.
3. 카메라 연동 0인 기본 재생과 연동 조정안을 혼동하지 않는다. 시야 연동이 있으면 조준 회전은 불변이고 설정 한도를 넘지 않는다.
4. 팔 전용 메시의 다리 부재가 그대로 유지된다. 화면에서 발이 보이지 않는다면 실패를 숨기지 않고 이 동작의 현행 적용 결과로 설명한다.
5. 종료 후 프리뷰 진입 전의 애니메이션 모드·클래스, SingleNode 자산/시간/재생/반복/속도(해당 시), 메시·재질·명시적 뼈 가림, 부모·소켓·상대변환, owner 표시, 카메라 FOV·스케일·부모·상대변환을 복원한다.
6. 테스트가 소유한 입력무시 stack만 반납하고 고정 시간 설정을 원래 값으로 돌린다. 월드·캐릭터 소멸이나 조기 실패도 같은 정리 경로를 통과한다.
7. 복구 뒤 FistAnimInstance와 원래 기본 자세가 돌아오는지 확인한다. 생산 입력/피해 연결을 바꾸지 않았으므로 새 발차기 피해 검증은 요구하지 않는다.

## 산출물 표현

최종 영상은 반드시 실제 Rogue10m 프리뷰임을 밝힌다. '정식 공격으로 적용 완료' 또는 '발차기 판정 구현 완료'라고 표현하지 않는다. 기본 팔 전용 상태에서 무엇이 보이는지 먼저 설명하고, 발을 보이도록 구성하려면 별도 표시 방식의 조정이 필요하다는 점은 실제 화면을 근거로 짧게 덧붙인다.

## 완료 기록 — 2026-09-22

기획 1·개발 2·검증 2 역할로 실제 Manny 팔 전용 적용, Editor 빌드, 독립 게임 촬영, 소스·화면 검토를 완료했다. 최종 자산의 별도 프로세스 재사용과 게임 촬영 209프레임을 검증했다. 고정 카메라와 블렌딩 없는 진입·복귀는 비교용 미리보기의 명시적 한계다. 결과와 증거는 Feature/doc/2026-09-22_martelo-first-person-preview.md에 기록했다.
