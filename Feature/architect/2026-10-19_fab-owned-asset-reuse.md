# Fab 보유 에셋 우선 활용 계획

## 사용자 의도와 범위

앞으로 Rogue10m 개발에서 Fab 보유 에셋을 최대한 활용한다. 먼저 실제 Epic Games Launcher의 Fab > 내 라이브러리와 프로젝트의 기존 팩·사용 기록을 대조하고, 다음 기능 작업에서 적용할 재사용 원칙을 저장한다. 특정 새 기능이나 전체 라이브러리 일괄 설치 요청으로 해석하지 않는다.

작업 브랜치: `Sprint#5-36-fab-owned-asset-reuse`. 게임 코드·설정·에셋 변경 없이 문서와 프로젝트 지침을 보완한다.

## 실행 기준

- Computer Use의 실제 런처 창만 읽는다. 로그인/계정 보유를 숨은 캐시나 API 추정으로 대체하지 않는다.
- Fab 보유 확인, 프로젝트 존재, 과거 사용 문서, 실제 현재 의존성 검증을 구분한다.
- 판타지/스타일라이즈드 아트와 기존 C++·Data Asset 구조, 머리 카메라 안정화와 저장 계약을 유지한다.
- 팩은 필요한 메시·재질·클립·Niagara·소리 단위로 평가한다. framework 전체 도입은 기존 시스템과 맞는 별도 범위에서 판단한다.
- 이번 단계에서 구매·다운로드·팩 설치·에셋 import·게임 동작 변경은 하지 않는다. 후속 기능에 필요한 보유 자산의 일반 데이터 반입은 사용자 재사용 지시에 따라 범위 안에서 진행하고, 플러그인/프레임워크 코드 실행 등은 해당 도구의 권한 규칙을 따른다.
- C++ 변경이 없어 UE 빌드/PIE를 실행하지 않는다. 커밋·푸시는 하지 않는다.

## 사용자 후속 선호 반영 — 기본 애니메이션·VFX 편집

기본 애니메이션과 VFX는 보유 에셋의 프로젝트용 파생본을 수정·편집하는 것을 기본 경로로 구체화한다. 애니메이션은 클립·리타깃·구간·재생률·블렌딩·몽타주/Notify를, VFX는 파라미터·재질·색·규모·수명·타이밍·부착을 요구에 맞게 조정한다. 기존 원본·카메라·타격·root motion 계약은 보존한다. 적합한 원본이 부족하거나 사용자가 새 제작을 명시하면 이유를 기록하고 새로 제작할 수 있다.

이 후속은 F2 지침의 범위 보완으로 같은 작업 브랜치에서 AGENTS/가이드·결과/로그를 갱신한다. 실제 게임 에셋 수정은 구체적인 콘텐츠 작업에서 수행한다.
