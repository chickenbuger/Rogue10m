# Obsidian 소스 전용 그래프

- 목표: 전체 문서 대신 Source/Rogue10m의 .h/.cpp 파일 간 내부 include 관계만 그래프에 표시한다.
- 범위: 기존 아키텍처 노트 생성기, 실행기, 검증기와 로컬 graph.json 설정. Unreal 코드와 자산 변경은 없다.
- 구현: Files 경로 필터, 태그·첨부·미해결 링크 숨김, 화살표 활성화. 기존 표시 크기와 색상 설정을 보존하고 최초 설정을 백업한다.
- 방향: 나가는 include만 Wiki Link로 생성한다. 들어오는 의존성은 일반 텍스트로 남기고 대시보드 탐색 링크는 제거하여 가짜 역방향·허브 관계를 없앤다.
- 검증: 생성기 실행, 모든 파일 노트의 링크 집합과 outgoing 관계 일치 검사, 링크 유효성·지표 검증, 설정 JSON 확인 및 PowerShell 구문 검사. 게임 변경이 없어 UE 빌드는 생략한다.
- 한계: 정적 include 그래프이며 함수 호출·상속·전방 선언·Blueprint/에셋 참조 그래프는 아니다. Obsidian 실행 중 설정 반영은 재로드 또는 UI 필터 적용이 필요할 수 있다.
- 롤백: 이번 스크립트 수정만 되돌리고 노트를 재생성한다. graph.json은 graph.before-source-only.json.bak에서 복원한다. 기존 미커밋 변경은 보존한다.

## 기능 노드 확장 (사용자 선택 반영)

- 소스 노드와 별도로 Functions 폴더에 전투·스킬·인벤토리 등 기능 노드를 생성한다. Feature 폴더의 개발 문서는 표시하지 않는다.
- 명시적인 소스 경로 분류 규칙을 JSON으로 관리하며 공유 소스는 여러 기능에 포함할 수 있다. 분류는 검토 가능한 탐색용 매핑이며 호출 그래프나 실행 추적으로 해석하지 않는다.
- 기능 → 소스 선은 소속/관련 관계, 소스 → 소스 선은 기존 include 의존성이다. 기능 노트를 색상으로 구분한다.
- 기존 생성기에 기능 노드 생성을 통합하고 기능 노트·소스 대응·링크 유효성을 함께 검증한다.
- 검증은 생성/검증 스크립트 및 소스 include 관계 292개 보존 확인으로 한정하며 엔진 빌드는 필요하지 않다.

## Feature 문서 근거 연결 보완 — ULW 패킷

범위: 기존 Sprint#4-29 생성 도구와 문서만 확장한다. 게임 소스·에셋·브랜치 변경은 없다.

1. 근거 수집: Feature/architect와 Feature/doc의 최상위 Markdown을 기능 주제별로 분류한다. 현재 존재하는 소스 이름·클래스 이름·유일한 축약 이름을 찾고 문서 경로/행 번호/언급 문자열을 기록한다. README, 증거 하위 폴더, 그래프 도구 자체 문서는 제외한다.
   - 완료 조건: 기능→소스 선마다 하나 이상의 실제 문서 근거가 존재한다.
   - 검증: 근거 문자열이 해당 문서 행에 존재하는지 및 대상 소스 실재 여부 검사.
   - 롤백 경계: 기능 분류 JSON과 근거 수집 스크립트.
2. 생성·검증: 기존 파일명 패턴에 의한 임의 연결을 문서 근거 연결로 교체한다. Feature 원문은 노드로 만들지 않고 기능 노트의 근거 표에 경로와 행을 일반 텍스트로 남긴다.
   - 완료 조건: 기능 노드 연결과 근거 보고서 일치, 소스 include 292개 보존.
   - 검증: TestObsidianArchitectureMetrics.ps1 및 문서 참조 해석의 작은 회귀 사례.
   - 롤백 경계: 기능 생성기·검증기·생성 출력.
3. 결과 기록: 문서 언급 기반 연관도이며 계획/삭제 언급도 실제 호출 관계를 보증하지 않음을 표시한다. 미분류/근거 없는 파일은 소스 그래프에 유지하되 기능선을 억지로 만들지 않는다.
   - 완료 조건: 결과 문서, SprintChangeLog, 한국어 DevLog 업데이트.
   - 검증: git diff --check.
   - 롤백 경계: 이번에 추가한 문서 기록.
