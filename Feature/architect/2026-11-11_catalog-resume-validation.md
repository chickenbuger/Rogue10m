# 카탈로그 재개 검증 계획

범위: 새 격리 물리 사본에서만 스크립트·테스트·문서를 수정한다. 공유 소스·에셋·에디터·빌드 프로세스는 변경하거나 사용하지 않는다. 1인칭은 보류하고 3인칭 계약을 유지한다. 커밋·푸시는 하지 않는다.

## 확인한 현재 상태

이전 source.patch는 공유 forward-check 실패/reverse-check 성공이므로 이미 반영됐다. CatalogSharedA는 카탈로그/소비/정책3개와 기존성장3개 모두 Success/경고0/오류0이다. 이전 격리 이관 실패는 실제 ChargedShockwave 에셋이 없는 환경의 결과이며 공유 기능 회귀 실패가 계속되는 상태로 보고하지 않는다. 원본 feature 문서의 이전 상태 설명은 보완이 필요하다.

## Ultrawork Packets

1. 상태·에셋 조사: canonical SkillProductionTracker의 K/G20개를 기술명+무기 계열로 현재 C++ legacy 정의와 조인하는 오프라인 감사 도구를 만든다. 기존 소스 파일 존재와 새 독립 기술/실제 카탈로그 활성화를 구분한다. 보존 readback은 당시 관측으로만 표시한다. 검증은 경로·중복·문서 ID 드리프트·소스 매핑 단위검사와 읽기 전용 실제 감사다. 롤백은 새 감사 스크립트·테스트·보고서다.
2. 회귀 실행 전 조건: 검증 runner에 PreflightOnly와 성장 콘텐츠 선행조건 검사를 넣는다. Content 없는 사본에서 잘못된 회귀 실패를 만들기 전에 정확한 누락 원인을 기록하며 UE는 시작하지 않는다. launcher의 content_assets=false 고정 표시를 정확한 검사 정보로 바꾼다. 검증은 격리 fixture 디렉터리의 PowerShell 호출이며 엔진·빌드 프로세스를 실행하지 않는다. 롤백은 runner hunk와 해당 테스트다.
3. 검토·인계: 독립 리뷰, git diff --check, 경로 검사, 현재 공유 적용 점검, SHA manifest와 별도 패치를 준비한다. 격리 DevLog/20261111.txt와 Sprint 추가 문단을 한국어로 남긴다. 실제 에셋 제작·이관·새 선택 UI·게임 시각 QA는 담당자 소유권 조율 후 이어갈 작업으로 남긴다.

완료 조건: 새 엔진 실행 없이 현재 통합 상태와 콘텐츠 공백이 재현 가능하고, 누락 콘텐츠를 자동검사 실패와 혼동하지 않으며, 공유 파일을 덮어쓰지 않는 인계 자료가 준비된다.
