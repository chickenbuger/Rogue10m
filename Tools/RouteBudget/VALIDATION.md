## 변경 파일과 목적

기존 파일을 덮어쓰지 않고 새 `Tools/RouteBudget/`에만 추가했다.

- `route_budget.py`: 기존 CLI를 통합하고 기본 입력을 프로젝트 경로 JSON으로 연결했다. 입력 바이트를 한 번 읽어 계산과 해시가 같은 버전을 가리키도록 했다.
- `test_route_budget.py`: 독립 자동 회귀47개를 고정 fixture로 연결했다. 기존 출력 파일 보존 검사를 추가했고 직접 실행 시 출력용 디렉터리를 준비한다.
- `verify.py`: 실행별 새 증거 디렉터리, 원본 스냅샷, 같은 입력의 Python/PowerShell 실행, 새 정적 검사, 보고서 재현, 원본 해시 비교를 구현했다.
- `inputs/*`: 원래 독립 도구의 회귀 fixture·검증기·계획 스냅샷을 보존했다. 실제 설계본으로 편집하지 않는다.
- `provenance/standalone-*`: 이전 독립 작업의 결과·리뷰·계획 기록을 보존했다.
- `.gitignore`, `README.md`, `ARCHITECTURE.md`, 본 문서 및 일지·스프린트 후보: 도구 실행과 적용 범위를 기록한다.

기존 `Sprint#9-29-humanoid-boss-npc` 작업 브랜치를 유지해 동시에 진행 중인 작업을 방해하지 않았다. 기존 소스·에셋·문서·공유 DevLog·설정·브랜치 상태 변경, 에디터·빌드 실행, 사용자 저장 데이터 접근, 커밋·푸시는 하지 않았다.

## 시간 기준과 한계

기존 설계 JSON은 **보스룸 입구900초 + 가정 보스180초 + 여유120초 = 활성 런1200초**이다. 이전 architect의 **입구720초 + 보스180초 = 처치900초**와는 불일치한다. 원본 문서는 그대로 두었으며 사용자 최신 원문의 도착 약15분을 통합 기준으로 사용했다.

기존 입력의 가정6m/s로 직행300m는50초, V4↔V1 왕복500m는83.333초다. 입구900초 예산에 추가 던전180초를 넣으면 가정 보스 종료1260초로1200초를 넘는다. 이 값들은 실제 이동·전투·게임 시간을 측정한 결과가 아니다.

지도에 다섯 마을이나 새 경로를 배치하지 않았다. 실제 지형 통행·충돌·입력·퀘스트 상태·안전 메뉴 정지·보상·보스전·풀런은 별도 작업으로 남는다. 독립 리뷰가 지적한 실제 입력/fixture 혼용, 과거 정적 결과 재사용, 출력 덮어쓰기, 입력 해시 경합 위험은 통합 구현에서 처리했다.
