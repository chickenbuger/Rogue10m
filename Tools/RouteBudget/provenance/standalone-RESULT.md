# 다섯 마을 경로·시간 예산 도구 결과

2026-11-10. 상태: **독립 도구 구현·검증 완료 / 프로젝트 미통합 / 실제 게임 검증 미실시**.

## 산출물

- `route_budget.py`: 표준 라이브러리 CLI. 최단경로, 마을 미방문, 참조 우회·재방문 경로, 선택 활동, 속도·거리 민감도, 의뢰 보고 왕복 예산.
- `test_route_budget.py`: 독립 작성 회귀46개. 정상 결과뿐 아니라 잘못된 경로·누락 예산·중복 활동·비유한 숫자·교차로·시간 종료 경계를 검증.
- `verify.py`: 회귀 실행, 로그/입력 해시/보고서 기록, 동일 보고서의 바이트 재현 확인. `--project-root`는 원본 파일 해시를 읽기만 함.
- `inputs/`: 기존 JSON·PowerShell 검증기·architect 문서의 고정 스냅샷. 최신 시점 JSON도 별도 보존.
- `evidence/`: `verification-summary.json`, `unittest.txt`, `model-report.json`, `existing-static-validation.json`, `input-manifest.json`, `source-drift.json`, `model-report-current-at-finish.json`.
- `ARCHITECTURE.md`, `REVIEW.md`, `README.md`: 패킷 계획·독립 리뷰·재현/통합 안내.

프로젝트의 공유 소스·설정·에셋·일지·스프린트 문서는 이 작업에서 변경하지 않았다. 브랜치 변경·커밋·푸시·에디터·빌드·사용자 저장 데이터 접근도 하지 않았다. 이 임시 폴더 안에서만 구현·기록했다.

## 기존 자료와 중복 조정

기존 `Feature/doc/evidence/five-village-route-spec-20261110/route-plan.json`은 이미 교차로3개를 명시한10노드·19왕복 간선과 두900초 예산을 갖고 있었다. 별도 마을 설계를 만들지 않고 그대로 재사용했다. 기존 `VerifyRoutePlan.ps1`의199개 정적 검사도 복사본에서 실행했다. 본 도구는 추가 선택·왕복 판단·민감도·입력 변이 회귀에 집중한다.

기존 architect 스냅샷의 예산은 **입구720초 + 보스180초 =900초**지만 JSON은 최신 사용자 목표대로 **입구900초 + 보스180초 + 여유120초 =1200초**이다. JSON V4 활동165초·V5 던전270초도 architect의90~120초·120~180초와 다르다. 이를 자동으로 합치거나 게임 수치를 변경하지 않았으며, 통합 시 문서 기준을 정리해야 한다.

작업 도중 원본 JSON에는 `source_snapshot`, `working_tree_dirty_at_inspection` 두 메타데이터가 추가됐다. 초기 스냅샷 SHA-256은 `c303bdf5abba28d51bd8ca96c028675baf08308c7dd387adb9c8ea5eca41552e`, 마감 시점 스냅샷은 `19960be3f703b399bfbecdfe4d4d02781c1ecd813fffac6fde72c1b78c678698`이다. 두 입력으로 각각 검증했고, 입력 해시를 제외한 모델 결과가 동일했다. 자세한 비교는 `evidence/source-drift.json`에 있다.

## 발견된 시간 선택 비용

**아래 수치는 모두 평면 좌표·속도·활동 시간의 설계 가정이다. 실제 통행 거리·MaxWalkSpeed 측정·플레이 시간 결과가 아니다.**

| 사례 | 가정 기반 결과 | 해석 |
|---|---|---|
| 마을 전체 건너뛰기 직행 | 300m ÷6m/s =50초 | 60초 목표에 순수 보행 기준10초 여유. 실제 입구 접근 비용은 미측정 |
| 직행 속도 변화 | 4/5/6m/s →75/60/50초 | 5m/s에서는 이미 기하 보행만60초 |
| 재방문 경로 | 1332.758m, 순수 보행222.126초, 여행 예산255초 | 여행 여유32.874초를 중복 없이 보존 |
| 재방문·반대편 성장 | 각각 입구900초, 보스 완료1080초 | 여유120초를 더하면 런 한도1200초와 같음 |
| 다섯 마을 방문 | 이동1462.075m/243.679초 하한 | 활동 예산이 없어 모든 마을 콘텐츠 완료 시간은 계산하지 않음 |
| 재방문 경로 거리10% 증가 | 입구922.213초 | 가정 보스 완료는 시간 안이지만120초 여유를22.213초 침식 |
| 추가 던전180초 | 입구1080초, 가정 보스 완료1260초 | 20분 한도 초과. 이미900초 예산을 전부 썼다면 다른 활동과 교환 필요 |
| V4→V1→V4 | 왕복500m/83.333초 | 완료 의뢰 보고30초·보스 이동15.366초·보스180초·여유120초 포함428.699초 필요 |
| 위 왕복 + 미완료 목표180초 | 필요608.699초 | 잔여600초면120초 여유를8.699초 침식. 전투 완료 자체 불가능과는 구분 |

가정 완료시간이 잔여시간과 같으면0초 시간초과로 거부한다. 여유를 포함한 필요시간과 잔여시간이 같아도 가정 전투가0초 전에 끝나면 여유 보존 조건은 만족한다. 목표 시간을 넘는 정상 시나리오 계산은 CLI 오류로 취급하지 않고 JSON 결과로 판단한다.

## 검증

실행: `python verify.py --project-root D:\Project\Rogue10m`.

- 자동 테스트46개, 실패0·오류0·생략0.
- 노드 간90개 방향별 경로, 마을 미방문32개 조합 검증.
- 기존 PowerShell 정적 검사199개, 실패0.
- 같은 고정 입력의 전체 JSON 보고서가 두 실행에서 바이트 단위 일치.
- 초기/마감 JSON 모두 모델 검증 통과. 변경된 원본의 경로·시간 결과 동일.
- 독립 리뷰에서 원본 여행 ID 중복 계상 및 성장 예산 누락 통과 문제2건을 발견하고 수정·회귀 검증함.

## 남은 통합 및 게임 검증

통합 제안과 실행 예시는 `README.md`에 있다. 원본/fixture를 구분해 전용 작업 브랜치에 도구만 추가한 뒤 architect/feature 결과/스프린트 변경로그/한국어 DevLog를 갱신한다. 이 위임은 커밋·푸시를 명시적으로 제외한다.

실제 지도 배치·지형 충돌·스트리밍·필드 마을 일시정지·동일 RunId 퀘스트 재방문·중복 보상·보스 입구 및 이탈 정책·물리 입력·성장 효율·풀런 시간은 별도 미검증이다. 선택 활동의 장소·선후행·퀘스트 상태는 시뮬레이션하지 않는다. 원본 활동에는 coverage_keys가 없어 실제 같은 처치가 두 활동에 들어 있는지도 의미상 확정할 수 없다. 이 모델의 통과를 실제60초/15분 플레이 달성으로 표시하면 안 된다.
